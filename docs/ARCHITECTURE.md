# 当前代码结构

JustConnect 将可修改的 aTrust Go 源码直接纳入 `corelib/` 单一模块。Qt 通过版本化 C ABI 在同一宿主内调用正式会话；数据转发留在 Go 内。来源及许可证见 [corelib/UPSTREAM.md](../corelib/UPSTREAM.md)，契约见 [CORE-ABI.md](CORE-ABI.md)。

## 目录与依赖

```text
presentation/     Qt Widgets、认证窗口与流程 Coordinator
application/      连接／配置／系统代理用例及基础设施端口
core/             连接配置、错误与状态规则
infrastructure/   内嵌库适配、QSettings、系统代理、日志与更新实现
corelib/          会话、aTrust、underlay、解析、gVisor、回环代理及 C ABI
cmake/            应用和原生宿主共享的 Go 库／Qt 适配构建入口
tests/            领域、端口、界面、真实 C ABI 与受控网关回归
```

`application` 依赖 `core`，不引用 Widgets 或具体基础设施。`MainWindowCoordinator` 组合 `CoreEngine → EmbeddedCoreEngine`、`SystemProxyBackend → ProxyRecoveryBackend → JustConnectProxyRecovery → PlatformSystemProxyBackend` 和 `ProfileBackend → ProfileManager`。认证方式窗口通过应用层 `AuthMethodsQuery` 使用 `CoreEngine`，允许注入测试端口；只在查询与清理均成功后交付完整方法身份，取消或失败不暴露部分结果。

## 会话与线程

`ConnectionSession` 持有连接意图、重连计时器及当前配置，使用 `ConnectionSessionState` 管理状态。`EmbeddedCoreEngine` 将配置序列化后提交专属 Qt 工作线程；每次 connect（含重连）先读取原网络与系统 DNS 快照，复用应用模型推导保护前缀及名称规则，再把默认无校园例外的完整初始策略交给核心。读取或推导失败不启动会话；原子取消标志避免工作线程读取期间收到的停止请求在读取完成后仍开始会话，既有有界退出继续等待线程所有者。认证方式查询不读取保护快照。创建、异步启动、认证回应、读取、停止和销毁都在该线程调用 C ABI。每次最多一个 Qt 事件在途，应用线程确认交付后继续读取，避免另造无界日志队列。诊断字符串只供记录，状态仅由结构化状态／终态事件改变。`observation` 将认证、恢复和维护结果及观测时间独立传入同一会话，按阶段保留最新结果，未观测显示未知。主窗口和托盘共用该状态；当前仅显示“通道就绪”，不把核心 ready 标成产品“已连接”。设置页的自动／目标／关闭经现有 Profile 及 Go 配置校验接入维护循环；主窗口／托盘分别显示会话续期、DNS／HTTP 流量保活、节点和隧道维护的结果／时间，缺少获授权资源明确提示不可用。

`AuthenticationCacheCoordinator` 统一编排认证缓存的保存、失效、首次 SSO 账户绑定与清除代次，使用现有 CredentialAccess 串行存储入口；界面控制器只处理连接意图、输入和提示，并在退出时等待协调器的绑定续接。账户键和有效性规则仍归连接模型／ProfileCredentials，存储来源与修订校验归 CredentialAccess，避免界面重排或后续重连重复维护这些规则。Go 仅通过绑定身份的 ClientData 恢复并由服务器确认账户、取得当前资源；不再保留直接注入旧资源并跳过认证的旁路。

应用重连和核心隧道重拨各自最多五次，指数退避间隔封顶 30 秒；两层预算只在持续就绪 60 秒后重置；核心按节点组保留预算，短暂连通不会重新获得次数。Go 的结构化传输错误分类排除证书、权限、协议和明确失效，不匹配错误文本。完成交互认证后允许后续网络恢复；尚在认证中的超时不自动重放登录。进入应用退避时撤销失效的系统代理，手动取消清除上一轮错误。隧道重拨耗尽会终止该会话，取消同时停止等待和拨号。

Go 的会话代次和请求 ID 全程保留为十进制字符串。`AuthDialogCoordinator` 异步展示短信、TOTP、RADIUS、内存图片验证码和 SSO；回应带原始身份。应用及 Go 都检查当前请求，旧窗口提交／取消不能影响新会话。停止不等待认证 UI；销毁先中断读取，再等待句柄与借用缓冲区结束。Unix 静态链接；Windows 从可执行文件目录固定加载随包 DLL，并保持 Go runtime 到宿主退出。

观测按适配器校验代次后的 ABI 交付顺序更新；UTC 时间仅用于展示，不用于判旧。系统校时回拨或相同毫秒内的结果仍能更新；停止后的维护事件被忽略，新连接清空上代观测。

`Session.Run` 拥有 underlay、认证／隧道、gVisor、解析器及 SOCKS／HTTP（含 UDP association），所有清理结束后才释放活动会话名额。进程只允许一个活动连接或认证方式查询。查询界面等待清理终态后才允许确认选择。系统代理由单独用例拥有，仅在用户启用自动设置时于通道就绪后应用，也可手动设置；当前库不创建系统 TUN、不改变系统路由／DNS，GUI 无需为连接整体提权。核心 `ready` 目前只证明通道与本地代理初始化完成。

`Listeners.Close` 先在所属锁下封闭并接管整张连接登记表，再取消会话；TUN 停止收发／移除 NIC 并停止 TCP 调度器后，关闭所属连接并加入流协程，最后关闭及等待完整协议栈；已进入关闭的连接／TUN 流不再逐项竞争共享登记锁，流表在所有流协程结束后整体清空。开放期间的登记／注销仍由同一锁保护，晚到连接被拒绝并关闭；TCP／UDP 入口与数据报中继检查取消，取消后不启动无用拨号、复制协程或大缓冲区分配。关闭仍等待泵、转发器、流协程及协议栈退出，不通过清空登记表推断线程已经结束。

当前非校园出口复用系统原路由的 `net.Dialer`。 必须走校园通道的拨号先匹配服务器授权资源，拒绝未知资源、未支持的 IPv6／协议及原网络 DNS 回落；IPv4 映射地址按 IPv4 授权匹配。校园专用解析复用 `ResolveCampus`，保留学校内置解析与域名授权。普通 HTTP／SOCKS 路径中，已匹配学校域名资源的解析也禁止公共 DNS／来源未知缓存和失败后原网络回落；尚未支持的校园 IPv6 返回拒绝。DNS 缓存标记隧道内解析来源，校园查询可复用该类回答而不复用未知来源；保持既有寿命、容量和会话隔离。旧上游 HTTP／SOCKS 串联构造参数没有产品调用，已与专属实现／测试一并删除；Clash 上游联动由 S6 的实际入口与恢复验证后接入，不保留第二套待用出口配置。

<a id="transparent-packet-ingress"></a>

`service.Listeners.AttachTUN` 接收由调用方提供的原始 IPv4 包设备，仅成功时取得所有权；每次读写一包，设备关闭须能中断 I/O。独立 gVisor 入口终止本机 TCP／UDP 流，复用现有 `Dialer.DialCampusIPPort`、服务器授权及原网络保护，再由会话已有校园栈发送，不创建第二个校园 L3 读取者。捕获流禁止直连回退；SOCKS、CONNECT 与透明 TCP 共用半关闭／错误转发，UDP 保留报文边界、空包及分片，空闲 90 秒释放。最多 256 个活跃流／待握手，停止关闭所属连接及设备、撤销入口 NIC，并中止迟到握手后等待全部工作退出。包入口不配置地址、路由或 DNS。`Session.AttachTUN` 复用所属监听器，`bridge.Engine.AttachTUN` 只允许当前就绪连接代次交付设备；失败保留调用者所有权，停止／运行失败关闭设备并等待工作退出，重启不继承旧设备。设备读写错误保留原始原因并以网络操作错误进入既有会话分类，权限／超时优先，其他设备 I/O 故障按网络失败退出。Linux／macOS 的[正式 C ABI fd 接口](CORE-ABI.md#raw-tun-fd)借用非阻塞设备并持有独立 `CLOEXEC` 副本，校验真实内核帧配置及 MTU；不改变原 fd 标志；macOS 在该入口转换 utun 地址族头，其他平台明确不支持。Qt `CoreEngine::attachTUN` 在调用线程同步保留 fd 后排队到核心线程，调用返回即可释放原引用；确认保留代次且在应用线程交付，关闭期间回应过期，销毁释放尚在队列中的引用。原生交接回归使用正式安装助手，由普通用户经真实内核 TUN／Qt／C ABI／校园协议验证 TCP、UDP 空包与停止／重启／销毁；仅助手退出时先确认客户端撤回 fd，再停止核心副本后新授权恢复，反向恢复同时核对 IPv4／IPv6 路由、规则和接口。Linux 与 macOS 的助手／Qt 会话、动态校园 DNS 与正式核心数据面已接入；Windows 透明入口、完整 IPv6 能力及实际桌面／校园仍待，当前自动验收证据与具体缺口见[计划 S5](../plan.md#s5)。

核心 DNS 为有效校园 A 回答记录原查询域名与实际 IPv4 的绑定，仅跟随 Answer 中同一 IN CNAME 链，忽略无关记录及其他类；不由 Additional 或普通代理解析缓存授予透明访问。绑定按 CNAME／A 最短 TTL 和现有 DNS 缓存寿命到期，零 TTL 留一秒首流交接窗口；最多 4096 项，容量不足整次拒绝，写入时回收过期项，不增设清理线程。每次新透明流复用学校域名协议／端口、节点组及当时的保护快照；同 IP 含已知受保护名称时不使用域名绑定授权，名称选择不绕过地址保护。校园 DNS 上游继续走严格 IP 授权接口。绑定归本次解析器所有，关闭后不可取得授权，已建立流沿既有请求生命周期结束；助手增量发布已通过隔离原生调用；DNS 应答前的自动发布确认及 Linux／macOS 应用编排已接入；运行中路由寿命协调、Windows 与真实环境验收仍待。

S4 的 `policy.ProtectionPolicy` 由生产拨号、校园 DNS 与保活共用，接收实际保护前缀、明确 IPv4 选择及原网络名称规则／精确名称例外；保护不授予校园访问权限，域名、IP、协议和端口授权继续归既有拨号层。默认／分割默认路由属于原出口策略，不作为目标范围。核心通过[版本／代次／修订 API](CORE-ABI.md#保护策略更新)完整校验并原子替换快照；名称解析结果与随后业务拨号沿用同一快照，直接 IP 拨号取当前规则。Qt 已自动安装启动地址及名称保护，并接入明确 IPv4／名称选择及撤回；[原网络快照 API](CORE-ABI.md#原网络只读快照)提供真实接口／路由及 Linux 策略规则，系统 DNS 已进入只读模型。网络变化自动协调仍待；Linux UI 仅在实际助手及核心设备确认后显示校园就绪，其他平台仍显示通道就绪。

Linux 平台另提供工作线程使用的 `readLinuxDnsSnapshot`：保留实际 `resolv.conf` 的路径、符号链接目标和内容，再从已经运行的 systemd-resolved 读取全局／接口 DNS、IPv4／IPv6、扩展端口／TLS 名称、路由域与搜索域、接口默认解析路径和安全模式。调用使用现有 Qt DBus，禁止自动启动服务，整次 D-Bus 读取限时五秒；文件及序列化结果有上限，仅在 UTF-8 可无损往返时发布文件文本，失败不交付部分结果。服务缺失单独标记，不把空列表解释为无保护域。数据经统一入口进入应用只读模型；它不是 NSS、NetworkManager 或加密 DNS 提供者的完整恢复记录。接口来源见 [systemd-resolved D-Bus 契约](https://www.freedesktop.org/software/systemd/man/258/org.freedesktop.resolve1.html)。

Windows 的 `readWindowsDnsSnapshot` 调用同目录的普通权限 `JustConnectDnsReader.exe`，在独立进程中使用[原生 MI API](https://learn.microsoft.com/en-us/windows/win32/api/mi/nf-mi-mi_application_newsession)；固定从系统目录加载 mi.dll，显式 WMIDCOM／空目标，读取本地同一组 DNS 提供者。NRPT 固定调用 Get 并传入 Effective=true，接口／后缀／可选 DoH 只查固定类；不启动 PowerShell、接受任意查询或加载调用者目录的 MI 库。命名空间／服务器统一为数组，NRPT IP 地址规范化，保留查询、回退、DirectAccess 与 DNSSEC 约束；DoH 注册不代表连接已启用。仅可选类不存在视为能力缺失；NRPT 成功空结果保留空数组，非零返回码、非空数据缺少返回码或必需提供者异常仍失败。十秒预算包含进程启动与完整读取，超时只终止这个无写操作的子进程；结果限 256 KiB，数组／结果上限 4096，完整查询及清理后才输出。Qt 保留相同 DnsSnapshot 校验，只提取白名单阶段／计时，不发布原始诊断或部分事实。读取器随 CoreRuntime 安装，生产程序拒绝测试参数；故障及库来源夹具仅编译进测试目标。原生 x64 完整结果等价已验，MSVC／ARM64 及安装路径待对应 CI；完整网络恢复仍待实现。

macOS 的 `readMacDnsSnapshot` 通过公开的 [SCDynamicStoreCopyMultiple](https://developer.apple.com/documentation/systemconfiguration/scdynamicstorecopymultiple(_:_:_:)) 一次读取 State／Setup 下的网络 DNS 字典，分别保留当前及配置来源的完整键名、服务器／搜索域／补充分域、端口和排序字段。仅复制原生文本、布尔、无损整数与容器；不支持的值、过深／过大数据或读取失败不交付部分结果。沿用 SystemConfiguration／CoreFoundation，没有私有 DNS API 或 scutil 文本解析。该视图已进入应用只读模型，但不保证覆盖 Network Extension 等解析提供者；原生同步调用没有独立超时／取消边界；此只读视图不代替所属助手的恢复记录。

按 [R11／S3-01／S7-02](../plan.md)，Linux 与 macOS 已由同一应用层会话汇总核心、分流／DNS 和网络接管的生效确认，再向主窗口与托盘发布校园就绪；失败逆向撤销自身修改。核心 `ready` 只是其中一个输入；普通流量、已有终端及真实校园验收仍按计划逐平台完成，Windows 透明入口仍待实现。界面不另建第二套就绪标志，也不维护分流／恢复规则。

`UpdateChecker` 从已加载库读取提交、工作树状态、ABI、平台／架构和 Go 版本。应用更新随 JustConnect 发布；没有独立核心版本探测、上游版本比较或运行时后端回退。

## 验证与迁移边界

`tests/coreabi/` 验证实际 C11／C++17 导出、内存与生命周期、QThread／WebEngine 共存、测试驱动认证，以及受控 TLS 网关的真实协议。S1-11 性能基线通过正式宿主测量正常／慢节点的 CPU、峰值 RSS、TCP／UDP 和 20 次认证重连，实际安装包另记录体积及离线启动自检耗时；场景与限制见 [构建说明](DEVELOPMENT.md#atrust-性能基线)。Qt 适配器覆盖旧／重复回应、取消、重启与销毁竞态；`coreengineui_test` 验证实际窗口、会话和正式协议，运行认证方式查询、短信提交、SOCKS／HTTP 数据收发与活动停止。

旧 `CoreProcess`、命令构造、输出解析、CLI 查询／版本／设备授信及 sudo 窗口已删除。测试与打包已统一通过 CMake 构建本仓库的核心库，运行组件安装固定 DLL／工具链／来源与许可证；三平台实际包运行正式应用离线 ABI 自检并审计依赖、架构、最低系统版本与签名。旧下载 action、脚本、清单、专属测试及无调用的 Wintun 分发文件已删除；包检查拒绝独立核心、旧来源目录及 Wintun（含大小写变体）。S2-02 已删除旧高级设置窗口、EasyConnect／未实现选项控件及专属运行字段；设置页和向导共用 Fudan／Custom 服务器控件，保存前通过实际 C ABI 的纯校验接口复用 Go 严格解析。升级仅补齐缺失默认值、按明确清单清理废弃键，保留有效 aTrust 设置、未知键及其他账户。旧协议保留服务器值供人工确认，但不能自动连接；配置版本和旧分组迁移由 SettingsMigrator 维护。真实校园样本、生产 TLS、Clash 共存与透明入口按 [plan.md](../plan.md) 独立验收。

公开导出的字段由默认配置维护，并排除凭据和登录 URL，不复制整份 INI 或未知私有字段；导出通过原子文件提交且拒绝覆盖源配置。导入／重置先编辑草稿，取消不改原文件；保存失败不关闭窗口。密码／TOTP 通过系统安全存储异步读写，公开字段由 ProfileService 批量提交；原生写入与 INI 提交不是跨资源事务，若公开提交失败，已验证的原生值可能已更新，界面报告保存未完成且不写明文。旧缓存先加密隔离并回读确认，不因编辑身份直接丢弃。账户级票据复用及配置用例见下文。

ProfileService 维护公开字段到 ConnectionProfile 的唯一映射（`application/profileconfiguration.cpp`）；设置与引导先组装将要保存的公开草稿，再通过同一映射生成查询／校验配置，连接与安全存储也复用它。引导未展示的网络字段从来源快照保留，密码和 TOTP 仅从安全存储或当前输入补入。设置与引导只接收来源快照并自行打开读取对象，不借用主窗口在切换时销毁的 QSettings；关闭／销毁的旧窗口不交付晚到凭据，新窗口的未保存输入也不被覆盖。

INI 格式检查由 SettingsMigrator 维护：在私有临时目录用仅所有者可读写的副本强制重新解析，随检查清理，避免 Qt 缓存丢失格式错误后重复尝试改写损坏文件。切换、迁移、公开写入及凭据来源复用此检查；状态文件的活动选择、自启动和静默启动由 ProfileManager 共用写入／失败恢复路径。静默启动保存失败会保留窗口及草稿，不能继续报告整体保存成功。

主窗口仍处理配置菜单和托盘；`ProfileService::settings()` 仍为主窗口和连接控制器的动态设置提供者保留 QSettings 后端，设置／引导已不借用该指针；不为消除底层类型而新增配置框架。平台代理与自启动按操作系统拆分，由共享 CMake 选择，只返回结构化结果；状态区分失败／取消／权限／超时／不支持及可能已修改，界面负责提示。代理查询失败不能触发设置，查询返回可能已修改时也保留待清理状态并显示原因；查询进行中请求关闭会排队恢复，确认无责任才跳过清理，后续只读查询不清空既有责任；自启动或偏好保存失败时保留设置窗口和认证材料。三平台后端已保存代理快照并按所有权恢复；当前链路的退出由 `ApplicationShutdown` 在 15 秒总预算内编排：禁止启动／重连，异步撤销代理及所属网络接管，再取消核心，并等待已有凭据、SSO 绑定续接及认证方式查询清理。失败／超时报告残留并保留事件循环与线程所有者，明确重试才再清理；不强杀线程或卸载 Go。应用 Quit 事件进入同一入口；关闭仍在查询的认证方式窗口先取消并等待清理，避免在 GUI 线程同步销毁活跃工作线程。宿主 `TerminationRequests` 将 SIGTERM／SIGINT／SIGHUP 和 Windows 控制台通知交给 GUI 事件循环；Unix handler 使用 `sigaction(SA_ONSTACK)`，不接管同步崩溃信号或在 handler 中调用 Qt。Qt `commitDataRequest` 在同一关闭入口等待有界结果，系统结束期间不弹交互对话框；真实 OS 注销、控制台关闭仍须各自验证。应用菜单提供独立的偏好入口，关闭行为通过既有 ProfileManager 的 `state.ini/Global/CloseToTray` 保存，不进入学校配置；默认隐藏到可用托盘，无托盘保留窗口。保存本身不关闭或断开，显式退出及系统结束始终进入有序关闭。领域和应用层允许 Qt Core 类型，与 Widgets 分离不表示脱离 Qt。针对性重构随功能推进，不增加协议插件框架或通用工具目录。

S2-03 将 TLS 信任策略收敛到会话配置，查询用例只复制端点与 TLS 策略，不携带账户密码。服务器编辑控件维护验证开关及可选学校 CA；旧配置默认验证系统证书，显式关闭会显示持续提示。认证、节点探测与隧道复用同一个带取消的 TLS 握手实现，失败类型通过 ABI 和 Qt 保留；不再把上游历史兼容行为当作跳过证书验证的默认值。

平台实现按 `infrastructure/platform/linux/`、`macos/`、`windows/` 归档，未支持平台的回退实现位于 `unsupported/`。外层保留公共端口适配声明、命令执行、代理校验和自启动共用规则；Windows／macOS 的原生代理 API 注入声明归各自目录。`cmake/Platform.cmake` 只按目标系统选择对应目录，主应用与原生测试复用同一入口，调用方继续使用公共接口。

Unix 的 `UnixTunDevice` 统一维护所属 fd、设备名／索引及完整连接 UUID，平台各自分配并回读后才交付：Linux 排他创建非持久原始 IP TUN；macOS 由内核自动分配新 utun，核对四字节地址族帧模式，均不附着已有设备。失败关闭私有 fd，回读未确认时保守报告可能已修改；共享隔离测试核对 fd 所有权、普通用户收发和正常／强杀清理。Linux 正式助手已复用设备及路由后端，测试程序不安装为助手；Linux 与 macOS 主应用会话均已接入正式 Go／TUN／DNS 数据面；Linux／macOS 完整矩阵及 Mac 双架构原生检查已通过，真实桌面验收状态见[权限入口](#privileged-helper-entry)和计划。运行中模型协调须结合后端所有权排除自身 TUN／路由，不能把本软件的捕获范围重新当作原网络保护目标。验证状态及剩余范围见[设备记录](CORELINK-PROBE.md#设备与权限边界)。

Linux 的 `LinuxOwnedRouteTable` 为明确原接口／IPv4 源地址建立全新专用表和精确源规则，仅为请求的非默认前缀配置直连或经网关路径；不修改原接口或既有表／规则。表／metric 派生自连接 UUID，priority 1 冲突或未知更早规则均拒绝，源地址须实际属于接口（含地址别名），接口名限 ASCII 字母、数字、下划线、点和连字符。原生全表快照以数字标识读取，索引匹配避免大表反复扫描；记录原先不存在及完整应用值。恢复先删除并回读所属源规则，确认没有新引用后才删除路由；外部引用、重复身份、失败或首次未确认的值保留责任记录，不覆盖未知设置。已确认删除后新建的同值规则不会被重试接管；linkdown 仅作为派生状态处理。`apply` 可由权限调用方提供写前存储：首次内核批次前提交完整未确认意图，失败且未发布时清空内存，可能发布时保留责任；提交后复用同一容量／表／规则检查并重新核对接口身份／源地址，避免存储等待期间的改写被接管。快照绑定本次系统启动及调用线程的网络命名空间，`recover` 在新实例中严格校验所有者、完整结构、派生表／metric 及路由／规则值后复用同一恢复逻辑；活动实例不可被替换。调用者必须先认证权限所有者的受保护记录，JSON 校验不授予恢复权限。正式 Linux 助手已复用此后端，实际 TCP／UDP 隔离验证保持严格 rp_filter；自动出口选择、IPv6、桌面授权及任意属性竞争仍待，见[原出口后端](CORELINK-PROBE.md#linux-source-routes)。

### 正式权限助手入口

S4-04 的授权入口采用平台机制；Linux 普通权限 Qt 调用方、系统部署与遗留记录扫描与系统周期恢复均通过原生及发行版包检查，Linux 实际会话编排已接入并通过本地受控联验，跨平台 CI 和桌面验收仍待。授权成功只表示可以请求受限网络操作，接管就绪仍须实际回读和连通验证。

Linux 的 `JustConnectNetworkHelper` 运行层仅依赖 Qt Core／DBus 与系统运行库，复用正式设备、源路由、捕获路由、所属 TUN DNS 及受保护日志，不包含 Go、GUI、凭据或校园策略。固定入口从 `PKEXEC_UID` 取得原账户，连接该账户与完整连接 UUID 派生的抽象 Unix `SOCK_SEQPACKET` 地址，再以 `SO_PEERCRED` 验证实际 UID／PID 及网络命名空间。协议 8 每包最多 64 KiB，仅接受完整字段的 `apply`、`extend`、`routes`、`recover`、`restore`、已恢复回执的 `cleanup` 和完成确认；参数不包含程序、存储路径或恢复 JSON。地址、MTU、明确前缀及 DNS 路由域由调用方提供；`dns` 数组必须显式存在，空数组表示仅接管 IP，非空域名复用 DNS 后端的规范性验证，客户端与助手共用解码及所属后端验证，不将夹具地址作为产品默认。

每个账户／连接在固定 `/var/lib/JustConnect/network` 下维护 root 私有目录及启动／命名空间绑定的上下文；依次建立原出口、设备、捕获及可选 DNS，再交付 fd；DNS 使用固定 `unix:path=/run/dbus/system_bus_socket`，不接受请求或环境选择另一总线。恢复先确认 DNS 释放，再撤销捕获和原出口，最后关闭设备；任一步失败保留后续操作与记录。确认应用后才经 `SCM_RIGHTS` 交付一个原始 IP fd，收端原子设置 `CLOEXEC`；控制 EOF、非法后续操作或交付失败触发助手自身恢复。新实例只读取受保护的所属记录；完成回执在客户端明确确认前保留，恢复时上下文缺失不解释为成功。退出码 0 证明回执已移除，2 表示网络已恢复但回执仍保留；新上下文采用存储版本 2，DNS 日志复用相同私有存储与检查点。仍恢复不含 DNS 目录的版本 1 记录；未知版本或声称由旧版拥有的 DNS 记录拒绝，旧助手也不能接管新版记录。`cleanup` 只清已恢复且无操作日志的回执；缺失可重复确认，回执删除后遗留的私有空目录可在锁内移除，非空未知内容及活跃记录均拒绝，不执行网络恢复。交付后的 fd 属于普通调用方，整体停止还须关闭客户端／核心持有的全部副本。系统周期恢复与助手／会话／核心 fd 整体编排已通过 Linux 自动验收；实际桌面授权及其他平台缺口见计划，S4-04 保持未完成。

活动连接的 `extend` 仅携带版本、连接 UUID 与规范 IPv4 地址数组；客户端／助手共用解析，设备源／对端、原接口源／网关及未知字段拒绝。两类后端复用 `ipv4PrefixContainsAddress`，已有前缀覆盖或重复地址不增设路由。先在原出口表追加 `/32`，确认后才在所属 TUN 追加捕获；已有规则、路由应用值、接口和地址对在写前／检查点后重核，追加意图与实际值仍由原日志维护。写入部分失败保留责任，助手按 DNS→捕获→原出口的既有顺序恢复整体连接；不通过先撤销旧路由再重建来追加。每次追加重新核对调用者网络域和独立恢复服务。成功只回确认，不重新交付 fd；Qt 串行状态覆盖追加、取消及回执，继续使用原授权连接，旧协议须更新。当前追加地址保留到连接整体恢复；过期与在途流量的安全释放协调仍待。

`DNSRoutePublisher<LinuxNetworkHelperClient>` 将核心的同代次 `dns_routes` 事件串行接到活动助手 `extend`，收到实际成功确认后才回传确认；无活动所有权、发布失败或助手丢失均拒绝，核心结束取消尚未完成的发布。Qt 主线程持续处理事件，普通程序的系统解析可等待助手完成；原生夹具的 `getaddrinfo` 在独立工作线程调用，以免阻塞 Qt 事件交付。应用策略事务期间暂拒新发布，查询可重试，避免与路由替换交错。核心复用现有 DNS Answer 链解析及授权缓存，路由发布成功后才开始授权寿命，原始手动 fd 接入仍兼容。此组件不负责选择初始接口／设备地址、就绪及整体退出；这些由应用接管编排统一管理。

`LinuxNetworkHelperClient` 在普通 Qt 线程异步检查固定程序及各级目录的 root 所有权、不可写权限、非链接 ELF 与来源／协议，再清理 Qt／加载器注入环境并启动固定 `pkexec --disable-internal-agent`。私有监听只接受 root 且 PID 等于实际启动进程的对端；收到 fd 后核对连接派生接口、内核 TUN 类型、原始 IP 帧及 `CLOEXEC`，并在交付核心前设置非阻塞 I/O。授权期间 Qt 事件循环持续运行，拒绝／取消分别分类；提交后取消须等待反向恢复及回执确认。客户端销毁只关闭通道／自身 fd，由助手处理 EOF；应用所属监视器负责回收子进程，不强杀已接管网络的助手。活跃助手意外退出会撤回 fd 并保留恢复责任，新授权实例按原连接恢复；已恢复但确认失败仅重试回执清理。测试 broker 仅在私有挂载／网络命名空间临时安装，实际 polkit 桌面交互仍待。

`ConnectionSession` 通过同一 `NetworkAccess` 端口编排启动恢复、接管与停止。Linux 在核心启动前取得当前账户／启动／网络命名空间的排他锁，读取私有目录中的规范 UUID 提示，由已认证助手核对 root 日志并恢复；提示不携带任何恢复 JSON 或高权限路径。每次连接使用新 UUID，`QSaveFile` 在首次助手请求前写入提示，助手确认恢复及完成证明清理后才删除。协议 5 增补这一恢复结果；旧助手在请求前即要求更新，存储版本仍为 2。对经认证且 root 目录确实不存在的所有者，`recover` 返回 `cleaned`，覆盖宿主写前记录尚未触发 root 写入的崩溃窗口；外来、链接、损坏或不可访问的 root 记录仍拒绝，不能按缺失处理。

Linux 通道就绪后复用 `NetworkPolicySession` 的实际资源、原网络／DNS 与核心已确认保护，在线程中生成配置，再由助手应用及回读，核心确认接收 fd 后进入 `CampusReady`。主窗口与托盘共用此状态；其他平台仍只显示通道就绪。停止／取消先恢复所属网络，再停止核心并等待终态；失败保留事件循环、责任提示与活动所有者，明确重试才继续。核心意外结束也先恢复再重连，保留原重连预算；UUID 隔离旧回应，权限拒绝不进入自动授权循环。 助手丢失且恢复失败时，由同一 `ConnectionSession` 停止核心并释放最后设备引用，但保留未解除责任；核心结束不再次发起已失败的恢复，须显式重试。普通恢复失败仍保留核心，正常断开的先恢复后停止顺序不变。恢复的空闲／进行中／失败共用一个状态，核心停止请求共用幂等入口；重复丢失、旧 UUID 和结束通知不重复授权或提前完成会话。真实 resolved、安装后的助手和正式 C ABI 已在本地完成双次启动／DNS／TCP／UDP／停止及缺失 root 记录续接；运行中网络变化与路由寿命协调、桌面授权及其他平台助手仍待，不能据此勾选完整 S4／S5。

`LinuxNetworkHelperClient` 仅在实际 fd 交付后保留已确认的类型化配置和设备身份；只有成功的追加确认才补充未覆盖的 `/32`，恢复、取消或通道丢失即失效。`linuxOriginalNetworkView` 从这些事实生成不可变读取过滤器：按名称／索引／地址核对设备，逐条精确扣除所属捕获、原出口及内核设备路由、源规则和 resolve1 设置；未知属性、额外地址、外部改变及其他接口信息保留，身份不符不发布模型。路由作用域与规范源地址参与比较，表号派生与正式后端共用。该过滤器只修正原网络读取模型，不授予 root 恢复权限，也不自动改写核心策略或内核路由。

`NetworkPolicySession` 按代次接收过滤器；准备、应用、追加和恢复期间阻止刷新及新校园选择，已有 DNS 读取完成后再排队读取最新快照，旧过滤结果不能覆盖新模型。成功接管和实际新增路由后重新读取，重复追加不触发额外读取。Linux 协议 6 起要求新建 IPv4 专用 TUN 在启用前仅关闭自身 IPv6 并回读确认，避免意外生成 IPv6 本地地址和路由；不修改原接口或全局设置，存储仍为版本 2，旧日志恢复兼容。实际安装助手联验覆盖初次接管、手动刷新、动态 DNS 追加后的原网络视图，以及普通 TCP／UDP／DNS、停止／重启和双杀后独立恢复；显式策略／捕获协调见下文，自动网络变化和过期撤销仍待。

Linux 的显式校园选择由同一 `NetworkPolicySession` 提交到 `LinuxNetworkAccess`。后者在工作线程按已确认源地址查询完整目标前缀首尾的真实出口，歧义、接口／网关变化或 DNS 路由域变化均在核心写入前拒绝；核心确认后，再沿原助手连接执行协议 8 `routes`。只有核心和助手均成功才发布新确认选择，旧代／修订回应不能完成当前事务。准备／应用期间暂停新选择、刷新及 DNS 路由追加；取消进入既有网络恢复后停止核心的路径。核心拒绝保留原状态，平台部分失败按原 DNS→捕获→原出口顺序恢复整组连接，不继续报告校园就绪。

`routes` 只接收规范的捕获前缀集合，不接受新设备、路径或命令。先复用源后端补原出口，再补新捕获，最后按原日志的删除检查点撤销旧捕获；保留项也重新核对，外部改写不被当成已确认成功。空捕获仍保留当前设备及所有者，可再次增加；新进程恢复复用原日志格式和所有权检查，存储版本仍为 2。已有原出口记录保留到整体断开，避免提前释放仍可能使用的原出口；最终恢复全部撤销，容量仍受 4096 行及完整快照限制。初始和运行中出口查询共用前缀端点推导，追加与替换共用既有后端的确认／持久化流程。

捕获规划复用同一资源／保护规则，保留已确认且仍允许的动态 DNS `/32`，新增保护或撤回校园选择同时撤销相应捕获。读取过滤随助手确认更新，不能把仍归本连接所有的原出口记录误当成原网络保护。普通调用方已在真实内核完成两次连接、明确地址选择、校园 DNS／TCP／UDP 和撤回后的实际原路由回读，部分失败及双杀恢复仍有覆盖。另已用真实助手 SIGKILL 验证应用保持事件循环、核心 fd 清零、责任提示保留、显式恢复及新连接的实际 DNS／TCP／UDP，结束保留本次真实错误；保护范围和原 DNS／IPv4／IPv6 清单完整恢复。 运行中撤回的整组验证由外层隔离夹具观察[真实进程 fork 事件](https://man7.org/linux/man-pages/man2/ptrace.2.html)，在持久删除意图之后分别确认路由仍在／已消失、设备仍在，再终止所属助手与尚受控的命令子进程；两种情况下均验证显式恢复、原清单及新 UUID 的实际流量。不添加产品故障钩子，不提高助手／恢复服务权限，测试目标限定为同一私有挂载／网络命名空间及所属进程。同 IP 的原网络端使用独立网络命名空间、veth 与普通用户 TCP／UDP 服务：选择前与撤回后收到原端专属标识，选择期间收到校园端原始载荷，包含空 UDP。原接口 IPv6 初始化完成后才采集基线，保留完整 IPv4／IPv6 与 DNS 回读。精确 `/32` 的独立捕获表增量已通过 `cf69bf8` 的九项矩阵；该证据尚不包含动态 DNS 过期／在途流量安全释放、原出口迁移与外部策略路由变化协调、重叠名称原 DNS 转发或其他平台的对应助手；这些保持待验收。地址侧切换可能中断该地址的既有连接，界面不承诺旧连接保持原路径。

固定助手的 `--recover-stale` 提供系统恢复入口，仅接受真实／有效 UID 都为 root 且无 `PKEXEC_UID` 的执行，不接受路径、恢复 JSON 或其他参数。它扫描固定私有目录，从可信文件取得账户／连接与当前启动／网络命名空间，再复用交互入口的同一存储、应用和反向恢复生命周期；不依赖 GUI PID 仍存在。持锁连接计为活跃并跳过；畸形、跨命名空间、链接及未知项报告失败，保存完成回执供新 GUI 确认。每轮最多检查 4096 项，超量返回失败及明确的限额标志，不把部分扫描当成成功；输出仅为计数摘要，退出 0 不表示活跃连接已被撤销。

<a id="linux-network-observation"></a>

Linux 活动连接每两秒通过现有 `NetworkPolicySession` 读取完整原网络、资源和 DNS；模型读取与助手操作串行，停止时取消后续观察。`refresh` 仍只负责读取，活动 Linux 编排器再显式调用 `synchronizeProtection`，从最新模型重建地址／名称保护，保留用户已确认的校园例外。有效范围未变化不提交新修订；发生变化时复用核心→原出口／捕获的双确认事务，成功后才发布新保护。界面在读取期间保留上次列表及选中行、禁用旧数据操作，失败或代次结束清空，不把旧行当作新确认。

`linuxOriginalExitSnapshot` 比较原接口身份／源地址、所属 IPv4 路由、默认／分割默认路由与外部策略规则，排序消除枚举顺序差异；不使用已被自身源规则固定的查询来证明原出口未变。普通新增覆盖接口／路由可动态进入保护。原出口或策略路由变化由 `NetworkAccess::restartRequired` 请求同一会话恢复：仅接受当前 Running 代次一次，保留原连接意愿，正常路径先确认所属网络释放再停止核心，恢复失败则保留责任并阻断新启动；两端释放后，用户启用自动重连时复用现有五次／30 秒上限与持续就绪 60 秒重置预算，重新准备实际出口并分配新 UUID，关闭自动重连则恢复后结束。手动断开／退出取消重连；真实认证失效、权限或恢复失败不被合成的网络错误覆盖，不自动重复授权。完整读取失败、尚不支持的 DNS 路由域变化及自动事务失败仍走普通失败恢复。原地改写活动源规则及保持既有流量的迁移未实现。原设备真实消失后，仅在名称和原索引均未被复用时清理已确认的所属源规则；改名、替换、未知引用及外部值仍保留责任。

新增自动出口恢复已通过本地 31 安装场景：保持已改变的网关完成第二次连接、实际 TCP／UDP，新 UUID／重连次数及恢复前无新启动均有断言；禁用重连的原场景保留，跨平台 CI 待。针对性会话测试另覆盖旧代／重复、恢复拒绝、认证失效、预算耗尽及手动取消，证据 `build/reports/network-restart.json`。

本地原生增量通过覆盖网络加入／移除后的实际原端→校园 UDP（含空报文），以及默认出口改变后的自动恢复、fd／提示清理和新 UUID 实际 TCP／UDP。普通用户通过同一已安装助手、C ABI 与真实 resolved 完成，原 DNS／IPv4／IPv6 清单保持完整；源设备删除、策略双确认／失败／旧代和界面选中行另有针对性回归。`c309971` 的三平台 Tests 与六组 Core ABI 已通过，30 安装场景与构建证据归 `build/reports/network-observation.json`；桌面／真实网络迁移及其他平台仍待。

系统包提供 `justconnect-network-recovery.timer` 和同名 oneshot service，由 system manager 在 `system.slice` 运行，权限限定为 root 与 `CAP_NET_ADMIN`。定时器启动一秒后检查，此后每次服务结束五秒后再次检查，时间精度一秒；服务不保留 active 状态，避免阻止后续触发，依据 [systemd.timer](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html)。服务仅可写固定状态目录，父子目录由 `StateDirectory` 创建为 0700。安装包后管理员须执行 `sudo systemctl daemon-reload` 和 `sudo systemctl enable --now justconnect-network-recovery.timer`；GUI 不自动启用服务。每次应用／追加前，助手以固定受信 `systemctl` 和最小环境核对定时器运行、服务身份与当前网络命名空间；未启用或命名空间不同即拒绝，尚未写入网络。恢复／回执清理不依赖定时器仍启用。

隔离验收由真实 system manager 启动相同程序及沙箱，先验证实际 Qt／核心持有 TUN fd 完成收发时不干扰活跃所有权，再强杀 Qt／核心与助手并观察独立定时恢复，无新 GUI 或手工恢复命令。仅助手退出、核心仍持有副本的回归验证先停止核心、再由新授权实例恢复；应用层另外保留未解除责任并阻止新连接，实际会话编排的本地联验见下文。同一隔离 resolved 夹具覆盖正式 Qt 调用方的系统解析与 DNS 故障恢复；先在当前挂载域保留原管理器通道／日志，再隔离 `/run`，复用原生管理命令而不模拟 systemd 输出。恢复服务只读绑定隔离 DNS socket，权限不扩大。测试不覆盖真实桌面注销或发行版差异，不能据此勾选完整恢复任务。

Linux 系统助手由 `infrastructure/platform/linux/helper` 独立构建，只查找发行版 Qt Core／DBus；`scripts/build-system-network-helper.sh` 清除 GUI SDK 的加载／查找环境并保留 runner 构建工具路径，再由系统 qmake 定位开发包。CMake 复用同一后端和源码来源记录，`dpkg-shlibdeps` 生成实际 Qt／libc／C++ 依赖及最低版本，另明确依赖 iproute2、polkit 与 systemd。DEB 仅含助手、固定 polkit 策略、许可证、源码版本及恢复服务／定时器六个文件，不捆绑 Qt 或安装脚本；GUI 的 `CoreRuntime`／AppImage 不携带此提权部署。协议／上下文版本、安装路径、授权程序／动作、状态目录及恢复单元统一归 `resource/network-helper.json`；安装后的 ELF 不保留 SDK RPATH，实际执行路径必须匹配固定入口。`--version` 可由普通进程读取协议、Qt 与源码状态。

策略仅对活动本地会话请求 `auth_admin`，不保留授权、不允许 GUI 环境注入；程序与依赖由系统包管理器维护。包检查拒绝可写／非 root 项、链接、额外程序／维护脚本、放宽的授权范围和错误源码。当前本地已在私有 `/usr`／`/var/lib`／网络命名空间验收安装入口与外来路径拒绝；开发阶段仅在该命名空间复制必要 SDK 库，不能算发行版包验收。真实发行版 Qt／DEB 及双架构预览包由 Ubuntu 26.04 CI 验收，其他发行版与旧系统仍待；不在日常系统安装测试程序或接管网络。桌面授权及安装后的 Qt 调用仍需独立验收。

助手只复用已验的设备／路由／恢复后端，不链接 VPN 核心或 Widgets／WebEngine，不接受 shell、任意程序、路径或未经认证的恢复 JSON。高权限运行时的可执行文件及非系统依赖须来自受信部署；当前开发测试程序的 Qt RUNPATH 指向用户可写 SDK，因此不能直接当成正式提权部署。Linux AppImage／只读包须先完成受限助手及依赖的受信安装，再使用固定授权入口；不以 AppImage 挂载只读代替来源校验。连接数据、保护记录与实际修改仍由所属后端维护；安装、批准、对端认证、原生操作及回滚须分别验收，当前隔离 root／管理员测试不代替桌面授权。

Unix 的 `UnixNetworkJournal` 由 Linux 源／捕获／DNS 与 macOS 捕获后端复用，存储所属意图及恢复检查点：只接受显式打开的 root 私有目录描述符，独立打开描述并持有非阻塞独占锁；固定记录文件须为 root 所有、0600、单链接的普通文件，目录须为 0700，拒绝符号链接及隐式当前目录。记录使用共用的 2 MiB 恢复预算及连接 UUID，已有记录必须显式载入；更新／删除比较完整原字节和文件身份，同值替换或确认删除后重建不接管。私有临时文件完整写入并 fsync 后原子发布，再同步目录；首次发布不替换并发出现的文件，删除同步失败可重试。调用方先验证可信来源，恢复仍由所属后端校验全部字段及启动／接口身份；Linux 另核对网络命名空间。`apply`、`restore` 和新实例 `recover` 共用同步检查点端口：应用值确认、删除开始及规则释放均由后端提交，空对象请求持久移除记录；调用方只适配存储。每次删除前写记录后重读引用／完整应用值和接口身份；存储失败不继续下一次内核修改，最后同步删除失败保留内存责任供重试。新进程看到删除已开始且匹配对象仍存在时保留并报告结果不明，不猜测它是原项还是外部同值重建；对象已消失则可完成剩余恢复。Linux 系统助手、应用会话与周期恢复复用此日志并已通过自动验收；macOS 原生助手与完整会话已通过双架构检查，实际桌面授权／注销及产品交付仍待。

同一对象的 `createIpv4` 在交付前配置规范的点对点 IPv4 `/32`、MTU 与启用状态，回读地址、对端、掩码、MTU、标志及接口身份后才发布成功。快照记录连接、设备及配置前／实际应用值；失败关闭尚未交付的私有设备，不修改或恢复已有接口。Linux 复用受信 iproute2 批次，macOS 使用受信系统 ifconfig；共享原生读回不假定设备初始为 down。Linux 系统助手与 macOS 签名助手及核心 fd 接入均复用该入口和内核地址回读；Linux 地址避让、应用编排及恢复已通过跨平台 CI，macOS 完整会话已通过双架构原生检查，完整验收状态见计划。

Linux 的 `LinuxTunRoutes` 将当前捕获操作委托给共享 `LinuxOwnedRouteTable`：校园捕获使用 UUID 专用表和 priority 2 规则，原出口使用另一专用表与 priority 1 精确源规则，local 表仍最先；既有 main 路由保持原样。两种角色共用写前记录、完整回读、恢复检查点及未知／外部值保留规则，捕获与源记录分别保存在各自 root 私有操作目录，复用 `UnixNetworkJournal`。当前捕获记录为版本 2；详见[独立捕获路由表](CORELINK-PROBE.md#linux-独立捕获路由表)。

旧 main 表版本 1 路径仅用于升级恢复，已删除创建、追加及运行中协调入口。恢复仍核对启动／网络命名空间、UUID、设备索引、原先不存在及完整应用值；未确认应用或删除已开始却仍匹配的项保留，不猜测同值重建。停止支持可能遗留版本 1 记录的版本后，再删除该恢复代码和专属回归。Linux 主应用、正式核心数据面与独立恢复已通过对应三平台 Tests／六组 Core ABI；实际桌面与校园验收、其他平台助手及完整网络迁移仍待，证据见[计划](../plan.md#s4)。

<a id="macos-owned-routes"></a>
macOS 的 `MacTunRoutes` 仅为当前拥有、已配置点对点 IPv4 的新 utun 添加捕获；`/sbin/route` 使用固定参数及空继承环境，不接收任意程序、路径或命令。`NET_RT_DUMP` 从原生路由消息读取有界完整 IPv4 清单，保存地址、接口、标志和指标；仅忽略使用／报文计数及派生接口引用位。规范前缀不得捕获自有源／对端，已有相同前缀保留并拒绝，暂不支持同 IP 的原路由替换。`RTF_PROTO1` 作为自有捕获标志，含义依据 [XNU route.h](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/net/route.h)。

捕获记录绑定启动 UUID、连接 UUID、utun 名称／索引和地址对，写前意图、完整回读确认、删除开始及完成移除复用 `UnixNetworkJournal`。首次原子发布分别使用 Linux `RENAME_NOREPLACE` 和 macOS `RENAME_EXCL`，固定文件名与 Linux 存储格式不变；已有日志、同步失败、链接、同值替换和外部改写的拒绝语义保留。同前缀的其他作用域／内核派生项通过完整已应用值与所属父路由区分，不按前缀唯一性判断。新恢复进程只消费由权限入口认证的 root 私有记录：未确认应用或已开始删除的匹配值保留；已消失或完整属性不同的路由只解除原责任，不改写当前值。设备改名／索引复用或地址对变化时保留责任。

原生夹具在 fd 交付前调用正式 macOS 捕获后端，已删两处 Python 手写路由；C ABI 流量之后，先在普通调用方仍持有 utun fd 时撤销捕获，再验证最终 fd、接口及路由清理。保护日志、部分失败、指标改写、已有精确路由和新进程恢复由同一后端验证。此增量的当前本地／原生状态见[计划](../plan.md#s4)，不代表完整应用接管已验收。

macOS 权限入口使用应用内 `SMAppService` LaunchDaemon 和固定的特权 Mach 服务，布局／协议由 `resource/network-helper-macos.json` 生成；root 进程只链接 Qt Core 与系统安全框架，复用上述设备、捕获及日志，不链接校园数据面或界面。双方逐条以 [SecCodeCreateWithXPCMessage](https://developer.apple.com/documentation/security/seccodecreatewithxpcmessage(_:_:_:)) 校验消息签名、角色标识、相同叶证书与 hardened runtime，拒绝调试／禁用库验证的身份；内核连接要求只设置一次。网络应用另需已授予的 `system.services.systemconfiguration.network` Authorization Services 凭据（[Apple 网络配置规则](https://github.com/apple-oss-distributions/Security/blob/main/OSX/authd/authorization.plist)），按实际网络配置操作授权，服务端只验证，不弹窗或扩展权限。客户端在工作队列注册／授权，通过 Qt 排队回调交付非阻塞 fd；事件和回应绑定实际原生连接，替换连接后丢弃旧回调，避免撤销当前会话。无证书的预览包明确报告不支持。

协议 4／存储 1 将 root 私有记录限定为当前内核启动 UUID、XPC 调用方 UID 和连接 UUID，调用方不能指定程序、目录、接口或其他用户。写前记录创建／设备／捕获阶段，正常恢复保留持久回执直至客户端确认清理；断开、服务退出和重启扫描复用同一恢复路径，其他存活连接与未知／外部记录不接管。旧启动下的磁盘记录保留，不据此修改当前内核网络。双架构原生夹具已验证真实网络授权、普通用户 fd／UDP、持 fd 撤销、取消／EOF／助手强杀及重启恢复；签名夹具与整包重签均保留助手角色标识，包审计独立核对应用和助手实际签名标识。权限助手基线已通过完整矩阵和六组实际包；当前 DNS 动态追加及 Qt／Go 双会话已通过双架构原生检查与完整矩阵，证据见计划。已有 Mac 包为较早源码的临时签名包，真实系统设置批准、当前 Developer ID 签名包及原出口重叠保护仍待。临时证书与直接 bootstrap 的 CI 服务不能替代桌面注册批准。

macOS 协议 5 的 `extend` 仅接受规范单播 IPv4 数组，必须来自当前持有该连接的同一签名 XPC peer；不能接管其他存活或已脱离的连接，也不增加授权入口。助手先核对 guardian 与捕获记录，再复用原写前意图／内核回读／成功检查点追加 `/32`；已覆盖地址幂等，外部精确路由保留并拒绝。已有捕获也逐项核对，部分失败仍先释放 DNS，再恢复整组捕获；存储格式仍为 1，新进程复用同一恢复路径。

`DNSRoutePublisher<Helper>` 为 Linux 与 macOS 共用确认关联、串行请求、旧代拒绝和结束取消，不维护第二份解析绑定或路由规则。助手确认后才回报核心 `acknowledgeDNSRoutes`；失败／所有权丢失拒绝确认。Linux 与 macOS 正式会话均使用该协调器；Mac 原生签名夹具同时覆盖 CoreEngine 端口与完整 Qt／Go 双会话，状态及证据见计划。

macOS 的 `MacNetworkAccess` 复用 `ConnectionSession`／`NetworkPolicySession`：先取得当前账户／内核启动的应用锁并经助手发现、恢复及确认旧回执，再启动核心；实际资源／保护和既有 DNS 共同预留地址，助手配置完成并交付原生 fd、Qt 队列及 Go 确认后才报告校园就绪。停止先恢复 DNS／捕获和回执，再停止核心；取消、失败及助手丢失继续沿同一入口处理。助手丢失后若恢复失败，仍停止核心释放设备，保留未决责任与新连接阻断，明确恢复确认后再重连。探测／注册／授权尚未写入网络时，取消立即释放当前请求与会话责任；后台结果按同一请求 UUID 校验，迟到授权在引用释放时撤销，不能批准或覆盖新请求。授权提供者可在后台返回，退出不等待它；真实系统授权窗口和同时强杀应用与助手的验收状态见计划。Mac 无网络命名空间，不额外保存用户路径下的恢复凭据；root 日志仍为恢复权威。

协议 5 的成功应用／追加回应携带完整已确认捕获记录、设备派生 IPv4 路由及 DNS 视图；请求仍限制 64 KiB，回应预算由既有日志上限和设备／DNS 信封派生。捕获记录的只读校验与 root 恢复共用，Qt 不由前缀猜测所有权。原网络过滤在当前原生 RIB 完整匹配记录后才扣除对应读取行，保留额外字段、外部地址及改变的 DNS；此读取投影不授权任何恢复写入。地址预留复用 Linux 的解析逻辑，无产品测试地址默认值。原网络变化先安全恢复并按会话重连预算处理；macOS 运行中手动覆盖／精确路由替换仍待，拒绝更新并保留已确认策略，不能据此声称完整重叠地址已可用。真实桌面批准、签名包及校园验收另见计划。

<a id="owned-tun-dns"></a>
macOS 的 `MacTunDns` 在独立 SystemConfiguration 会话中为连接 UUID 发布临时 IPv4 服务绑定与 supplemental DNS：接口、地址／掩码来自已配置 utun 的内核回读，DNS 端点为实际 peer，只接受明确的规范域名。两项均要求原先不存在，逐项添加并回读；不设置 Router、默认域或全局 DNS；显式使用 Apple [VPN.DNS](https://developer.apple.com/documentation/devicemanagement/vpn/dns-data.dictionary) 定义的 `SupplementalMatchDomainsNoSearch=1`，防止系统把校园后缀合并到全局搜索列表。域名校验与 Linux 共用，助手协议 5 的必填 `dns_domains` 数组，空数组表示禁用；磁盘存储仍为 1。

[SCDynamicStoreAddTemporaryValue](https://developer.apple.com/documentation/systemconfiguration/1437789-scdynamicstoreaddtemporaryvalue) 将临时键绑定到发布会话；关闭或进程终止只删除仍属于该会话的值，其他会话即使写入相同值也转移所有权。因此 DNS 无需另存恢复日志，正常停止、部分失败和连接丢失先关闭该会话，再恢复捕获与设备；磁盘记录改变不妨碍释放仍持有的 DNS 会话。原生夹具覆盖部分发布、外部同值改写／命名冲突、默认路由不变及普通用户系统解析；Qt／核心完整会话与真实桌面批准仍待，验收状态见计划。

Linux 的 `LinuxTunDns` 为本次新建、已配置的 TUN 设置 peer 地址上的 DNS 端点、明确路由域和 `DefaultRoute=false`，接口原先须无 DNS／域配置。权限工作线程传入可信总线；读取和写入固定 resolve1 API，不自动启动解析服务，缺失时报告不支持。API 依据 [resolve1 契约](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.resolve1.html)。配置成功证明原生值已回读；核心在该 peer 的 53 端口提供 IPv4 UDP／TCP DNS，设备地址由内核回读，不另设产品地址常量。

版本 1 记录绑定连接 UUID、启动／网络命名空间、接口索引／名称／地址对及总线／服务实例；修改整体有十秒预算。每次读取由总线取得服务进程 PID，在本域持有一个已绑定 netlink socket，并在该进程的内核 netlink 表中核对其唯一 inode；表不可读、超限或不含该 socket 时返回不支持，不按接口索引猜测归属。无需读取受 ptrace 权限限制的 namespace 链接，也不增加恢复服务的 capability；内核表按目标进程的网络域过滤，依据 [proc 进程网络域](https://github.com/torvalds/linux/blob/v6.12/fs/proc/proc_net.c)及 [netlink 表](https://github.com/torvalds/linux/blob/v6.12/net/netlink/af_netlink.c)。每次设置一个属性前保存完整意图，原生回读后才确认；三项配置整组比较，外部改写保留。未确认应用及恢复开始后仍匹配旧值的配置不在新进程中猜测归属；确认释放先持久记录，再移除回执，失败重试不会接管外部同值重建。复用 `UnixNetworkJournal`，TUN 地址身份检查由路由与 DNS 共用，resolve1 标识由读取与设置共用；权限助手在可读取 namespace 链接的授权入口继续比较原生身份。真实 resolved、规范系统总线路径及系统 DNS 均在私有挂载／网络命名空间验证，包括不同命名空间同索引拒绝、普通用户 `getaddrinfo` 经 TUN 收发 DNS、部分失败、外部改写、回执重试及强杀后的保护文件恢复。上述后端检查与新进程恢复均限制为 `CAP_NET_ADMIN`，夹具由外层 root 进程预开宿主 namespace fd 并传入低权限进程，仍比较原生身份以拒绝宿主，规范系统总线 socket 也核对原身份；不依靠提权让检查通过。后端已进入正式助手的应用／恢复生命周期；原生夹具验证普通用户经助手获取 fd 后真实系统解析、DNS 恢复失败时保留捕获与原出口、受限新进程恢复。查询和 TUN 回包夹具已共用。实际安装入口的 DNS／system manager 联合验收已通过 SDK stage 本地和发行版双架构 CI：普通 Qt 调用方经授权取得 fd 后执行系统解析，错误调用方总线地址不改变助手固定总线；真实恢复服务绑定同一隔离 DNS 总线，保持生产 `CAP_NET_ADMIN` 沙箱，持锁跳过及双杀后的 DNS／路由恢复有回归，原接口 DNS 和 IPv4／IPv6 清单保持一致。安装验收同时保留独立后端 fd 夹具和正式核心数据面：普通 getaddrinfo 经系统解析器、助手所属 TUN 和核心校园解析回答，随后做真实校园 TCP／UDP；正常停止／重启／销毁及实际系统定时器双杀恢复核对原接口 DNS 和 IPv4／IPv6 清单。本地补验中，同一隔离环境的独立原网络 UDP DNS 记录公共／原网络测试域名的 A／AAAA 查询，校园名只进入核心；普通 localhost 解析及本机 TCP 连接仍为回环。核心复用现有校园 ACL／名称保护，不新增监听端口配置或第二个校园包读取者。远程回复保留完整 DNS 记录、TTL 与 CNAME，UDP 超限截断并支持 TCP；学校 DNS 禁用、无授权、受保护或非校园名称均不会偷偷回退到原网络／公共 DNS。当前透明入口拒绝 AAAA，校园路由域内受保护名称的原网络转发、动态地址释放协调、应用接管编排、真实 MagicDNS／桌面及其他解析提供者／平台仍待。

系统代理端口取 ConnectionSession 的活动监听快照，冲突检查和模态确认按连接代次隔离。SystemProxySession 继续在 QtConcurrent 工作线程串行执行用例，产品调用改由 `ProxyRecoveryBackend` 委托同包 `JustConnectProxyRecovery`：独立进程仅持有同一正式平台代理后端及其快照，不链接 Go／Widgets／WebEngine，不提供通用命令或提权入口。客户端的私有本地通道固定接受查询／应用／恢复，64 KiB 完整 UTF-8 帧、规范端口和完整回复校验；每次请求含启动最多十五秒，失败／超时关闭通道并保留未确认责任。私有协议 2 在启动前分配责任 UUID，每次开始无旧责任的新操作更换标识；严格续接从启动起只接受对应作用域的受保护记录。敏感快照删除并回读确认后才发布独立的受保护完成证明，只含版本、责任标识与机器身份；每个存储范围仅保留一份。快照缺失且无匹配证明时保持未决，后来出现的其他记录或同值副本不删除。清理通道中断在原预算内最多重连一次，应用与查询不重放。已有原生快照格式继续读取，作用域封装和确认均复用原凭据存储与日志。宿主退出／强杀使通道断开，恢复进程继续按原后端撤销自身修改，拒绝时保留快照并退避重试；Linux 使用按有效用户标识派生的固定 `/tmp` 锁，数据目录或 `TMPDIR` 改变不能创建第二个所有者；同时持有当前数据目录的旧锁以阻止同目录旧版所有者与升级进程重叠；任一锁不可用即拒绝，不回退到其他目录。Windows 同时持有按进程 SID 固定的系统互斥量和当前数据目录旧锁，握手汇总两者，任一不可用即明确拒绝且不运行后端；旧锁保留到停止支持仅使用旧锁的进程。macOS 改为固定 `/var/tmp/JustConnect-system-proxy-recovery.lock`，仅在父目录是 root 所有的 sticky 目录时使用，并同时持有旧数据目录锁；任一条件失败由同一握手拒绝，不运行后端。双架构及应用原生用例已验证不同根／账户的排他、外来遗留锁保留、旧锁拒绝、EOF 与强杀后同账户重新取得所有权。Unix 通道在私有临时目录内，Windows 限同一用户；[Qt 的权限说明](https://doc.qt.io/qt-6/qlocalserver.html#socketOptions-prop)明确 macOS 不依赖 socket 模式位，因此保留目录隔离。普通关闭仍须等待明确恢复确认，再停止核心；进行中的应用与已请求恢复保持同一忙区间。三平台恢复进程通过受保护凭据存储保存记录，新进程先恢复旧记录才允许新应用；macOS 产品接入亦通过双架构与应用原生验收。启动查询和通道断开也可能恢复旧记录，客户端从启动成功起保留未决责任，仅明确拒绝所有权或完整回复确认无责任时释放；查询不能丢弃已有应用责任。适配器的加载／恢复阶段收敛为未载入、就绪、恢复中与已确认四态，完成缓存区分未读取和已读取空值。同一客户端的缺失／不同所有者、同值重建、证明畸形／写入失败及重试边界已通过本地和三平台原生回归；同源码六组实际包核对了私有协议 2、依赖及来源。无人值守启动／注销与实际桌面授权仍待，不能据此勾选 S2-06／S3-05／S4-06／S7-03。

三平台正式后端在首次修改前保存原值，恢复时保留外部新值；已确认恢复的项立即解除责任，通知失败的重试不接管后来出现的同值设置。Linux 记录已释放的键，Windows 按字段记录已恢复／外部接管项并移除无剩余责任的连接，macOS 在提交并回读后只重试激活通知；恢复目标已等于当前完整字典（含原先不存在）时不重复写入或提交，仍核对原值并确认激活。Windows 按 LAN／RAS 连接记录 WinINet 状态，macOS 使用 SystemConfiguration 锁定并提交原生字典，Linux 分别处理 GNOME／KDE 的实际配置类型和依赖开关。PAC 地址等未管理字段保留；禁用服务保持原样，新增对象不被恢复流程接管；macOS 已删除服务不重建。KDE 命令行不能安全写回含用户信息的旧代理 URL 时在修改前返回不支持。原生写入回归使用临时 runner 或私有配置；桌面授权、Clash 和校园实测的缺口不由这些用例代替。

`PlatformSystemProxyBackend::recoverySnapshot`／`recover` 是同一后端的新实例交接端口；记录绑定机器、连接 UUID 及平台范围，校验失败不触发原生操作。Linux 还绑定用户、配置目录、桌面及 GSettings／dconf 上下文；macOS 用二进制属性列表保留完整原生类型，Base64 只作编码；Windows 保留每个 LAN／RAS 的 flags、代理、绕过和 PAC 原值及字段释放位；schema 3 还记录写入意图／确认、未决恢复及不确定字段，拒绝尚未用于产品持久化的旧导出。记录含敏感数据，不可存入普通配置或日志。三平台的同步检查点端口在原生写入前保存意图、回读成功后确认，恢复也在写回前保存状态；存储失败停止后续修改，并重验存储等待期间的外部变化。新实例遇到未确认写入或恢复后仍匹配的设置时保留并报告，不能区分的同值重建不重新接管。`PersistentProxyBackend` 共用同一受保护存储适配，已扩展 macOS 构造及构建；私有 Keychain 与私有 SystemConfiguration 的组合回归已通过双架构及应用原生验收，覆盖写前顺序、提供者重新打开、锁定重试与外来记录拒绝。三平台产品恢复进程均复用该适配；构造不读存储，取得平台所有权锁后才在首次操作中加载。加载失败、非规范 JSON 或原生范围校验失败保留原记录并阻止新应用；已拒绝的损坏／外来记录不在当前进程内重新绑定，外部删除不能作为恢复成功证据。未接管原生项的拒绝在宿主断开后退出，记录仍保留；暂时锁定／不可用则继续退避等待，已接管项沿原恢复路径重试。成功恢复后回读并删除记录。Windows 在恢复读取前也提交检查点，防止观察到原值后丢失释放确认，新实例不接管随后同值重建的字段；仅剩激活通知时仍须确认通知。Windows 产品接入已通过双架构原生验收。macOS 后端已接入同一检查点端口并通过双架构原生验收，产品进程已接入 Keychain，实际进程的原生端点、并发拒绝、EOF 和强杀后新进程恢复已通过双架构与应用原生验收；测试仅在一次性 runner 使用临时默认 Keychain；sudo 使用目标账户目录，夹具先核对目录归属，再核对并恢复原默认项与搜索列表，失败时保留尚有未决记录的受保护夹具。

macOS 恢复记录 schema 2 按 HTTP／HTTPS／SOCKS 端点组、绕过和两个自动模式保存写入意图、成功确认、释放、未决观察／恢复及不确定字段；未用于产品持久化的旧导出拒绝加载。未尝试提交的本次暂存编辑不接管后来匹配的外部值；新实例对未确认且仍匹配的字段保留并报告，已恢复或外部接管项不重新接管。完整字典在存储等待后重读，外部变化使本次事务停止；原生提交并回读后确认释放，激活或记录删除失败只重试剩余责任。端点未决时暂缓依赖的自动模式，外部 PAC 地址与未管理字段保持原样。复用 [SCPreferences 的排他锁](https://developer.apple.com/documentation/systemconfiguration/scpreferenceslock(_:_:))及[提交／激活分离](https://developer.apple.com/documentation/systemconfiguration/scpreferencescommitchanges(_:))；[默认 preferences 属于系统范围](https://developer.apple.com/documentation/systemconfiguration/scpreferences-ft8)，产品持久接入的桌面授权与注销仍待验收。当前固定机器锁不随账户、工作或临时目录派生；普通其他账户不得删除原账户遗留的锁，也不推断其设置可被接管，依据 [sticky 目录删除限制](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/unlink.2.html)。锁只协调排他所有者，不授予代理修改或恢复权限；旧目录锁在停止支持仅使用旧锁的恢复进程后删除。

Linux 恢复记录 schema 3 将未决恢复保存为字段集合，并继续读取已交付的 schema 2 单字段记录。读取所属值前保存观察意图，看到原值或外部值后确认释放；实际写回前保存整组意图，再完整重读组及其依赖，不在重读与写入之间等待存储。认证开关须核对原主机／端口，模式须核对所有端点与 PAC，KDE 反向绕过须核对原绕过列表。组确认丢失时，新实例保留仍匹配的所有未决字段，不猜测其归属；外部恢复原值后才完成清理。记录格式迁移不更换受保护存储键，旧格式读取兼容在停止支持对应已交付记录后删除。

`WindowsProxyRecoveryLock` 从进程 TokenUser SID 派生固定全局互斥量，显式受保护 DACL 仅授予该 SID 同步／修改状态权限，句柄不继承，获取不等待；同一线程释放。正常与遗弃状态都只证明取得排他所有权，恢复记录仍须原后端校验。产品在原握手中汇总系统锁与旧目录锁，任一失败都不读恢复记录或运行后端，并保留旧目录锁直到不再支持仅持旧锁的进程。全局命名空间按 API 契约跨登录会话，实际跨会话／不同账户进程尚未实测；原生用例检查不同临时／工作目录的进程竞争及正常／强杀后的真实内核等待状态。依据：[命名空间](https://learn.microsoft.com/en-us/windows/win32/termserv/kernel-object-namespaces)、[创建与权限](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createmutexexw)、[线程所有权](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-releasemutex)。

系统凭据存储端口位于 `application/credentialstore.h`，提供有界不透明值的读／写／删和明确状态，平台工厂位于 `infrastructure/platform/systemcredentialstore.h`。`windows/credentialstore.cpp` 使用当前用户 Credential Manager，`macos/` 使用 Keychain，`linux/` 使用 Qt DBus 调用 Secret Service；锁定和权限状态不会被当作空凭据或成功。原生回归使用隔离条目／临时 Keychain／私有总线。`ProxyRecoveryJournal` 复用该端口存放代理恢复记录，要求先载入并比较已知完整字节，写／删后回读确认；拒绝外部改写、异常空值和超限值，保留发布后确认丢失的可能结果。系统凭据 API 没有原子比较替换，调用方必须持有独占恢复锁；记录校验、作用域和原生恢复由平台代理后端负责。主窗口协调器持有串行后台 CredentialAccess，连接、设置窗口和配置引导复用它；退出先等待后台写入，再销毁配置存储。

`application/ProfileCredentials` 维护按配置命名空间、服务器／端口、完整认证身份、手机号和账户派生的存储键，以及有版本的密码／TOTP 记录。修改密码不改变键；网络／TLS 偏好不改变账户归属。迁移在来源身份改变之前运行，只有系统存储写入并回读一致后才能移除旧 INI 值；已有安全值与旧 INI 冲突时保留双方，不用旧值覆盖新值。旧 Cookie 文件缺少可靠账户绑定，只可验证后隔离保存，不自动投入登录。原生调用为同步边界，由 CredentialAccess 在工作线程串行执行；访问旧配置时先完成验证迁移，来源变化的结果不交付凭据。

认证缓存使用独立的 `authentication-cache-v1` 条目，记录服务器确认账户及不透明核心快照，密码／TOTP 清除互不影响。缓存必须绑定选定账户，SMS 可按手机号绑定；残留的 SMS 手机号不能替代 SSO 账户。CredentialAccess 复用同一串行线程池及来源检查，读写前后核对完整公开快照和缓存修订号。调用方在开始一次连接前捕获修订号，并用于该次连接的全部保存；明确清除会立即推进修订号，再排队删除，旧读写及迟到刷新不能交付或重建材料。原生清除失败保留数据并报告失败，仍阻止已持有材料的旧回调再次保存；普通断开不推进修订号。保存策略默认关闭，设置中的明确选择由默认配置维护，连接模型与界面共用该键。关闭后停止恢复／更新已有缓存，删除使用文件菜单的当前账户清除入口；普通断开保留允许保存的材料。核心确认账户和会话后即交付认证快照，不等待资源获取或隧道就绪；资源响应如更新 Cookie，会再次交付更新后的快照，相同材料不重复交付。后续 TLS／网络失败保留有效认证，明确会话失效仍按作用域清除；缓存保存事件不能表示连接就绪。连接先尝试有效缓存，缺少密码且恢复失败时才请求一次输入，TOTP 继续按原账户读取。SSO 首次保存先把服务器确认账户写入公开选择，再写其安全条目；已选 SSO 账户与缓存所有者必须一致，密码登录别名与服务器账户允许不同。正常退出等待核心停止、后台操作及首次 SSO 绑定续接完成，避免退出打断已授权保存。

`ApplicationPaths::clientDataFile` 仅定位自身旧缓存，不创建目录或明文文件；保留它用于旧版本升级迁移和用户显式清理；只有停止支持读取旧缓存的版本后才可删除。明确清理在同一后台串行入口验证删除当前配置的加密隔离副本，再删除所属旧文件，失败不误报完成，不触及账户缓存或其他配置。正式库不通过该路径持久化认证材料。

`infrastructure/settings/credentialaccess.*` 将凭据读写与旧值迁移放到单线程 Qt 线程池，使用独立 QSettings 实例；提交与结果交付前按同一配置模型核对来源文件、命名空间和认证身份，身份变化返回取消且不交付旧密码。主窗口、设置和引导共用该入口；公开批次通过 ProfileService 在同一工作线程提交，写入前另核对完整公开快照。原生失败不写明文替代值，窗口关闭不取消已授权保存，退出先等待后台写入。

配置复制通过 `SettingsMigrator::publicDraft` 与默认配置的公开字段判定复用迁移规则；只转移当前支持的公开设置及用户名，不复制密码、TOTP、存储命名空间、票据、URL 预览或未知键。来源不修改，目标不覆盖已有文件；缺失／损坏来源不能变成一个误报成功的空配置。设置窗口导入也使用同一入口，不从导入文件填充私有字段或存储命名空间。

每个 `SsoLoginWebView` 创建独立的无存储名称 QWebEngineProfile，使 Cookie／浏览器状态仅在本次登录窗口内存中存在，多个学校／账户的登录窗口不复用进程默认 Profile。实际受控 HTTP 回归先验证同一窗口能发送刚设置的 Cookie，再确认另一窗口不发送该 Cookie；同时保留内存 Profile 断言，防止改成独立磁盘 Profile。核心认证恢复使用上述独立安全缓存。 浏览器回调绑定活动网关的完整 CAS／OAuth2 路径，仅交付主框架结果并在网络提交前拦截；其他路径、iframe、其他来源或歧义票据不能完成登录。地址栏与页面导航复用协议／来源策略，HTTPS 页面可正常跳转；HTTP 仅用于明确配置的同一回环网关。Go 在认证回调的实际请求边界及门户票据返回处共用来源／路径／唯一参数校验，覆盖直接提供 callback 的调用，不依赖浏览器已经检查。专用 Page 丢弃身份提供方脚本的控制台文本，避免其中的票据／登录 URL 进入全局 Qt 日志；页面 JavaScript 与安全的内部 iframe 继续工作。

连接使用安全存储中的凭据，失败时提示并允许明确的手动登录；未勾选记住时仅交给当前会话，勾选后保存失败仍可手动连接。密码／TOTP 留空保留已保存值，删除由设置中的独立按钮确认后执行且验证删除结果。来源文件／账户身份和请求代数限制晚到结果；公开编辑另检查完整公开快照，防止覆盖较新的 TLS／网络设置。没有明确认证方式的旧“自动选择”配置需要用户确认，不能据此绑定旧凭据。未确认服务器／账户的旧凭据进入独立加密归档，不自动用于登录。配置重命名前先完成遗留迁移；删除配置明确提示原生凭据仍保留，可事先按保存账号清除。外部覆盖配置不推断其旧缓存目录，避免与同名托管配置串用。

SSO 浏览器从当前连接会话接收 TLS 策略，回调来源与策略在窗口构造时固定。学校 CA 只加入该窗口的内存 Profile，默认窗口仍使用正常信任库；不会修改全局 QSslConfiguration 或系统证书。关闭校验仅接受当前网关的可覆盖证书错误并持续提示。Chromium 会按主机缓存证书例外，因此该模式还在所有资源请求和页面导航中阻止同主机的其他来源／端口；跨端口的正常登录应配置学校 CA 并启用验证。请求拦截器只使用不可变来源，不跨线程读取控件。Qt 最低构建版本为 6.10，当前固定 SDK 仍为 6.12。

认证 Handler 只交付结构化种类、图片／登录 URL 和明确能力，不再携带无人读取的终端提示。可信设备登记要求 `trusted_device` 请求及明确 `confirm` 回应，缺少处理器、取消或过期都不能登记。后续未知服务返回固定的不支持状态，不透传服务器原文。核心统一限制单次认证等待五分钟；超时关闭本次认证且旧回应失效，重试使用新的代次与请求标识。图片、点数及响应画布上限由 ABI 契约集中定义，Go 和 Qt 分别在交付／解码边界验证；认证 HTTP 控制面通过 Session.request 统一限制解压后的响应体，业务隧道保留原有流式传输。

系统浏览器是后续认证入口的优先评估方向，见 [plan.md 的 S7-13](../plan.md#s7)。当前 WebEngine 仍负责在网关消费一次性票据前截获回调；外部浏览器的服务器跳转及 Cookie 不会自动变成 Go 会话，须先验证服务端支持的安全交接。认证入口改变继续使用现有结构化认证端口与会话代次；完成真实交接和回归之前，保留当前实现及资源。

宿主信号与系统会话结束的实现依据：[Go 与非 Go 宿主的信号约束](https://pkg.go.dev/os/signal@go1.27.2#hdr-Non_Go_programs_that_call_Go_code)、[Qt 会话管理](https://doc.qt.io/qt-6/qsessionmanager.html)。CI 的实际进程 SIGTERM、GUI 信号及会话入口模拟不代替操作系统强制终止时限或真实桌面注销验证。

原网络保护范围由 `application/networkprotection.*` 从原生网络快照推导，保留接口地址与所有路由表的来源索引，相同前缀合并来源。回环始终保护；默认和分割默认路由仅描述出口，不成为保护范围，也不把所有私网当作实际网络。结果是目标范围及来源，不推测策略路由优先级、不重新绑定物理网卡；原快照须与来源引用一起保留。同一模块计算校园 IP 区间、内置 DNS 记录与校园 DNS 的已知地址重叠，保留目标及资源来源索引；IP 区间可跨越或包含整个保护前缀。解析记录不是业务授权，缺少已知重叠也不证明动态域名无冲突；协议／端口授权仍归核心。冲突结果上限 4096 条，畸形／超限使整次推导失败，不交付部分说明。启动前地址保护与应用模型复用同一推导，明确校园选择经完整策略提交；运行中网络变化的自动提交仍待实现。

核心的同一不可变保护策略还接收原网络名称规则及精确校园名称例外。名称保护先于校园资源、内置解析和缓存；默认使用系统默认解析与原生名称拨号，保留绝对查询及原生 IPv4／IPv6 连接选择，强制校园查询直接拒绝。校园名称例外仅影响该名称的连接，仍核对学校协议／端口授权；直接 IP 及其他名称的保护不变。原生查询失败不尝试校园或公共解析，关闭取消所属原生解析；更新与初始配置共用 `ProtectionConfig`，不维护两套字段。格式及边界见[核心 API](CORE-ABI.md#保护策略更新)。Qt 在每次连接前自动安装实际地址及 DNS 名称保护；核心接受 Start 后，工作线程随该代 starting 事件向应用交付已确认的完整初始策略。IPv4 选择及撤回保留最后确认的名称规则／例外，查看模型的刷新不会隐式替换名称保护。名称选择按具体主机规范化为小写 ASCII／ACE，拒绝根域、IP 和通配符；是否在保护范围内继续由核心唯一校验。名称更新及撤回保留已确认的地址范围／选择，原子确认前只保留待提交策略，失败不覆盖；读取中／失败仍可撤回本会话确认的名称例外。网络变化自动协调尚待接入，系统解析提供者限制仍适用。

系统 DNS 结果类型归 `application/dnssnapshot.h`，平台适配由 `readSystemDnsSnapshot()` 统一选择既有原生读取实现；调用者在工作线程运行，返回值沿用状态、完整事实和失败时空数据。各平台的原生回归经过统一入口，私有总线与故障夹具仍直接注入平台读取器。

同一模块的 `campusCaptureTargets` 从实际资源和核心已确认的保护策略推导初始 IPv4 捕获／DNS 路由域。合并 IP 区间、静态解析地址及启用的校园 DNS，扣除实际保护范围，仅恢复已确认的精确地址例外；回环、0/8 和多播／保留高地址不允许例外。区间分解为去重的 `/2`—`/32`，结果过限整批拒绝，不生成默认路由；协议／端口授权仍由核心执行。不生成 IPv6 捕获前缀，当前规划不宣称透明 IPv6。远端 DNS 关闭时仅保留内置解析记录的路由域；域名从资源规范化并合并重复及父子覆盖。受保护的校园 DNS 地址或相交名称域使规划失败，须先完成原网络 DNS 转发／必要选择，不能以扩大校园域接管掩盖冲突。该规划不选择原出口或私有设备地址；初始出口查询、设备避让及 Linux 应用编排见下文；运行中撤销与策略协调仍待。

Linux 的 `prepareLinuxNetworkHelper` 在工作线程上只读准备实际助手配置：复用捕获规划，采纳核心资源快照的原接口偏好，用一次受信 `ip -N -j -4 -batch -` 查询每个目标前缀的首尾地址，保留十秒预算及完整输出上限；结果须全部同接口／源地址／网关，源地址仍在原生接口快照中，歧义、截断、外部出口不同或查询失败均不返回部分配置。`privateTUNAddresses` 使用统一的 RFC 1918 候选范围，合并并避开原接口／非默认路由、校园目标和实际系统／自定义 DNS 的 IPv4 地址；只选择未占用的连续点对点地址，空间不足时失败。DNS 快照字面量仅用作保守分配保留，不增加授权或改写解析规则。接口名称规则由原出口模块与准备共用；真实助手仍在写入前重新验证接口、源地址与所有权。原生联合夹具已使用真实快照、内核出口和生成地址，不再手填 DNS 模式的设备／原出口配置。准备不修改网络；当前已接入 Linux 应用启动／就绪／退出并通过本地受控联验；运行中变化与路由寿命协调仍待。

同一模型模块从 DNS 快照提取 `dns_namespaces`，每项保留原始表达式、角色及原快照来源（字段／行／数组项或动态存储键）。resolved 的路由域与搜索路由域分开，Windows 生效 NRPT 保留原始命名空间，不能统一解释成后缀；macOS State／Setup 的匹配域、搜索域和主域作为配置输入分别保留，不冒充最终作用域或搜索顺序。`resolv.conf` 仅提取文件内最后一个非空 search／domain 指令，保留 glibc 的列首及空白语法，不代替 NSS、LOCALDOMAIN 或其他解析提供者。畸形、NUL 与超过 4096 项均使整次模型失败；表达式不直接成为授权或已生效保护。依据：[resolved 域路由](https://www.freedesktop.org/software/systemd/man/latest/systemd-resolved.service.html)、[Windows NRPT 命名空间](https://learn.microsoft.com/en-us/windows-server/networking/dns/name-resolution-policy-table)、[Apple DNS 配置处理](https://github.com/apple-oss-distributions/configd/blob/main/Plugins/IPMonitor/dns-configuration.c)、[glibc 文件解析](https://github.com/bminor/glibc/blob/master/resolv/res_init.c)。


`originalDnsProtection` 复用原命名空间事实生成 `name_targets`，每条规则引用原数组索引，相同规则合并来源；localhost 及其子域的默认原网络范围由同一模块提供。后缀和完整名称转换为规范小写 ASCII／ACE，Windows 无点 NRPT 按名称前缀处理；不把根域扩成全部域名，也不把 macOS Setup 保存值当作当前范围。搜索配置生成无点名称范围；macOS 数值 NoSearch、显式空搜索列表、私有／作用域解析器及反向域按已知输入语义区分，不重建最终解析顺序。无法表示的表达式、非 ASCII NRPT 前缀、非法标记或超过模型预算时整次模型失败，不发布部分保护说明。每类模型项共用模块内 4096 项预算；实际核心请求仍受独立的 ABI 字节及条目限制。该结果只用于模型展示，尚未自动提交名称保护。

`application/networkpolicysession.*` 按核心会话代次聚合网络与已就绪的校园资源，在两者成功后由单个后台任务读取系统 DNS 并推导保护／冲突模型。刷新清空旧模型，缺少能力、读取失败或畸形数据不发布部分内容；新代等待旧任务退出后仅构建当前代，停止立即失效交付。底层只读调用仍按各平台已有边界完成，协调对象销毁前等待所属任务。主窗口协调器复用同一个核心，断开进入停止阶段即失效模型；有序退出先失效结果，再由既有关闭流程等待后台读取完成，保留事件循环及原有超时边界。`setCampusAddress` 为显式调用生成完整地址策略，只接受实际保护范围内的规范 IPv4 地址；移除本会话已确认的例外不受刷新后范围变化阻挡，读取未结束或失败时沿用最后确认的完整策略撤回，不猜测新范围。版本沿用已校验的原生快照，代次内修订递增；同一时刻只提交一项，确认与待确认各保留完整策略，例外及待确认身份／忙状态由其派生；匹配确认后才发布选择，失败保留最后有效值，停止／换代丢弃晚到确认。刷新不重置修订；此处尚未自动随网络变化提交。启动前地址保护由核心适配器安装。

`NetworkPolicyWindow` 在地址页展示当前完整模型的原网络范围、接口／路由来源和已知校园地址重叠，保留授权协议／端口及内置记录／校园 DNS 的角色。选择实际 IPv4 范围后可输入单个地址，调用 `setCampusAddress`；界面只展示核心已确认的 `/32` 例外，失败保留原选择，并说明学校授权及相同地址无法同时访问两侧的限制。恢复入口仅提供本会话已确认例外，读取中或失败仍可撤回。输入窗异步且归属查看窗口，代次变化／会话销毁拒绝旧输入。DNS 页并列展示原始表达式、用途、来源和名称规则模型，另列系统保留的 localhost；单独展示已确认的具体校园名称，异步输入只提交该名称，撤回列表仅包含本会话确认的例外。长内容保留完整提示，说明最近读取的模型与核心已确认策略的区别。根域明确标为默认查询范围，NRPT 保留原生表达式，macOS 已保存配置与当前配置分开。刷新失败、停止、代次变化或会话对象销毁先清空旧行；内容使用纯文本，查看及刷新不调用策略提交。主窗口“文件 → 网络范围与校园地址重叠…”复用单个窗口，关闭释放窗口；无活动连接也可打开并查看无结果提示。受控选择／撤回、确认失败、旧输入、真实协议展示、清空和查询期间退出均有回归。
