# 当前代码结构

JustConnect 将可修改的 aTrust Go 源码直接纳入 `corelib/` 单一模块。Qt 通过版本化 C ABI 在同一宿主内调用正式会话；数据转发留在 Go 内。来源及许可证见 [corelib/UPSTREAM.md](../corelib/UPSTREAM.md)，契约见 [CORE-ABI.md](CORE-ABI.md)。

## 目录与依赖

```text
presentation/     Qt Widgets、认证窗口与流程 Coordinator
application/      连接／配置／系统代理用例及基础设施端口
core/             连接配置、错误与状态规则
infrastructure/   内嵌库适配、QSettings、系统代理、日志与更新实现
corelib/          会话、aTrust、underlay、解析、gVisor、回环代理及 C ABI
cmake/            应用和原生宿主共享的 Go 库／Qt 适配构建入口
tests/            领域、端口、界面、真实 C ABI 与受控网关回归
```

`application` 依赖 `core`，不引用 Widgets 或具体基础设施。`MainWindowCoordinator` 组合 `CoreEngine → EmbeddedCoreEngine`、`SystemProxyBackend → ProxyRecoveryBackend → JustConnectProxyRecovery → PlatformSystemProxyBackend` 和 `ProfileBackend → ProfileManager`。认证方式窗口通过应用层 `AuthMethodsQuery` 使用 `CoreEngine`，允许注入测试端口；只在查询与清理均成功后交付完整方法身份，取消或失败不暴露部分结果。

## 会话与线程

`ConnectionSession` 持有连接意图、重连计时器及当前配置，使用 `ConnectionSessionState` 管理状态。`EmbeddedCoreEngine` 将配置序列化后提交专属 Qt 工作线程；每次 connect（含重连）先读取原网络与系统 DNS 快照，复用应用模型推导保护前缀及名称规则，再把默认无校园例外的完整初始策略交给核心。读取或推导失败不启动会话；原子取消标志避免工作线程读取期间收到的停止请求在读取完成后仍开始会话，既有有界退出继续等待线程所有者。认证方式查询不读取保护快照。创建、异步启动、认证回应、读取、停止和销毁都在该线程调用 C ABI。每次最多一个 Qt 事件在途，应用线程确认交付后继续读取，避免另造无界日志队列。诊断字符串只供记录，状态仅由结构化状态／终态事件改变。`observation` 将认证、恢复和维护结果及观测时间独立传入同一会话，按阶段保留最新结果，未观测显示未知。主窗口和托盘共用该状态；当前仅显示“通道就绪”，不把核心 ready 标成产品“已连接”。设置页的自动／目标／关闭经现有 Profile 及 Go 配置校验接入维护循环；主窗口／托盘分别显示会话续期、DNS／HTTP 流量保活、节点和隧道维护的结果／时间，缺少获授权资源明确提示不可用。

`AuthenticationCacheCoordinator` 统一编排认证缓存的保存、失效、首次 SSO 账户绑定与清除代次，使用现有 CredentialAccess 串行存储入口；界面控制器只处理连接意图、输入和提示，并在退出时等待协调器的绑定续接。账户键和有效性规则仍归连接模型／ProfileCredentials，存储来源与修订校验归 CredentialAccess，避免界面重排或后续重连重复维护这些规则。Go 仅通过绑定身份的 ClientData 恢复并由服务器确认账户、取得当前资源；不再保留直接注入旧资源并跳过认证的旁路。

应用重连和核心隧道重拨各自最多五次，指数退避间隔封顶 30 秒；两层预算只在持续就绪 60 秒后重置；核心按节点组保留预算，短暂连通不会重新获得次数。Go 的结构化传输错误分类排除证书、权限、协议和明确失效，不匹配错误文本。完成交互认证后允许后续网络恢复；尚在认证中的超时不自动重放登录。进入应用退避时撤销失效的系统代理，手动取消清除上一轮错误。隧道重拨耗尽会终止该会话，取消同时停止等待和拨号。

Go 的会话代次和请求 ID 全程保留为十进制字符串。`AuthDialogCoordinator` 异步展示短信、TOTP、RADIUS、内存图片验证码和 SSO；回应带原始身份。应用及 Go 都检查当前请求，旧窗口提交／取消不能影响新会话。停止不等待认证 UI；销毁先中断读取，再等待句柄与借用缓冲区结束。Unix 静态链接；Windows 从可执行文件目录固定加载随包 DLL，并保持 Go runtime 到宿主退出。

观测按适配器校验代次后的 ABI 交付顺序更新；UTC 时间仅用于展示，不用于判旧。系统校时回拨或相同毫秒内的结果仍能更新；停止后的维护事件被忽略，新连接清空上代观测。

`Session.Run` 拥有 underlay、认证／隧道、gVisor、解析器及 SOCKS／HTTP（含 UDP association），所有清理结束后才释放活动会话名额。进程只允许一个活动连接或认证方式查询。查询界面等待清理终态后才允许确认选择。系统代理由单独用例拥有，仅在用户启用自动设置时于通道就绪后应用，也可手动设置；当前库不创建系统 TUN、不改变系统路由／DNS，GUI 无需为连接整体提权。核心 `ready` 目前只证明通道与本地代理初始化完成。

当前非校园出口复用系统原路由的 `net.Dialer`。 必须走校园通道的拨号先匹配服务器授权资源，拒绝未知资源、未支持的 IPv6／协议及原网络 DNS 回落；IPv4 映射地址按 IPv4 授权匹配。校园专用解析复用 `ResolveCampus`，保留学校内置解析与域名授权。普通 HTTP／SOCKS 路径中，已匹配学校域名资源的解析也禁止公共 DNS／来源未知缓存和失败后原网络回落；尚未支持的校园 IPv6 返回拒绝。DNS 缓存标记隧道内解析来源，校园查询可复用该类回答而不复用未知来源；保持既有寿命、容量和会话隔离。旧上游 HTTP／SOCKS 串联构造参数没有产品调用，已与专属实现／测试一并删除；Clash 上游联动由 S6 的实际入口与恢复验证后接入，不保留第二套待用出口配置。

S4 的 `policy.ProtectionPolicy` 由生产拨号、校园 DNS 与保活共用，接收实际保护前缀、明确 IPv4 选择及原网络名称规则／精确名称例外；保护不授予校园访问权限，域名、IP、协议和端口授权继续归既有拨号层。默认／分割默认路由属于原出口策略，不作为目标范围。核心通过[版本／代次／修订 API](CORE-ABI.md#保护策略更新)完整校验并原子替换快照；名称解析结果与随后业务拨号沿用同一快照，直接 IP 拨号取当前规则。Qt 已自动安装启动地址及名称保护，并接入明确 IPv4／名称选择及撤回；[原网络快照 API](CORE-ABI.md#原网络只读快照)提供真实接口／路由及 Linux 策略规则，系统 DNS 已进入只读模型。网络变化自动协调及透明入口仍待接入，当前 UI 不宣称系统接管已就绪。

Linux 平台另提供工作线程使用的 `readLinuxDnsSnapshot`：保留实际 `resolv.conf` 的路径、符号链接目标和内容，再从已经运行的 systemd-resolved 读取全局／接口 DNS、IPv4／IPv6、扩展端口／TLS 名称、路由域与搜索域、接口默认解析路径和安全模式。调用使用现有 Qt DBus，禁止自动启动服务，整次 D-Bus 读取限时五秒；文件及序列化结果有上限，仅在 UTF-8 可无损往返时发布文件文本，失败不交付部分结果。服务缺失单独标记，不把空列表解释为无保护域。数据经统一入口进入应用只读模型；它不是 NSS、NetworkManager 或加密 DNS 提供者的完整恢复记录。接口来源见 [systemd-resolved D-Bus 契约](https://www.freedesktop.org/software/systemd/man/258/org.freedesktop.resolve1.html)。

Windows 的 `readWindowsDnsSnapshot` 调用同目录的普通权限 `JustConnectDnsReader.exe`，在独立进程中使用[原生 MI API](https://learn.microsoft.com/en-us/windows/win32/api/mi/nf-mi-mi_application_newsession)；固定从系统目录加载 mi.dll，显式 WMIDCOM／空目标，读取本地同一组 DNS 提供者。NRPT 固定调用 Get 并传入 Effective=true，接口／后缀／可选 DoH 只查固定类；不启动 PowerShell、接受任意查询或加载调用者目录的 MI 库。命名空间／服务器统一为数组，NRPT IP 地址规范化，保留查询、回退、DirectAccess 与 DNSSEC 约束；DoH 注册不代表连接已启用。仅可选类不存在视为能力缺失；NRPT 成功空结果保留空数组，非零返回码、非空数据缺少返回码或必需提供者异常仍失败。十秒预算包含进程启动与完整读取，超时只终止这个无写操作的子进程；结果限 256 KiB，数组／结果上限 4096，完整查询及清理后才输出。Qt 保留相同 DnsSnapshot 校验，只提取白名单阶段／计时，不发布原始诊断或部分事实。读取器随 CoreRuntime 安装，生产程序拒绝测试参数；故障及库来源夹具仅编译进测试目标。原生 x64 完整结果等价已验，MSVC／ARM64 及安装路径待对应 CI；完整网络恢复仍待实现。

macOS 的 `readMacDnsSnapshot` 通过公开的 [SCDynamicStoreCopyMultiple](https://developer.apple.com/documentation/systemconfiguration/scdynamicstorecopymultiple(_:_:_:)) 一次读取 State／Setup 下的网络 DNS 字典，分别保留当前及配置来源的完整键名、服务器／搜索域／补充分域、端口和排序字段。仅复制原生文本、布尔、无损整数与容器；不支持的值、过深／过大数据或读取失败不交付部分结果。沿用 SystemConfiguration／CoreFoundation，没有私有 DNS API 或 scutil 文本解析。该视图已进入应用只读模型，但不保证覆盖 Network Extension 等解析提供者；原生同步调用没有独立超时／取消边界，完整恢复记录仍待实现。

后续按 [R11／S3-01／S7-02](../plan.md) 将一次连接扩展为完整校园访问：同一个应用层会话汇总核心、分流／DNS 和网络接管的生效确认，通过有界检查后才向主窗口与托盘发布产品就绪；失败逆向撤销自身修改。核心 `ready` 是其中一个输入，不能直接代表浏览器与终端已可用；无需另设系统代理、修改终端配置或重开应用的要求由该流程统一满足。这一自动接管尚未实现，不在界面中另建第二套就绪标志，也不把分流／恢复规则迁入窗口。

`UpdateChecker` 从已加载库读取提交、工作树状态、ABI、平台／架构和 Go 版本。应用更新随 JustConnect 发布；没有独立核心版本探测、上游版本比较或运行时后端回退。

## 验证与迁移边界

`tests/coreabi/` 验证实际 C11／C++17 导出、内存与生命周期、QThread／WebEngine 共存、测试驱动认证，以及受控 TLS 网关的真实协议。S1-11 性能基线通过正式宿主测量正常／慢节点的 CPU、峰值 RSS、TCP／UDP 和 20 次认证重连，实际安装包另记录体积及离线启动自检耗时；场景与限制见 [构建说明](DEVELOPMENT.md#atrust-性能基线)。Qt 适配器覆盖旧／重复回应、取消、重启与销毁竞态；`coreengineui_test` 验证实际窗口、会话和正式协议，运行认证方式查询、短信提交、SOCKS／HTTP 数据收发与活动停止。

旧 `CoreProcess`、命令构造、输出解析、CLI 查询／版本／设备授信及 sudo 窗口已删除。测试与打包已统一通过 CMake 构建本仓库的核心库，运行组件安装固定 DLL／工具链／来源与许可证；三平台实际包运行正式应用离线 ABI 自检并审计依赖、架构、最低系统版本与签名。旧下载 action、脚本、清单、专属测试及无调用的 Wintun 分发文件已删除；包检查拒绝独立核心、旧来源目录及 Wintun（含大小写变体）。S2-02 已删除旧高级设置窗口、EasyConnect／未实现选项控件及专属运行字段；设置页和向导共用 Fudan／Custom 服务器控件，保存前通过实际 C ABI 的纯校验接口复用 Go 严格解析。升级仅补齐缺失默认值、按明确清单清理废弃键，保留有效 aTrust 设置、未知键及其他账户。旧协议保留服务器值供人工确认，但不能自动连接；配置版本和旧分组迁移由 SettingsMigrator 维护。真实校园样本、生产 TLS、Clash 共存与透明入口按 [plan.md](../plan.md) 独立验收。

公开导出的字段由默认配置维护，并排除凭据和登录 URL，不复制整份 INI 或未知私有字段；导出通过原子文件提交且拒绝覆盖源配置。导入／重置先编辑草稿，取消不改原文件；保存失败不关闭窗口。密码／TOTP 通过系统安全存储异步读写，公开字段由 ProfileService 批量提交；原生写入与 INI 提交不是跨资源事务，若公开提交失败，已验证的原生值可能已更新，界面报告保存未完成且不写明文。旧缓存先加密隔离并回读确认，不因编辑身份直接丢弃。账户级票据复用及配置用例见下文。

ProfileService 维护公开字段到 ConnectionProfile 的唯一映射（`application/profileconfiguration.cpp`）；设置与引导先组装将要保存的公开草稿，再通过同一映射生成查询／校验配置，连接与安全存储也复用它。引导未展示的网络字段从来源快照保留，密码和 TOTP 仅从安全存储或当前输入补入。设置与引导只接收来源快照并自行打开读取对象，不借用主窗口在切换时销毁的 QSettings；关闭／销毁的旧窗口不交付晚到凭据，新窗口的未保存输入也不被覆盖。

INI 格式检查由 SettingsMigrator 维护：在私有临时目录用仅所有者可读写的副本强制重新解析，随检查清理，避免 Qt 缓存丢失格式错误后重复尝试改写损坏文件。切换、迁移、公开写入及凭据来源复用此检查；状态文件的活动选择、自启动和静默启动由 ProfileManager 共用写入／失败恢复路径。静默启动保存失败会保留窗口及草稿，不能继续报告整体保存成功。

主窗口仍处理配置菜单和托盘；`ProfileService::settings()` 仍为主窗口和连接控制器的动态设置提供者保留 QSettings 后端，设置／引导已不借用该指针；不为消除底层类型而新增配置框架。平台代理与自启动按操作系统拆分，由共享 CMake 选择，只返回结构化结果；状态区分失败／取消／权限／超时／不支持及可能已修改，界面负责提示。代理查询失败不能触发设置，查询返回可能已修改时也保留待清理状态并显示原因；查询进行中请求关闭会排队恢复，确认无责任才跳过清理，后续只读查询不清空既有责任；自启动或偏好保存失败时保留设置窗口和认证材料。三平台后端已保存代理快照并按所有权恢复；当前链路的退出由 `ApplicationShutdown` 在 15 秒总预算内编排：禁止启动／重连，异步撤销代理，再取消核心，并等待已有凭据、SSO 绑定续接及认证方式查询清理。失败／超时报告残留并保留事件循环与线程所有者，明确重试才再清理；不强杀线程或卸载 Go。应用 Quit 事件进入同一入口；关闭仍在查询的认证方式窗口先取消并等待清理，避免在 GUI 线程同步销毁活跃工作线程。宿主 `TerminationRequests` 将 SIGTERM／SIGINT／SIGHUP 和 Windows 控制台通知交给 GUI 事件循环；Unix handler 使用 `sigaction(SA_ONSTACK)`，不接管同步崩溃信号或在 handler 中调用 Qt。Qt `commitDataRequest` 在同一关闭入口等待有界结果，系统结束期间不弹交互对话框；真实 OS 注销、控制台关闭仍须各自验证。应用菜单提供独立的偏好入口，关闭行为通过既有 ProfileManager 的 `state.ini/Global/CloseToTray` 保存，不进入学校配置；默认隐藏到可用托盘，无托盘保留窗口。保存本身不关闭或断开，显式退出及系统结束始终进入有序关闭。领域和应用层允许 Qt Core 类型，与 Widgets 分离不表示脱离 Qt。针对性重构随功能推进，不增加协议插件框架或通用工具目录。

S2-03 将 TLS 信任策略收敛到会话配置，查询用例只复制端点与 TLS 策略，不携带账户密码。服务器编辑控件维护验证开关及可选学校 CA；旧配置默认验证系统证书，显式关闭会显示持续提示。认证、节点探测与隧道复用同一个带取消的 TLS 握手实现，失败类型通过 ABI 和 Qt 保留；不再把上游历史兼容行为当作跳过证书验证的默认值。

平台实现按 `infrastructure/platform/linux/`、`macos/`、`windows/` 归档，未支持平台的回退实现位于 `unsupported/`。外层保留公共端口适配声明、命令执行、代理校验和自启动共用规则；Windows／macOS 的原生代理 API 注入声明归各自目录。`cmake/Platform.cmake` 只按目标系统选择对应目录，主应用与原生测试复用同一入口，调用方继续使用公共接口。

Unix 的 `UnixTunDevice` 统一维护所属 fd、设备名／索引及完整连接 UUID，平台各自分配并回读后才交付：Linux 排他创建非持久原始 IP TUN；macOS 由内核自动分配新 utun，核对四字节地址族帧模式，均不附着已有设备。失败关闭私有 fd，回读未确认时保守报告可能已修改；共享隔离测试核对 fd 所有权、普通用户收发和正常／强杀清理。平台后端由隔离验证调用，测试程序不安装为权限助手；主应用、Go 入口及路由／DNS 操作尚未接入。运行中模型协调须结合后端所有权排除自身 TUN／路由，不能把本软件的捕获范围重新当作原网络保护目标。验证状态及剩余范围见[设备记录](CORELINK-PROBE.md#设备与权限边界)。

Linux 的 `LinuxSourceRoutes` 为明确原接口／IPv4 源地址建立全新专用表和精确源规则，仅为请求的非默认前缀配置直连或经网关路径；不修改原接口或既有表／规则。表／metric 派生自连接 UUID，priority 1 冲突或未知更早规则均拒绝，源地址须实际属于接口（含地址别名），接口名限 ASCII 字母、数字、下划线、点和连字符。原生全表快照以数字标识读取，索引匹配避免大表反复扫描；记录原先不存在及完整应用值。恢复先删除并回读所属源规则，确认没有新引用后才删除路由；外部引用、重复身份、失败或首次未确认的值保留责任记录，不覆盖未知设置。已确认删除后新建的同值规则不会被重试接管；linkdown 仅作为派生状态处理。`apply` 可由权限调用方提供写前存储：首次内核批次前提交完整未确认意图，失败且未发布时清空内存，可能发布时保留责任；提交后复用同一容量／表／规则检查并重新核对接口身份／源地址，避免存储等待期间的改写被接管。快照绑定本次系统启动及调用线程的网络命名空间，`recover` 在新实例中严格校验所有者、完整结构、派生表／metric 及路由／规则值后复用同一恢复逻辑；活动实例不可被替换。调用者必须先认证权限所有者的受保护记录，JSON 校验不授予恢复权限。当前仅隔离调用，实际 TCP／UDP 验证保持严格 rp_filter；自动出口选择、IPv6、正式授权及任意属性竞争仍待，见[原出口后端](CORELINK-PROBE.md#linux-source-routes)。

### 正式权限助手入口

S4-04 的授权入口采用平台机制；Linux 普通权限 Qt 调用方、系统部署与遗留记录扫描与系统周期恢复均通过原生及发行版包检查，实际会话接入和桌面验收仍待。授权成功只表示可以请求受限网络操作，接管就绪仍须实际回读和连通验证。

Linux 的 `JustConnectNetworkHelper` 运行层仅依赖 Qt Core 与系统运行库，复用正式设备、源路由、捕获路由及受保护日志，不包含 Go、GUI、凭据或校园策略。固定入口从 `PKEXEC_UID` 取得原账户，连接该账户与完整连接 UUID 派生的抽象 Unix `SOCK_SEQPACKET` 地址，再以 `SO_PEERCRED` 验证实际 UID／PID 及网络命名空间。协议 2 每包最多 64 KiB，仅接受完整字段的 `apply`、`recover`、`restore`、已恢复回执的 `cleanup` 和完成确认；参数不包含程序、存储路径或恢复 JSON。地址、MTU 与明确前缀由调用方提供，客户端与助手共用解码及所属后端验证，不将夹具地址作为产品默认。

每个账户／连接在固定 `/var/lib/JustConnect/network` 下维护 root 私有目录及启动／命名空间绑定的上下文；原出口先于捕获建立，恢复按相反顺序执行，捕获未确认释放时保留原出口。确认应用后才经 `SCM_RIGHTS` 交付一个原始 IP fd，收端原子设置 `CLOEXEC`；控制 EOF、非法后续操作或交付失败触发助手自身恢复。新实例只读取受保护的所属记录；完成回执在客户端明确确认前保留，恢复时上下文缺失不解释为成功。退出码 0 证明回执已移除，2 表示网络已恢复但回执仍保留；存储版本维持 1，可恢复已部署版本的记录。`cleanup` 只清已恢复且无操作日志的回执；缺失可重复确认，回执删除后遗留的私有空目录可在锁内移除，非空未知内容及活跃记录均拒绝，不执行网络恢复。交付后的 fd 属于普通调用方，整体停止还须关闭客户端／核心持有的全部副本。系统周期恢复的隔离验收见下文；实际桌面授权和会话／核心 fd 接入仍待，S4-04 保持未完成。

`LinuxNetworkHelperClient` 在普通 Qt 线程异步检查固定程序及各级目录的 root 所有权、不可写权限、非链接 ELF 与来源／协议，再清理 Qt／加载器注入环境并启动固定 `pkexec --disable-internal-agent`。私有监听只接受 root 且 PID 等于实际启动进程的对端；收到 fd 后核对连接派生接口、内核 TUN 类型、原始 IP 帧及 `CLOEXEC`。授权期间 Qt 事件循环持续运行，拒绝／取消分别分类；提交后取消须等待反向恢复及回执确认。客户端销毁只关闭通道／自身 fd，由助手处理 EOF；应用所属监视器负责回收子进程，不强杀已接管网络的助手。活跃助手意外退出会撤回 fd 并保留恢复责任，新授权实例按原连接恢复；已恢复但确认失败仅重试回执清理。测试 broker 仅在私有挂载／网络命名空间临时安装，实际 polkit 桌面交互仍待。

固定助手的 `--recover-stale` 提供系统恢复入口，仅接受真实／有效 UID 都为 root 且无 `PKEXEC_UID` 的执行，不接受路径、恢复 JSON 或其他参数。它扫描固定私有目录，从可信文件取得账户／连接与当前启动／网络命名空间，再复用交互入口的同一存储、应用和反向恢复生命周期；不依赖 GUI PID 仍存在。持锁连接计为活跃并跳过；畸形、跨命名空间、链接及未知项报告失败，保存完成回执供新 GUI 确认。每轮最多检查 4096 项，超量返回失败及明确的限额标志，不把部分扫描当成成功；输出仅为计数摘要，退出 0 不表示活跃连接已被撤销。

系统包提供 `justconnect-network-recovery.timer` 和同名 oneshot service，由 system manager 在 `system.slice` 运行，权限限定为 root 与 `CAP_NET_ADMIN`。定时器启动一秒后检查，此后每次服务结束五秒后再次检查，时间精度一秒；服务不保留 active 状态，避免阻止后续触发，依据 [systemd.timer](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html)。服务仅可写固定状态目录，父子目录由 `StateDirectory` 创建为 0700。安装包后管理员须执行 `sudo systemctl daemon-reload` 和 `sudo systemctl enable --now justconnect-network-recovery.timer`；GUI 不自动启用服务。每次应用前，助手以固定受信 `systemctl` 和最小环境核对定时器运行、服务身份与当前网络命名空间；未启用或命名空间不同即拒绝，尚未写入网络。恢复／回执清理不依赖定时器仍启用。

隔离验收由真实 system manager 启动相同程序及沙箱，在专属文件系统／网络命名空间验证活跃所有权不受影响，并在测试 GUI 与助手同时被强杀后自动恢复，无新 GUI 或手工恢复命令。测试不覆盖真实桌面注销、发行版差异或核心仍持有的 fd，不能据此勾选完整恢复任务。

Linux 系统助手由 `infrastructure/platform/linux/helper` 独立构建，只查找发行版 Qt Core；`scripts/build-system-network-helper.sh` 清除 GUI SDK 的加载／查找环境并保留 runner 构建工具路径，再由系统 qmake 定位开发包。CMake 复用同一后端和源码来源记录，`dpkg-shlibdeps` 生成实际 Qt／libc／C++ 依赖及最低版本，另明确依赖 iproute2、polkit 与 systemd。DEB 仅含助手、固定 polkit 策略、许可证、源码版本及恢复服务／定时器六个文件，不捆绑 Qt 或安装脚本；GUI 的 `CoreRuntime`／AppImage 不携带此提权部署。安装路径、授权程序／动作、状态目录及恢复单元统一归 `resource/network-helper.json`；安装后的 ELF 不保留 SDK RPATH，实际执行路径必须匹配固定入口。`--version` 可由普通进程读取协议、Qt 与源码状态。

策略仅对活动本地会话请求 `auth_admin`，不保留授权、不允许 GUI 环境注入；程序与依赖由系统包管理器维护。包检查拒绝可写／非 root 项、链接、额外程序／维护脚本、放宽的授权范围和错误源码。当前本地已在私有 `/usr`／`/var/lib`／网络命名空间验收安装入口与外来路径拒绝；开发阶段仅在该命名空间复制必要 SDK 库，不能算发行版包验收。真实发行版 Qt／DEB 及双架构预览包由 Ubuntu 26.04 CI 验收，其他发行版与旧系统仍待；不在日常系统安装测试程序或接管网络。桌面授权及安装后的 Qt 调用仍需独立验收。

| macOS | 应用包内 LaunchDaemon，通过 `SMAppService` 管理 | 当前最低 macOS 14.4 可采用该入口；[服务注册](https://developer.apple.com/documentation/servicemanagement/smappservice/register%28%29)受管理员批准约束，[BundleProgram](https://developer.apple.com/documentation/servicemanagement/updating-helper-executables-from-earlier-versions-of-macos) 指向包内助手，界面按真实授权状态反馈。注册不代替 IPC 身份验证或网络生效确认。 |

助手只复用已验的设备／路由／恢复后端，不链接 VPN 核心或 Widgets／WebEngine，不接受 shell、任意程序、路径或未经认证的恢复 JSON。高权限运行时的可执行文件及非系统依赖须来自受信部署；当前开发测试程序的 Qt RUNPATH 指向用户可写 SDK，因此不能直接当成正式提权部署。Linux AppImage／只读包须先完成受限助手及依赖的受信安装，再使用固定授权入口；不以 AppImage 挂载只读代替来源校验。连接数据、保护记录与实际修改仍由所属后端维护；安装、批准、对端认证、原生操作及回滚须分别验收，当前隔离 root／管理员测试不代替桌面授权。

Linux 的 `LinuxSourceJournal` 由源／捕获路由复用，存储所属意图及恢复检查点：只接受显式打开的 root 私有目录描述符，独立打开描述并持有非阻塞独占锁；固定记录文件须为 root 所有、0600、单链接的普通文件，目录须为 0700，拒绝符号链接及隐式当前目录。记录使用共用的 2 MiB 恢复预算及连接 UUID，已有记录必须显式载入；更新／删除比较完整原字节和文件身份，同值替换或确认删除后重建不接管。私有临时文件完整写入并 fsync 后原子发布，再同步目录；首次发布不替换并发出现的文件，删除同步失败可重试。调用方先验证可信来源，恢复仍由同一源后端校验全部字段及启动／网络命名空间。`apply`、`restore` 和新实例 `recover` 共用同步检查点端口：应用值确认、删除开始及规则释放均由后端提交，空对象请求持久移除记录；调用方只适配存储。每次删除前写记录后重读引用／完整应用值和接口身份；存储失败不继续下一次内核修改，最后同步删除失败保留内存责任供重试。新进程看到删除已开始且匹配对象仍存在时保留并报告结果不明，不猜测它是原项还是外部同值重建；对象已消失则可完成剩余恢复。Linux 系统助手与周期恢复复用此日志并已验收；实际桌面授权、会话接入及注销仍待，不能视为完整产品恢复已交付。

同一对象的 `createIpv4` 在交付前配置规范的点对点 IPv4 `/32`、MTU 与启用状态，回读地址、对端、掩码、MTU、标志及接口身份后才发布成功。快照记录连接、设备及配置前／实际应用值；失败关闭尚未交付的私有设备，不修改或恢复已有接口。Linux 复用受信 iproute2 批次，macOS 使用受信系统 ifconfig；共享原生读回不假定设备初始为 down。Linux 系统助手已复用该入口及路由持久恢复；应用／Go 会话、地址避让、DNS 和 macOS 权限／恢复仍待接入，不能据此宣称完整网络接管已实现。

Linux 的 `LinuxTunRoutes` 为所属 TUN 新增 main 表 IPv4 捕获路由，要求已有非零点对点地址，拒绝已有目标；创建／删除使用受信 iproute2 的固定数字参数，不经过 shell。版本 1 记录绑定启动／线程网络命名空间、连接 UUID、派生设备名／metric、接口索引、原先不存在及完整应用值；畸形、歧义身份及外来记录拒绝。捕获与原出口后端共用容量边界、命名空间身份、地址校验和完整路由比较规则，仅忽略派生 linkdown／默认 unicast 差异。

捕获后端通过同步 `CheckpointWriter` 在内核写入前保存意图、回读后保存确认、删除前保存进度，存储失败停止后续内核修改；存储等待后重验容量、已有目标和接口／源身份，删除前重验完整值。新进程只消费经权限所有者认证的保护记录：未确认应用或已开始删除但仍匹配的项保留，不猜测同值重建的归属；对象已消失或完整值改变后可解除原责任。活跃原实例知道尚未尝试写入时只撤销记录，不接管存储等待期间出现的外部值；最后移除失败可重试，不再接管已释放的路由。每次应用／恢复各有十秒命令预算，失败回滚另计。捕获与源记录分别使用各自 root 私有操作目录，复用 `LinuxSourceJournal` 的既有文件／锁契约和固定文件名，由各后端验证具体结构；没有新增存储后端、任意路径或命令接口。保护文件／保留 fd／进程强杀／新进程恢复已通过本地及 Linux 双架构隔离内核，完整跨平台构建矩阵亦已通过；Linux 系统助手与自动恢复服务已复用该后端；主应用／Go 入口和 DNS 仍待接入，不代表完整透明接管或任意属性的原子比较。

系统代理端口取 ConnectionSession 的活动监听快照，冲突检查和模态确认按连接代次隔离。SystemProxySession 继续在 QtConcurrent 工作线程串行执行用例，产品调用改由 `ProxyRecoveryBackend` 委托同包 `JustConnectProxyRecovery`：独立进程仅持有同一正式平台代理后端及其快照，不链接 Go／Widgets／WebEngine，不提供通用命令或提权入口。客户端的私有本地通道固定接受查询／应用／恢复，64 KiB 完整 UTF-8 帧、规范端口和完整回复校验；每次请求含启动最多十五秒，失败／超时关闭通道并保留未确认责任。私有协议 2 在启动前分配责任 UUID，每次开始无旧责任的新操作更换标识；严格续接从启动起只接受对应作用域的受保护记录。敏感快照删除并回读确认后才发布独立的受保护完成证明，只含版本、责任标识与机器身份；每个存储范围仅保留一份。快照缺失且无匹配证明时保持未决，后来出现的其他记录或同值副本不删除。清理通道中断在原预算内最多重连一次，应用与查询不重放。已有原生快照格式继续读取，作用域封装和确认均复用原凭据存储与日志。宿主退出／强杀使通道断开，恢复进程继续按原后端撤销自身修改，拒绝时保留快照并退避重试；Linux 使用按有效用户标识派生的固定 `/tmp` 锁，数据目录或 `TMPDIR` 改变不能创建第二个所有者；同时持有当前数据目录的旧锁以阻止同目录旧版所有者与升级进程重叠；任一锁不可用即拒绝，不回退到其他目录。Windows 同时持有按进程 SID 固定的系统互斥量和当前数据目录旧锁，握手汇总两者，任一不可用即明确拒绝且不运行后端；旧锁保留到停止支持仅使用旧锁的进程。macOS 改为固定 `/var/tmp/JustConnect-system-proxy-recovery.lock`，仅在父目录是 root 所有的 sticky 目录时使用，并同时持有旧数据目录锁；任一条件失败由同一握手拒绝，不运行后端。双架构及应用原生用例已验证不同根／账户的排他、外来遗留锁保留、旧锁拒绝、EOF 与强杀后同账户重新取得所有权。Unix 通道在私有临时目录内，Windows 限同一用户；[Qt 的权限说明](https://doc.qt.io/qt-6/qlocalserver.html#socketOptions-prop)明确 macOS 不依赖 socket 模式位，因此保留目录隔离。普通关闭仍须等待明确恢复确认，再停止核心；进行中的应用与已请求恢复保持同一忙区间。三平台恢复进程通过受保护凭据存储保存记录，新进程先恢复旧记录才允许新应用；macOS 产品接入亦通过双架构与应用原生验收。启动查询和通道断开也可能恢复旧记录，客户端从启动成功起保留未决责任，仅明确拒绝所有权或完整回复确认无责任时释放；查询不能丢弃已有应用责任。适配器的加载／恢复阶段收敛为未载入、就绪、恢复中与已确认四态，完成缓存区分未读取和已读取空值。同一客户端的缺失／不同所有者、同值重建、证明畸形／写入失败及重试边界已通过本地和三平台原生回归；同源码六组实际包核对了私有协议 2、依赖及来源。无人值守启动／注销与实际桌面授权仍待，不能据此勾选 S2-06／S3-05／S4-06／S7-03。

三平台正式后端在首次修改前保存原值，恢复时保留外部新值；已确认恢复的项立即解除责任，通知失败的重试不接管后来出现的同值设置。Linux 记录已释放的键，Windows 按字段记录已恢复／外部接管项并移除无剩余责任的连接，macOS 在提交并回读后只重试激活通知；恢复目标已等于当前完整字典（含原先不存在）时不重复写入或提交，仍核对原值并确认激活。Windows 按 LAN／RAS 连接记录 WinINet 状态，macOS 使用 SystemConfiguration 锁定并提交原生字典，Linux 分别处理 GNOME／KDE 的实际配置类型和依赖开关。PAC 地址等未管理字段保留；禁用服务保持原样，新增对象不被恢复流程接管；macOS 已删除服务不重建。KDE 命令行不能安全写回含用户信息的旧代理 URL 时在修改前返回不支持。原生写入回归使用临时 runner 或私有配置；桌面授权、Clash 和校园实测的缺口不由这些用例代替。

`PlatformSystemProxyBackend::recoverySnapshot`／`recover` 是同一后端的新实例交接端口；记录绑定机器、连接 UUID 及平台范围，校验失败不触发原生操作。Linux 还绑定用户、配置目录、桌面及 GSettings／dconf 上下文；macOS 用二进制属性列表保留完整原生类型，Base64 只作编码；Windows 保留每个 LAN／RAS 的 flags、代理、绕过和 PAC 原值及字段释放位；schema 3 还记录写入意图／确认、未决恢复及不确定字段，拒绝尚未用于产品持久化的旧导出。记录含敏感数据，不可存入普通配置或日志。三平台的同步检查点端口在原生写入前保存意图、回读成功后确认，恢复也在写回前保存状态；存储失败停止后续修改，并重验存储等待期间的外部变化。新实例遇到未确认写入或恢复后仍匹配的设置时保留并报告，不能区分的同值重建不重新接管。`PersistentProxyBackend` 共用同一受保护存储适配，已扩展 macOS 构造及构建；私有 Keychain 与私有 SystemConfiguration 的组合回归已通过双架构及应用原生验收，覆盖写前顺序、提供者重新打开、锁定重试与外来记录拒绝。三平台产品恢复进程均复用该适配；构造不读存储，取得平台所有权锁后才在首次操作中加载。加载失败、非规范 JSON 或原生范围校验失败保留原记录并阻止新应用；已拒绝的损坏／外来记录不在当前进程内重新绑定，外部删除不能作为恢复成功证据。未接管原生项的拒绝在宿主断开后退出，记录仍保留；暂时锁定／不可用则继续退避等待，已接管项沿原恢复路径重试。成功恢复后回读并删除记录。Windows 在恢复读取前也提交检查点，防止观察到原值后丢失释放确认，新实例不接管随后同值重建的字段；仅剩激活通知时仍须确认通知。Windows 产品接入已通过双架构原生验收。macOS 后端已接入同一检查点端口并通过双架构原生验收，产品进程已接入 Keychain，实际进程的原生端点、并发拒绝、EOF 和强杀后新进程恢复已通过双架构与应用原生验收；测试仅在一次性 runner 使用临时默认 Keychain；sudo 使用目标账户目录，夹具先核对目录归属，再核对并恢复原默认项与搜索列表，失败时保留尚有未决记录的受保护夹具。

macOS 恢复记录 schema 2 按 HTTP／HTTPS／SOCKS 端点组、绕过和两个自动模式保存写入意图、成功确认、释放、未决观察／恢复及不确定字段；未用于产品持久化的旧导出拒绝加载。未尝试提交的本次暂存编辑不接管后来匹配的外部值；新实例对未确认且仍匹配的字段保留并报告，已恢复或外部接管项不重新接管。完整字典在存储等待后重读，外部变化使本次事务停止；原生提交并回读后确认释放，激活或记录删除失败只重试剩余责任。端点未决时暂缓依赖的自动模式，外部 PAC 地址与未管理字段保持原样。复用 [SCPreferences 的排他锁](https://developer.apple.com/documentation/systemconfiguration/scpreferenceslock(_:_:))及[提交／激活分离](https://developer.apple.com/documentation/systemconfiguration/scpreferencescommitchanges(_:))；[默认 preferences 属于系统范围](https://developer.apple.com/documentation/systemconfiguration/scpreferences-ft8)，产品持久接入的桌面授权与注销仍待验收。当前固定机器锁不随账户、工作或临时目录派生；普通其他账户不得删除原账户遗留的锁，也不推断其设置可被接管，依据 [sticky 目录删除限制](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/unlink.2.html)。锁只协调排他所有者，不授予代理修改或恢复权限；旧目录锁在停止支持仅使用旧锁的恢复进程后删除。

Linux 恢复记录 schema 3 将未决恢复保存为字段集合，并继续读取已交付的 schema 2 单字段记录。读取所属值前保存观察意图，看到原值或外部值后确认释放；实际写回前保存整组意图，再完整重读组及其依赖，不在重读与写入之间等待存储。认证开关须核对原主机／端口，模式须核对所有端点与 PAC，KDE 反向绕过须核对原绕过列表。组确认丢失时，新实例保留仍匹配的所有未决字段，不猜测其归属；外部恢复原值后才完成清理。记录格式迁移不更换受保护存储键，旧格式读取兼容在停止支持对应已交付记录后删除。

`WindowsProxyRecoveryLock` 从进程 TokenUser SID 派生固定全局互斥量，显式受保护 DACL 仅授予该 SID 同步／修改状态权限，句柄不继承，获取不等待；同一线程释放。正常与遗弃状态都只证明取得排他所有权，恢复记录仍须原后端校验。产品在原握手中汇总系统锁与旧目录锁，任一失败都不读恢复记录或运行后端，并保留旧目录锁直到不再支持仅持旧锁的进程。全局命名空间按 API 契约跨登录会话，实际跨会话／不同账户进程尚未实测；原生用例检查不同临时／工作目录的进程竞争及正常／强杀后的真实内核等待状态。依据：[命名空间](https://learn.microsoft.com/en-us/windows/win32/termserv/kernel-object-namespaces)、[创建与权限](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createmutexexw)、[线程所有权](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-releasemutex)。

系统凭据存储端口位于 `application/credentialstore.h`，提供有界不透明值的读／写／删和明确状态，平台工厂位于 `infrastructure/platform/systemcredentialstore.h`。`windows/credentialstore.cpp` 使用当前用户 Credential Manager，`macos/` 使用 Keychain，`linux/` 使用 Qt DBus 调用 Secret Service；锁定和权限状态不会被当作空凭据或成功。原生回归使用隔离条目／临时 Keychain／私有总线。`ProxyRecoveryJournal` 复用该端口存放代理恢复记录，要求先载入并比较已知完整字节，写／删后回读确认；拒绝外部改写、异常空值和超限值，保留发布后确认丢失的可能结果。系统凭据 API 没有原子比较替换，调用方必须持有独占恢复锁；记录校验、作用域和原生恢复由平台代理后端负责。主窗口协调器持有串行后台 CredentialAccess，连接、设置窗口和配置引导复用它；退出先等待后台写入，再销毁配置存储。

`application/ProfileCredentials` 维护按配置命名空间、服务器／端口、完整认证身份、手机号和账户派生的存储键，以及有版本的密码／TOTP 记录。修改密码不改变键；网络／TLS 偏好不改变账户归属。迁移在来源身份改变之前运行，只有系统存储写入并回读一致后才能移除旧 INI 值；已有安全值与旧 INI 冲突时保留双方，不用旧值覆盖新值。旧 Cookie 文件缺少可靠账户绑定，只可验证后隔离保存，不自动投入登录。原生调用为同步边界，由 CredentialAccess 在工作线程串行执行；访问旧配置时先完成验证迁移，来源变化的结果不交付凭据。

认证缓存使用独立的 `authentication-cache-v1` 条目，记录服务器确认账户及不透明核心快照，密码／TOTP 清除互不影响。缓存必须绑定选定账户，SMS 可按手机号绑定；残留的 SMS 手机号不能替代 SSO 账户。CredentialAccess 复用同一串行线程池及来源检查，读写前后核对完整公开快照和缓存修订号。调用方在开始一次连接前捕获修订号，并用于该次连接的全部保存；明确清除会立即推进修订号，再排队删除，旧读写及迟到刷新不能交付或重建材料。原生清除失败保留数据并报告失败，仍阻止已持有材料的旧回调再次保存；普通断开不推进修订号。保存策略默认关闭，设置中的明确选择由默认配置维护，连接模型与界面共用该键。关闭后停止恢复／更新已有缓存，删除使用文件菜单的当前账户清除入口；普通断开保留允许保存的材料。核心确认账户和会话后即交付认证快照，不等待资源获取或隧道就绪；资源响应如更新 Cookie，会再次交付更新后的快照，相同材料不重复交付。后续 TLS／网络失败保留有效认证，明确会话失效仍按作用域清除；缓存保存事件不能表示连接就绪。连接先尝试有效缓存，缺少密码且恢复失败时才请求一次输入，TOTP 继续按原账户读取。SSO 首次保存先把服务器确认账户写入公开选择，再写其安全条目；已选 SSO 账户与缓存所有者必须一致，密码登录别名与服务器账户允许不同。正常退出等待核心停止、后台操作及首次 SSO 绑定续接完成，避免退出打断已授权保存。

`ApplicationPaths::clientDataFile` 仅定位自身旧缓存，不创建目录或明文文件；保留它用于旧版本升级迁移和用户显式清理；只有停止支持读取旧缓存的版本后才可删除。明确清理在同一后台串行入口验证删除当前配置的加密隔离副本，再删除所属旧文件，失败不误报完成，不触及账户缓存或其他配置。正式库不通过该路径持久化认证材料。

`infrastructure/settings/credentialaccess.*` 将凭据读写与旧值迁移放到单线程 Qt 线程池，使用独立 QSettings 实例；提交与结果交付前按同一配置模型核对来源文件、命名空间和认证身份，身份变化返回取消且不交付旧密码。主窗口、设置和引导共用该入口；公开批次通过 ProfileService 在同一工作线程提交，写入前另核对完整公开快照。原生失败不写明文替代值，窗口关闭不取消已授权保存，退出先等待后台写入。

配置复制通过 `SettingsMigrator::publicDraft` 与默认配置的公开字段判定复用迁移规则；只转移当前支持的公开设置及用户名，不复制密码、TOTP、存储命名空间、票据、URL 预览或未知键。来源不修改，目标不覆盖已有文件；缺失／损坏来源不能变成一个误报成功的空配置。设置窗口导入也使用同一入口，不从导入文件填充私有字段或存储命名空间。

每个 `SsoLoginWebView` 创建独立的无存储名称 QWebEngineProfile，使 Cookie／浏览器状态仅在本次登录窗口内存中存在，多个学校／账户的登录窗口不复用进程默认 Profile。实际受控 HTTP 回归先验证同一窗口能发送刚设置的 Cookie，再确认另一窗口不发送该 Cookie；同时保留内存 Profile 断言，防止改成独立磁盘 Profile。核心认证恢复使用上述独立安全缓存。 浏览器回调绑定活动网关的完整 CAS／OAuth2 路径，仅交付主框架结果并在网络提交前拦截；其他路径、iframe、其他来源或歧义票据不能完成登录。地址栏与页面导航复用协议／来源策略，HTTPS 页面可正常跳转；HTTP 仅用于明确配置的同一回环网关。Go 在认证回调的实际请求边界及门户票据返回处共用来源／路径／唯一参数校验，覆盖直接提供 callback 的调用，不依赖浏览器已经检查。专用 Page 丢弃身份提供方脚本的控制台文本，避免其中的票据／登录 URL 进入全局 Qt 日志；页面 JavaScript 与安全的内部 iframe 继续工作。

连接使用安全存储中的凭据，失败时提示并允许明确的手动登录；未勾选记住时仅交给当前会话，勾选后保存失败仍可手动连接。密码／TOTP 留空保留已保存值，删除由设置中的独立按钮确认后执行且验证删除结果。来源文件／账户身份和请求代数限制晚到结果；公开编辑另检查完整公开快照，防止覆盖较新的 TLS／网络设置。没有明确认证方式的旧“自动选择”配置需要用户确认，不能据此绑定旧凭据。未确认服务器／账户的旧凭据进入独立加密归档，不自动用于登录。配置重命名前先完成遗留迁移；删除配置明确提示原生凭据仍保留，可事先按保存账号清除。外部覆盖配置不推断其旧缓存目录，避免与同名托管配置串用。

SSO 浏览器从当前连接会话接收 TLS 策略，回调来源与策略在窗口构造时固定。学校 CA 只加入该窗口的内存 Profile，默认窗口仍使用正常信任库；不会修改全局 QSslConfiguration 或系统证书。关闭校验仅接受当前网关的可覆盖证书错误并持续提示。Chromium 会按主机缓存证书例外，因此该模式还在所有资源请求和页面导航中阻止同主机的其他来源／端口；跨端口的正常登录应配置学校 CA 并启用验证。请求拦截器只使用不可变来源，不跨线程读取控件。Qt 最低构建版本为 6.10，当前固定 SDK 仍为 6.12。

认证 Handler 只交付结构化种类、图片／登录 URL 和明确能力，不再携带无人读取的终端提示。可信设备登记要求 `trusted_device` 请求及明确 `confirm` 回应，缺少处理器、取消或过期都不能登记。后续未知服务返回固定的不支持状态，不透传服务器原文。核心统一限制单次认证等待五分钟；超时关闭本次认证且旧回应失效，重试使用新的代次与请求标识。图片、点数及响应画布上限由 ABI 契约集中定义，Go 和 Qt 分别在交付／解码边界验证；认证 HTTP 控制面通过 Session.request 统一限制解压后的响应体，业务隧道保留原有流式传输。

系统浏览器是后续认证入口的优先评估方向，见 [plan.md 的 S7-13](../plan.md#s7)。当前 WebEngine 仍负责在网关消费一次性票据前截获回调；外部浏览器的服务器跳转及 Cookie 不会自动变成 Go 会话，须先验证服务端支持的安全交接。认证入口改变继续使用现有结构化认证端口与会话代次；完成真实交接和回归之前，保留当前实现及资源。

宿主信号与系统会话结束的实现依据：[Go 与非 Go 宿主的信号约束](https://pkg.go.dev/os/signal@go1.27.2#hdr-Non_Go_programs_that_call_Go_code)、[Qt 会话管理](https://doc.qt.io/qt-6/qsessionmanager.html)。CI 的实际进程 SIGTERM、GUI 信号及会话入口模拟不代替操作系统强制终止时限或真实桌面注销验证。

原网络保护范围由 `application/networkprotection.*` 从原生网络快照推导，保留接口地址与所有路由表的来源索引，相同前缀合并来源。回环始终保护；默认和分割默认路由仅描述出口，不成为保护范围，也不把所有私网当作实际网络。结果是目标范围及来源，不推测策略路由优先级、不重新绑定物理网卡；原快照须与来源引用一起保留。同一模块计算校园 IP 区间、内置 DNS 记录与校园 DNS 的已知地址重叠，保留目标及资源来源索引；IP 区间可跨越或包含整个保护前缀。解析记录不是业务授权，缺少已知重叠也不证明动态域名无冲突；协议／端口授权仍归核心。冲突结果上限 4096 条，畸形／超限使整次推导失败，不交付部分说明。启动前地址保护与应用模型复用同一推导，明确校园选择经完整策略提交；运行中网络变化的自动提交仍待实现。

核心的同一不可变保护策略还接收原网络名称规则及精确校园名称例外。名称保护先于校园资源、内置解析和缓存；默认使用系统默认解析与原生名称拨号，保留绝对查询及原生 IPv4／IPv6 连接选择，强制校园查询直接拒绝。校园名称例外仅影响该名称的连接，仍核对学校协议／端口授权；直接 IP 及其他名称的保护不变。原生查询失败不尝试校园或公共解析，关闭取消所属原生解析；更新与初始配置共用 `ProtectionConfig`，不维护两套字段。格式及边界见[核心 API](CORE-ABI.md#保护策略更新)。Qt 在每次连接前自动安装实际地址及 DNS 名称保护；核心接受 Start 后，工作线程随该代 starting 事件向应用交付已确认的完整初始策略。IPv4 选择及撤回保留最后确认的名称规则／例外，查看模型的刷新不会隐式替换名称保护。名称选择按具体主机规范化为小写 ASCII／ACE，拒绝根域、IP 和通配符；是否在保护范围内继续由核心唯一校验。名称更新及撤回保留已确认的地址范围／选择，原子确认前只保留待提交策略，失败不覆盖；读取中／失败仍可撤回本会话确认的名称例外。网络变化自动协调尚待接入，系统解析提供者限制仍适用。

系统 DNS 结果类型归 `application/dnssnapshot.h`，平台适配由 `readSystemDnsSnapshot()` 统一选择既有原生读取实现；调用者在工作线程运行，返回值沿用状态、完整事实和失败时空数据。各平台的原生回归经过统一入口，私有总线与故障夹具仍直接注入平台读取器。

同一模型模块从 DNS 快照提取 `dns_namespaces`，每项保留原始表达式、角色及原快照来源（字段／行／数组项或动态存储键）。resolved 的路由域与搜索路由域分开，Windows 生效 NRPT 保留原始命名空间，不能统一解释成后缀；macOS State／Setup 的匹配域、搜索域和主域作为配置输入分别保留，不冒充最终作用域或搜索顺序。`resolv.conf` 仅提取文件内最后一个非空 search／domain 指令，保留 glibc 的列首及空白语法，不代替 NSS、LOCALDOMAIN 或其他解析提供者。畸形、NUL 与超过 4096 项均使整次模型失败；表达式不直接成为授权或已生效保护。依据：[resolved 域路由](https://www.freedesktop.org/software/systemd/man/latest/systemd-resolved.service.html)、[Windows NRPT 命名空间](https://learn.microsoft.com/en-us/windows-server/networking/dns/name-resolution-policy-table)、[Apple DNS 配置处理](https://github.com/apple-oss-distributions/configd/blob/main/Plugins/IPMonitor/dns-configuration.c)、[glibc 文件解析](https://github.com/bminor/glibc/blob/master/resolv/res_init.c)。


`originalDnsProtection` 复用原命名空间事实生成 `name_targets`，每条规则引用原数组索引，相同规则合并来源；localhost 及其子域的默认原网络范围由同一模块提供。后缀和完整名称转换为规范小写 ASCII／ACE，Windows 无点 NRPT 按名称前缀处理；不把根域扩成全部域名，也不把 macOS Setup 保存值当作当前范围。搜索配置生成无点名称范围；macOS 数值 NoSearch、显式空搜索列表、私有／作用域解析器及反向域按已知输入语义区分，不重建最终解析顺序。无法表示的表达式、非 ASCII NRPT 前缀、非法标记或超过模型预算时整次模型失败，不发布部分保护说明。每类模型项共用模块内 4096 项预算；实际核心请求仍受独立的 ABI 字节及条目限制。该结果只用于模型展示，尚未自动提交名称保护。

`application/networkpolicysession.*` 按核心会话代次聚合网络与已就绪的校园资源，在两者成功后由单个后台任务读取系统 DNS 并推导保护／冲突模型。刷新清空旧模型，缺少能力、读取失败或畸形数据不发布部分内容；新代等待旧任务退出后仅构建当前代，停止立即失效交付。底层只读调用仍按各平台已有边界完成，协调对象销毁前等待所属任务。主窗口协调器复用同一个核心，断开进入停止阶段即失效模型；有序退出先失效结果，再由既有关闭流程等待后台读取完成，保留事件循环及原有超时边界。`setCampusAddress` 为显式调用生成完整地址策略，只接受实际保护范围内的规范 IPv4 地址；移除本会话已确认的例外不受刷新后范围变化阻挡，读取未结束或失败时沿用最后确认的完整策略撤回，不猜测新范围。版本沿用已校验的原生快照，代次内修订递增；同一时刻只提交一项，确认与待确认各保留完整策略，例外及待确认身份／忙状态由其派生；匹配确认后才发布选择，失败保留最后有效值，停止／换代丢弃晚到确认。刷新不重置修订；此处尚未自动随网络变化提交。启动前地址保护由核心适配器安装。

`NetworkPolicyWindow` 在地址页展示当前完整模型的原网络范围、接口／路由来源和已知校园地址重叠，保留授权协议／端口及内置记录／校园 DNS 的角色。选择实际 IPv4 范围后可输入单个地址，调用 `setCampusAddress`；界面只展示核心已确认的 `/32` 例外，失败保留原选择，并说明学校授权及相同地址无法同时访问两侧的限制。恢复入口仅提供本会话已确认例外，读取中或失败仍可撤回。输入窗异步且归属查看窗口，代次变化／会话销毁拒绝旧输入。DNS 页并列展示原始表达式、用途、来源和名称规则模型，另列系统保留的 localhost；单独展示已确认的具体校园名称，异步输入只提交该名称，撤回列表仅包含本会话确认的例外。长内容保留完整提示，说明最近读取的模型与核心已确认策略的区别。根域明确标为默认查询范围，NRPT 保留原生表达式，macOS 已保存配置与当前配置分开。刷新失败、停止、代次变化或会话对象销毁先清空旧行；内容使用纯文本，查看及刷新不调用策略提交。主窗口“文件 → 网络范围与校园地址重叠…”复用单个窗口，关闭释放窗口；无活动连接也可打开并查看无结果提示。受控选择／撤回、确认失败、旧输入、真实协议展示、清空和查询期间退出均有回归。
