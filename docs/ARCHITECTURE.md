# 当前代码结构

JustConnect 将可修改的 aTrust Go 源码直接纳入 `corelib/` 单一模块。Qt 通过版本化 C ABI 在同一宿主内调用正式会话；数据转发留在 Go 内。来源及许可证见 [corelib/UPSTREAM.md](../corelib/UPSTREAM.md)，契约见 [CORE-ABI.md](CORE-ABI.md)。

## 目录与依赖

```text
presentation/     Qt Widgets、认证窗口与流程 Coordinator
application/      连接／配置／系统代理用例及基础设施端口
core/             连接配置、错误与状态规则
infrastructure/   内嵌库适配、QSettings、系统代理、日志与更新实现
corelib/          会话、aTrust、underlay、解析、gVisor、回环代理及 C ABI
cmake/            应用和原生宿主共享的 Go 库／Qt 适配构建入口
tests/            领域、端口、界面、真实 C ABI 与受控网关回归
```

`application` 依赖 `core`，不引用 Widgets 或具体基础设施。`MainWindowCoordinator` 组合 `CoreEngine → EmbeddedCoreEngine`、`SystemProxyBackend → ProxyRecoveryBackend → JustConnectProxyRecovery → PlatformSystemProxyBackend` 和 `SavedConnectionBackend → SavedConnectionStore`。认证方式窗口通过应用层 `AuthMethodsQuery` 使用 `CoreEngine`，允许注入测试端口；只在查询与清理均成功后交付完整方法身份，取消或失败不暴露部分结果。

`corelib/internal` 按职责分包。网络模型与快照收集、拨号流程、文件生命周期和共有 Unix 权限、设备地址校验、IPv4 包帧分别由所属模块维护。系统私有实现位于各模块自己的 `macos`、`windows` 子目录，不再设置混合不同能力的总 `platform` 包。入口文件仅在编译时选择后端；Windows 私有文件使用明确构建标签，不重复系统后缀，也不保留旧路径兼容包。

```text
corelib/internal/
  networkstate/  共有快照收集与 model；macos／windows 原生读取
  dialer/        共有拨号流程；macos／windows socket 绑定
  privatefile/   共有生命周期与 Unix 权限；windows 原生 DACL
  tundevice/     共有入口和 address；macos utun／windows Wintun
  packetpipe/    共有 IPv4 包帧及 Windows 设备桥接入
  namedpipe/     windows 重叠管道 I/O，设备桥与本地控制 HTTP 共用
  mihomo/        只读控制来源／真实解析；macos／windows 进程与端点身份
```

macOS utun 的创建仍由 C++ 平台助手完成；Go 原生实现接收、校验与持有 fd，并处理设备 I/O 语义。共有契约测试覆盖平台接入，原生解析和设备测试随实现存放。`tundevice/address` 是各后端与数据面的同一份地址契约，没有第二套默认值或解析状态。

两平台提权、安装与恢复统一由 C++ 助手承担。Windows 的设备桥、受保护安装、原生签名与进程身份、机器记录和所属 NRPT 操作已迁入各职责模块，并经双架构定向验证；Go 的安装／记录／NRPT 与设备后端及旧 SDK 布局补丁已删除；原生 PnP／收发断言归 `corelib/tests/windows/device`，设备配置直接使用官方 SDK。C++ 独立恢复服务及机器会话记录已接通；生产授权启动器／控制 IPC 与主窗口接入已实现，Windows 普通应用／故障恢复及免外部证书的受保护部署已自动验证，正常桌面授权随 Windows／Fudan 连接实测通过；macOS 实机与中断验收留待 S8。Go 核心继续拥有认证、aTrust、策略／分流与数据面，必要的原生读取、fd 或管道 I/O 不进入提权运行链路；Windows 的降权夹具归 `corelib/tests/windows`。Unix 保持直接交付 fd，Windows 保持最小受限设备桥，不为语言或目录对称增加额外逐包转发。

连接入口在普通权限工作线程只读检查可见的官方 `aTrustAgent` 进程，macOS 使用 sysctl 进程表、Windows 使用 Toolhelp；各实现归 `infrastructure/process/<系统>/running.cpp`。这个名称来自厂商的 [Windows](https://bbs.sangfor.com.cn/atrustdeveloper/aTrustClient/docs/2.%E5%AE%A2%E6%88%B7%E7%AB%AF%E5%90%AF%E5%8A%A8%E5%BC%82%E5%B8%B8/2.1Windows%E5%B9%B3%E5%8F%B0%E6%9C%8D%E5%8A%A1%E5%90%AF%E5%8A%A8%E5%A4%B1%E8%B4%A5.html) 与 [macOS](https://support.sangfor.com.cn/cases/read?category_id=25088&product_id=19) 排障说明。只在明确发起连接时提示可能的路由／DNS 冲突，不阻断登录、不停止或修改官方进程，也不据此推断认证／在线／接口所有权；读取失败仅记录无法检查。取消或退出后的迟到结果丢弃，无托盘通知能力时使用非模态提示。测试进程与 UI 提示分别验收，真实官方版本、桌面通知及其连接状态仍需实机核对。

## 会话与线程

`ConnectionSession` 持有连接意图、重连计时器及当前配置，使用 `ConnectionSessionState` 管理状态。`EmbeddedCoreEngine` 将配置序列化后提交专属 Qt 工作线程；每次 connect（含重连）先读取原网络与系统 DNS 快照，复用应用模型推导保护前缀及名称规则，再把默认无校园例外的完整初始策略交给核心。读取或推导失败不启动会话；原子取消标志避免工作线程读取期间收到的停止请求在读取完成后仍开始会话，既有有界退出继续等待线程所有者。认证方式查询不读取保护快照。创建、异步启动、认证回应、读取、停止和销毁都在该线程调用 C ABI。每次最多一个 Qt 事件在途，应用线程确认交付后继续读取，避免另造无界日志队列。诊断字符串只供记录，状态仅由结构化状态／终态事件改变。`observation` 将认证、恢复和维护结果及观测时间独立传入同一会话，按阶段保留最新结果，未观测显示未知。主窗口和托盘共用该状态；当前仅显示“通道就绪”，不把核心 ready 标成产品“已连接”。设置页的自动／目标／关闭经现有 Profile 及 Go 配置校验接入维护循环；主窗口／托盘分别显示会话续期、DNS／HTTP 流量保活、节点和隧道维护的结果／时间，缺少获授权资源明确提示不可用。

`AuthenticationCacheCoordinator` 统一编排认证缓存的保存、失效、首次 SSO 账户绑定与清除代次，使用现有 CredentialAccess 串行存储入口；界面控制器只处理连接意图、输入和提示，并在退出时等待协调器的绑定续接。账户键和有效性规则仍归连接模型／ConnectionCredentialVault，存储来源与修订校验归 CredentialAccess，避免界面重排或后续重连重复维护这些规则。Go 仅通过绑定身份的 ClientData 恢复并由服务器确认账户、取得当前资源；不再保留直接注入旧资源并跳过认证的旁路。

应用重连和核心隧道重拨各自最多五次，指数退避间隔封顶 30 秒；两层预算只在持续就绪 60 秒后重置；核心按节点组保留预算，短暂连通不会重新获得次数。Go 的结构化传输错误分类排除证书、权限、协议和明确失效，不匹配错误文本。完成交互认证后允许后续网络恢复；尚在认证中的超时不自动重放登录。进入应用退避时撤销失效的系统代理，手动取消清除上一轮错误。隧道重拨耗尽会终止该会话，取消同时停止等待和拨号。

Go 的会话代次和请求 ID 全程保留为十进制字符串。`AuthDialogCoordinator` 异步展示短信、TOTP、RADIUS、内存图片验证码和 SSO；回应带原始身份。应用及 Go 都检查当前请求，旧窗口提交／取消不能影响新会话。停止不等待认证 UI；销毁先中断读取，再等待句柄与借用缓冲区结束。Unix 静态链接；Windows 从可执行文件目录固定加载随包 DLL，并保持 Go runtime 到宿主退出。

观测按适配器校验代次后的 ABI 交付顺序更新；UTC 时间仅用于展示，不用于判旧。系统校时回拨或相同毫秒内的结果仍能更新；停止后的维护事件被忽略，新连接清空上代观测。

`Session.Run` 拥有 underlay、认证／隧道、gVisor、解析器及 SOCKS／HTTP（含 UDP association），所有清理结束后才释放活动会话名额。进程只允许一个活动连接或认证方式查询。查询界面等待清理终态后才允许确认选择。系统代理由单独用例拥有，仅在用户启用自动设置时于通道就绪后应用，也可手动设置；当前库不创建系统 TUN、不改变系统路由／DNS，GUI 无需为连接整体提权。核心 `ready` 目前只证明通道与本地代理初始化完成。

`Listeners.Close` 先在所属锁下封闭并接管整张连接登记表，再取消会话；TUN 停止收发／移除 NIC 并停止 TCP 调度器后，关闭所属连接并加入流协程，最后关闭及等待完整协议栈；已进入关闭的连接／TUN 流不再逐项竞争共享登记锁，流表在所有流协程结束后整体清空。开放期间的登记／注销仍由同一锁保护，晚到连接被拒绝并关闭；TCP／UDP 入口与数据报中继检查取消，取消后不启动无用拨号、复制协程或大缓冲区分配。关闭仍等待泵、转发器、流协程及协议栈退出，不通过清空登记表推断线程已经结束。

控制连接的 `underlay` 在认证方式、登录、节点探测、隧道及重连共用同一解析与出口生命周期。未指定显式本地 DNS 时，只读发现本地 Mihomo／Clash Meta 的实际启动参数、配置或所属原生 IPC；根据 PID＋创建时间确认进程，TCP 先核对监听归属再发送密钥，Unix socket／Windows pipe 校验对端 PID。只接受回环控制地址，不猜默认端口、不读取订阅；拒绝重定向、歧义实例和不完整响应，不把密钥或配置原文写入错误。经核验的 `/dns/query` 回答经标准 Go resolver 保留 CNAME／AAAA 与地址竞争，HTTP／TLS 继续使用原域名；解析后为 loopback 的连接不绑定物理接口。控制请求无环境代理，只 GET，不改第三方配置；关闭会话取消查询并回收连接，无第二份解析缓存。

macOS 跨 UID 的 `KERN_PROCARGS2` 不能读取 root 核心参数时，使用公开的系统 Unix 监听表：按表头读取 PID／路径并只保留已发现核心的 PID，再核验真实连接的对端 PID／创建时间。读取流有行界限与取消预算，失败不发布部分表；不读取 root 配置、订阅或密钥。此路径保持普通 Go 权限，没有新增提权操作或监听路径常量。

Windows 对权限受限的核心使用公开进程表的创建时间，无需打开目标进程；正常路径继续复用已有句柄查询。Verge 控制管道只从实际 NPFS 名称枚举，按上游控制命名空间筛选并通过内核服务端 PID 与创建时间确认；打开管道会建立连接，因此不探测其他系统服务。该命名空间常量归 Windows 发现模块，依据及自有受限进程回归见[开发说明](DEVELOPMENT.md#mihomo-控制连接真实解析)；其他高权限前端的私有 IPC 仍需公开发现契约，不猜路径或默认端口。

当前接入从实际参数／普通配置或已观测原生 IPC 核验的单个控制器。启动参数指向相对路径但 Windows 无法取得 cwd、仅环境变量覆盖、控制 API 关闭／不可读、私有 CA 未受信及多实例人工选择仍待支持，不静默回退到来源未知的 Fake-IP。检测到启用 TUN 且未显式指定接口时，自动启用现有原出口检测，不要求修改应用默认设置；显式指定接口继续优先。拒绝其已知设备及无法确认的未绑定出口；这项保护不代替运行中 Clash TUN 的真实原出口验收。实际测试范围和复现见[开发说明](DEVELOPMENT.md#mihomo-控制连接真实解析)。

控制连接在收到 VPN 虚拟地址后同样必须保留原出口，不因应用默认关闭可选的接口检测而继续无绑定拨号；该规则与已核验的外部 TUN 共用。未显式指定接口时，优先将接管前实际控制连接的源地址映射回原生接口，保留覆盖网络出口；原源地址消失或对应多个接口时拒绝换路，由宿主恢复后重连。没有先前连接事实时沿用既有原出口检测，显式接口仍优先。字面量 IPv4／IPv6 回环控制连接不依赖外部出口，域名解析后的回环继续由原生拨号器保持本机；不改变业务的按目标路由，也不增加 DNS 缓存、IPC 或逐包处理。

Windows 网卡事实由 `networkstate.Interfaces` 单次原生枚举，显式跳过未使用的 DNS 信息；网络快照、原源地址映射与接口可用性检查共用该入口。socket 绑定直接将接口别名转换为 LUID／索引，避免每次拨号枚举整机。Unix 保持原生标准库读取，接口事实不另加缓存；DNS 来源仍由独立 DNS 读取器拥有。测量范围与复现见[开发说明](DEVELOPMENT.md#windows-网卡查询与-cpu-采样)。

非校园出口默认复用系统原路由的 `net.Dialer`；S6 的共有拨号器可接经核验的普通上游，错误不切换出口，受保护目标仍绕过上游走原网络。`CampusOnly` 只共享资源索引与实时保护策略，SOCKS／HTTP 共用严格校园解析，不允许未授权请求返回普通上游。 必须走校园通道的拨号先匹配服务器授权资源，拒绝未知资源、未支持的 IPv6／协议及原网络 DNS 回落；IPv4 映射地址按 IPv4 授权匹配。校园专用解析复用 `ResolveCampus`，保留学校内置解析与域名授权。普通 HTTP／SOCKS 路径中，已匹配学校域名资源的解析也禁止公共 DNS／来源未知缓存和失败后原网络回落；尚未支持的校园 IPv6 返回拒绝。DNS 缓存标记隧道内解析来源，校园查询可复用该类回答而不复用未知来源；保持既有寿命、容量和会话隔离。旧上游 HTTP／SOCKS 串联构造参数没有产品调用，已与专属实现／测试一并删除；Clash 上游联动由 S6 的实际入口与恢复验证后接入，不保留第二套待用出口配置。

### 透明包入口与 DNS 授权

`service.Listeners.AttachTUN` 接收由调用方提供的原始 IPv4 包设备，仅成功时取得所有权；每次读写一包，设备关闭须能中断 I/O。独立 gVisor 入口终止本机 TCP／UDP 流，复用现有 `Dialer.DialCampusIPPort`、服务器授权及原网络保护，再由会话已有校园栈发送，不创建第二个校园 L3 读取者。捕获流禁止直连回退；SOCKS、CONNECT 与透明 TCP 共用半关闭／错误转发，UDP 保留报文边界、空包及分片，空闲 90 秒释放。最多 256 个活跃流／待握手，停止关闭所属连接及设备、撤销入口 NIC，并中止迟到握手后等待全部工作退出。包入口不配置地址、路由或 DNS。 DNS 发布在现有入口锁下引用计数保留已通过名称／地址保护校验的目的地址，直到同一解析器提交绑定或返回失败／取消；资源快照先读这些保留地址，再读有效绑定，防止观察器在确认交接中撤回新路由。保留责任不授予校园流量权限，不另存解析绑定。`Session.AttachTUN` 复用所属监听器，`bridge.Engine.AttachTUN` 只允许当前就绪连接代次交付设备；失败保留调用者所有权，停止／运行失败关闭设备并等待工作退出，重启不继承旧设备。设备读写错误保留原始原因并以网络操作错误进入既有会话分类，权限／超时优先，其他设备 I/O 故障按网络失败退出。macOS 的[正式 C ABI fd 接口](CORE-ABI.md#原始-ipv4-tun-fd-接入)借用非阻塞设备并持有独立 `CLOEXEC` 副本，校验真实内核帧配置及 MTU；不改变原 fd 标志；macOS 在该入口转换 utun 地址族头，其他平台明确不支持。Qt `CoreEngine::attachTUN` 在调用线程同步保留 fd 后排队到核心线程，调用返回即可释放原引用；确认保留代次且在应用线程交付，关闭期间回应过期，销毁释放尚在队列中的引用。原生交接回归使用正式安装助手，由普通用户经真实内核 TUN／Qt／C ABI／校园协议验证 TCP、UDP 空包与停止／重启／销毁；仅助手退出时先确认客户端撤回 fd，再停止核心副本后新授权恢复，反向恢复同时核对 IPv4／IPv6 路由、规则和接口。两平台的助手／Qt 会话、动态校园 DNS 与正式核心数据面已接入并通过受控原生自动验收；完整 IPv6 能力及实际桌面／校园仍待，当前自动验收证据与具体缺口见[计划 S5](../plan.md#s5-无-clash-的透明原型)。

核心 DNS 为有效校园 A 回答记录原查询域名与实际 IPv4 的绑定，仅跟随 Answer 中同一 IN CNAME 链，忽略无关记录及其他类；不由 Additional 或普通代理解析缓存授予透明访问。绑定按 CNAME／A 最短 TTL 和现有 DNS 缓存寿命到期，零 TTL 留一秒首流交接窗口；最多 4096 项，容量不足整次拒绝，写入时回收过期项，不增设清理线程。每次新透明流复用学校域名协议／端口、节点组及当时的保护快照；同 IP 含已知受保护名称时不使用域名绑定授权，名称选择不绕过地址保护。校园 DNS 上游继续走严格 IP 授权接口。绑定归本次解析器所有，关闭后不可取得授权，已建立流沿既有请求生命周期结束；两平台助手增量发布、DNS 应答前确认与应用编排已通过受控原生自动验收；已支持来源的系统接管已原生验收；临时／加密等剩余来源及真实环境仍按计划验收。

S4 的 `policy.ProtectionPolicy` 由生产拨号、校园 DNS 与保活共用，接收实际保护前缀、明确 IPv4 选择及原网络名称规则／精确名称例外；保护不授予校园访问权限，域名、IP、协议和端口授权继续归既有拨号层。默认／分割默认路由属于原出口策略，不作为目标范围。核心通过[版本／代次／修订 API](CORE-ABI.md#保护策略更新)完整校验并原子替换快照；名称解析结果与随后业务拨号沿用同一快照，直接 IP 拨号取当前规则。Qt 已自动安装启动地址及名称保护，并接入明确 IPv4／名称选择及撤回；[原网络快照 API](CORE-ABI.md#原网络只读快照)提供真实接口／路由及 ，系统 DNS 已进入只读模型。两平台网络接管后端负责观察实际网络变化，协调保护与捕获；应用仅在所属助手和核心设备均确认后显示校园就绪，受控验收及实机缺口见[计划](../plan.md#s4-策略与网络操作的恢复基础)。

原网络保护从完整原生快照派生，不删减底层路由清单。只有接口索引匹配且状态明确为断开时，其路由才不形成可达网络保护；未知状态／接口、无所属接口或仍有可用／未知下一跳的路由继续保留。所有接口的已配置地址仍保护并用于私有 TUN 地址避让，链路恢复后沿现有网络观察重新纳入该接口路由；不按驱动／网卡名称排除，不删除第三方配置，也不扩大捕获规则上限。

原 DNS 来源可由启动配置给出，或通过 `CoreEngine::prepareOriginalDNS` 在认证 ready 后、设备交接前一次性准备，便于使用认证后的资源与实际出口事实。Qt 工作线程调用同一 Go 会话的 C ABI，监听套接字全部绑定后才发布；失败释放本次资源，既有代理继续运行，成功后来源不可变。端点沿用代次绑定的资源快照，无额外进程、包转发 IPC 或 DNS 缓存；转发仍直接使用 Go 原生套接字。macOS 普通静态／State／DHCP 及 Windows 本地 NRPT 来源均已通过双架构自动接入／选择／恢复；各平台尚未支持的来源仍明确拒绝，具体边界见所属模块及计划。接口成功不代表系统 DNS 已生效。 原 A 回答在 `dns_routes` 中声明排除，两平台共用发布器从助手当前所属捕获扣除地址，通过同一 `Routes`／回读／恢复链确认后才返回 DNS。资源规划同样扣除仍受名称保护的原地址，精确校园名称选择可撤销自身排除，共享 IP 的其他原名称继续保护。业务数据留给原生网络栈选择实际路由，查询网卡不承担业务出口决策；Go 拒绝误捕获的已知原方向。待确认原发布按名称／地址引用计数，资源快照与提交绑定连续交接，不另建解析缓存。

Windows 的 `readWindowsDnsSnapshot` 调用同目录的普通权限 `JustConnectDnsReader.exe`，在独立进程中使用[原生 MI API](https://learn.microsoft.com/en-us/windows/win32/api/mi/nf-mi-mi_application_newsession)；固定从系统目录加载 mi.dll，显式 WMIDCOM／空目标，读取本地同一组 DNS 提供者。NRPT 固定调用 Get 并传入 Effective=true；发布前后读取 [MS-GPNRPT 的本地／托管原生存储](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-gpnrpt/06088ca3-4cf1-48fa-8837-ca8d853ee1e8)中的 Name 范围，确认有效规则仍有来源。若两次完整读取的范围不同或有效提供者仍返回已删除的范围，在原十秒总预算内重读，不能过滤行、补服务器或把残留校园规则当成原网络保护；字段值及安全约束仍来自完整的原生有效策略。路径与读取限额由 DNS 模块的 `dnscontract.h` 统一维护，注册表读取不修改策略。MI 后缀／NRPT／可选 DoH 只查固定类；不启动 PowerShell、接受任意查询或加载调用者目录的 MI 库。命名空间／服务器统一为数组，NRPT IP 地址规范化，保留查询、回退、DirectAccess 与 DNSSEC 约束；DoH 注册不代表连接已启用。仅可选类不存在视为能力缺失；NRPT 成功空结果保留空数组，非零返回码、非空数据缺少返回码或必需提供者异常仍失败。十秒预算包含进程启动与完整读取，超时只终止这个无写操作的子进程；结果限 256 KiB，数组／结果上限 4096，完整查询及清理后才输出。Qt 保留相同 DnsSnapshot 校验，只提取白名单阶段／计时，不发布原始诊断或部分事实。读取器随 CoreRuntime 安装，生产程序拒绝测试参数；故障及库来源夹具仅编译进测试目标。双架构原生读取、应用接管与实际包链已通过受控 CI；独立恢复由权限助手维护所有权记录，免申请的受保护部署与真实桌面要求见[计划](../plan.md#s4-策略与网络操作的恢复基础)。

Windows 原 DNS 来源事实另由同一读取器调用 [GetAdaptersAddresses](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getadaptersaddresses)、[GetInterfaceDnsSettings](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getinterfacednssettings) 及原生全局 DNS 设置接口读取。`adapters` 保留实际混合 IPv4／IPv6 服务器顺序、端口、作用域、GUID／LUID、接口索引／指标与状态；`native_global` 和各接口 `Settings` 保留原生返回码、DoH／DoT 属性、DDR 及全局安全标志。64 位标志用十进制字符串无损交付；未提供的文本保留 null，未知属性保留版本／类型和 null，不能据此允许普通 DNS。接口版本 4／全局版本 2 不支持或设置不存在时明确记录缺失，不回退到旧版结构推断安全模式；权限及其他读取错误不发布部分结果。仍沿用十秒子进程预算、256 KiB 和共有条目上限，无新权限、命令或设置写入。应用、原生回归和包校验已同步；原读视图按已确认 GUID／LUID 精确移除所属 Wintun 的原生 DNS 行，保留外部改值，拒绝索引复用。`958a943` 的 [ARM64](https://github.com/wtalioy/JustConnect/actions/runs/40455098957/job/122026474012)／[x64](https://github.com/wtalioy/JustConnect/actions/runs/40455098957/job/122026474172)均通过实际来源读取和各 40 项 CTest，两平台 Tests 及 Windows 安装目录入口也通过。整轮 ABI 的 macOS TLS 夹具失败另行修复，不算整轮通过。该读取增量已验；后续写入／恢复后端见 [Windows 原生助手](#windows-原生权限助手)，自动来源、监听及应用原视图已接入，完整调用链已通过 Windows 双架构普通应用联验。

Windows 原规则的只读身份保留在 `nrpt_sources`：区分 local／managed 存储，保留规则 ID、class、完整名称集合、原服务器字符串、版本／选项及本次端点替换标记。读取器在有效 NRPT 查询前后比较完整来源记录，名称未变但端点、身份或标记变化也会重新读取；字段缺失保留 null，类型错误不发布部分快照。`configured_encryption` 另外保留原生配置的加密端点，覆盖 DoH CIM 表省略的 DoT 专用项；与助手复用同一读取函数，不增加进程或查询缓存。所属读视图只移除已确认身份及原值完全相同的校园规则，重建／改写拒绝沿用所属快照，外部来源保留。`7304509` 的两平台 Tests／四组 Core ABI 已通过此身份增量的 schema、实际读取、DoT 配置事实与所属投影，包检查契约已同步；自动选源、固定 53 端口监听与原视图观察现已接入，完整应用场景已通过 Windows 双架构原生验收。

macOS 的 `readMacDnsSnapshot` 通过公开的 [SCDynamicStoreCopyMultiple](https://developer.apple.com/documentation/systemconfiguration/scdynamicstorecopymultiple(_:_:_:)) 一次读取 State／Setup 下的网络 DNS 字典，分别保留当前及配置来源的完整键名、服务器／搜索域／补充分域、端口和排序字段。仅复制原生文本、布尔、无损整数与容器；不支持的值、过深／过大数据或读取失败不交付部分结果。沿用 SystemConfiguration／CoreFoundation，没有私有 DNS API 或 scutil 文本解析。该视图已进入应用只读模型，但不保证覆盖 Network Extension 等解析提供者；原生同步调用没有独立超时／取消边界；此只读视图不代替所属助手的恢复记录。

按 [R11／S3-01／S7-02](../plan.md)，两平台已由同一应用层会话汇总核心、分流／DNS 和网络接管的生效确认，再向主窗口与托盘发布校园就绪；失败逆向撤销自身修改。核心 `ready` 只是其中一个输入；普通流量、已有终端及真实校园验收仍按计划逐平台完成。界面不另建第二套就绪标志，也不维护分流／恢复规则。

公开导出的字段由默认配置维护，并排除凭据和登录 URL，不复制整份 INI 或未知私有字段；导出通过原子文件提交且拒绝覆盖源配置。导入／重置先编辑草稿，取消不改原文件；保存失败不关闭窗口。密码／TOTP 通过系统安全存储异步读写，公开字段由 SavedConnectionService 批量提交；原生写入与 INI 提交不是跨资源事务，若公开提交失败，已验证的原生值可能已更新，界面报告保存未完成且不写明文。旧缓存先加密隔离并回读确认，不因编辑身份直接丢弃。账户级票据复用及配置用例见下文。

SavedConnectionService 维护公开字段到 ConnectionOptions 的唯一映射（`application/connectionoptions.cpp`）。连接配置页用公开草稿生成查询和校验配置，连接与安全存储也复用同一映射。编辑器从来源快照创建独立的 QSettings，密码和 TOTP 来自安全存储或当前输入。凭据结果按来源和窗口生命周期交付，保留当前窗口的未保存输入。

INI 格式检查由 SettingsMigrator 维护：在私有临时目录用仅所有者可读写的副本强制重新解析，随检查清理，避免 Qt 缓存丢失格式错误后重复尝试改写损坏文件。切换、迁移、公开写入及凭据来源复用此检查；状态文件的活动选择、自启动和静默启动由 SavedConnectionStore 共用写入／失败恢复路径。静默启动保存失败会保留窗口及草稿，不能继续报告整体保存成功。

主窗口仍处理配置菜单和托盘；`SavedConnectionService::settings()` 仍为主窗口和连接控制器的动态设置提供者保留 QSettings 后端，连接配置页使用自己的读取对象。平台代理与自启动按操作系统拆分，由共享 CMake 选择，只返回结构化结果；状态区分失败／取消／权限／超时／不支持及可能已修改，界面负责提示。代理查询失败不能触发设置，查询返回可能已修改时也保留待清理状态并显示原因；查询进行中请求关闭会排队恢复，确认无责任才跳过清理，后续只读查询不清空既有责任；自启动或偏好保存失败时保留设置窗口和认证材料。两平台后端已保存代理快照并按所有权恢复；当前链路的退出由 `ApplicationShutdown` 在 15 秒总预算内编排：禁止启动／重连，异步撤销代理及所属网络接管，再取消核心，并等待已有凭据、SSO 绑定续接及认证方式查询清理。失败／超时报告残留并保留事件循环与线程所有者，明确重试才再清理；不强杀线程或卸载 Go。应用 Quit 事件进入同一入口；关闭仍在查询的认证方式窗口先取消并等待清理，避免在 GUI 线程同步销毁活跃工作线程。宿主 `TerminationRequests` 将 SIGTERM／SIGINT／SIGHUP 和 Windows 控制台通知交给 GUI 事件循环；Unix handler 使用 `sigaction(SA_ONSTACK)`，不接管同步崩溃信号或在 handler 中调用 Qt。Qt `commitDataRequest` 在同一关闭入口等待有界结果，系统结束期间不弹交互对话框；真实 OS 注销、控制台关闭仍须各自验证。应用菜单提供独立的偏好入口，关闭行为通过既有 SavedConnectionStore 的 `state.ini/Global/CloseToTray` 保存，不进入学校配置；默认隐藏到可用托盘，无托盘保留窗口。保存本身不关闭或断开，显式退出及系统结束始终进入有序关闭。领域和应用层允许 Qt Core 类型，与 Widgets 分离不表示脱离 Qt。针对性重构随功能推进，不增加协议插件框架或通用工具目录。

S2-03 将 TLS 信任策略收敛到会话配置，查询用例只复制端点与 TLS 策略，不携带账户密码。服务器编辑控件维护验证开关及可选学校 CA；默认验证登录服务器的证书。内置 Fudan 配置预勾选跳过隧道验证，自定义连接默认验证隧道。编辑器会显示跳过校验的提示。认证、节点探测与隧道复用带取消的 TLS 握手实现，失败类型通过 ABI 和 Qt 保留。

基础设施同样按职责分组：`autostart`、`credentialstore`、`systemproxy`、`dns`、`tundevice`、`routing`、`networkhelper`、`networkaccess`、`networkjournal`、`networkaddress` 和 `process`。模块根目录维护共有端口适配、校验／生命周期和真实共有的 Unix／POSIX 逻辑；系统私有实现放在模块内的 `macos`／`windows`，显式不支持的端口仍返回 Unsupported。`cmake/SystemIntegration.cmake` 组合现有能力并按目标系统选择实现，主应用与原生测试复用同一入口；macOS 授权服务的源码／签名／安装契约保持原有职责，不另建兼容层。

### Windows 原生权限助手

校园 DNS 的内部连接与宿主网络捕获分开判定：认证服务给出的固定 IPv4 DNS 端点只在 aTrust 栈内建立查询连接，地址与原网络／原 DNS 相同不意味着必须截走原地址。普通应用流量仍遵守保护策略；TUN DNS 连接只对该固定端点临时取消宿主 IP 偏好，继续验证协议／端口及校园资源授权，名称与应答仍校验保护策略，失败不回退原网络或公共解析。原 DNS 上游继续从捕获范围排除。仅有域名且初始无需捕获地址时，两平台保留空捕获的设备／恢复所有权，收到有效 DNS 答案并确认路由后再交付地址；不制造占位路由。

Windows 的 C++ 部件按职责放在 `tundevice/windows`、`packetpipe/windows`、`networkhelper/windows`、`networkjournal/windows`、`dns/windows` 与 `process/windows`。Wintun 使用同一已校验归档的官方头文件及原生结构；创建前拒绝已存在的身份，配置后回读，分配通知先于地址／路由修改。助手持有适配器与环，普通 Qt／Go 通过实际 PID／SID 校验的本地字节管道收发 IPv4；关闭取消并等待 I/O，再释放所属设备。C++ 两方向复用事件与包缓冲，Go 同样复用方向事件／OVERLAPPED 和发包缓冲，避免逐包创建内核事件与分配完整帧；Unix 仍直接移交 fd。

Wintun 的关闭会排队执行 SDK 清理回调，DLL 由助手固定至进程退出，避免提前卸载回调代码及全局堆；依据 [QueueUserWorkItem 的 DLL 生命周期要求](https://learn.microsoft.com/en-us/windows/win32/api/threadpoollegacyapiset/nf-threadpoollegacyapiset-queueuserworkitem)。[SwDeviceClose](https://learn.microsoft.com/en-us/windows/win32/api/swdevice/nf-swdevice-swdeviceclose) 发起异步拔除：正常关闭先确认指定实例不再配置且 IP 接口已消失，再按原 UUID／NetCfgInstanceId 验证并卸载非在场节点；强杀恢复在确认原助手已退出后直接卸载所属遗留设备，不等待未执行的 SDK 关闭。两条路径最后均回读完整消失后才发布恢复回执。拔除与卸载确认共用原有五秒预算，权限错误、外部身份变化及未消失状态均保留责任。

原生 Windows 目标使用静态 CRT 和 [/DEPENDENTLOADFLAG:0x800](https://learn.microsoft.com/en-us/cpp/build/reference/dependentloadflag)，在进入 main 前约束静态依赖的搜索。安装由系统 UAC 明确批准，只复制本次运行映像及固定哈希的驱动／许可证，不要求开发者或用户申请代码签名。运行映像的 CodeView 链接身份与固定源文件分别核对；原生查询 Program Files，逐级固定目录句柄并检查所有者／写权限，不接管普通用户所有的同哈希文件。配置与 SDK 来源归 `resource/network-helper-windows.json`，构建生成原生常量；不加载 Qt／Go 运行时作为提权依赖。

`WindowsRegistryJournal` 在受保护的 64 位 HKLM 键保存有界 JSON 原子值，每次操作检查 SY／Administrators 所有者及受保护 DACL，写入后刷新。NRPT 部件在创建键时原子保存随机 class 身份，核对所有者、ACL、全部已存在的类型／字节及无未知值；准备值先刷新，匹配名称最后激活。恢复使用已验证的内核键句柄删除，外部修改保留。`WindowsNetworkRecovery` 在设备／DNS 修改前保存严格版本化的会话记录，以受保护的机器互斥量串行写入与恢复；调用方／助手均绑定实际 PID、创建时间和 SID。废弃记录仅在助手死亡后恢复，正常释放须核对当前助手身份；外部 DNS 修改保留；`tundevice/windows/recovery` 只清理记录 UUID 对应的 Wintun 软件节点，包含分配中崩溃留下的 phantom 节点，确认所属 PnP 节点不存在、接口已释放后才保存恢复回执。同账户确认回执前拒绝新 UUID，其他活动 Wintun 不被清理。Windows 可在设备删除后延迟保留 NSI 接口记录；仅对 Down／NotPresent 且 IPv4／IPv6 地址、路由均为空的所属记录忽略其账面存在，活动状态、配置残留或读取失败继续阻止完成。系统 NRPT 父键保留 Windows 自带的网络配置／防火墙服务权限，本助手规则子键仍只允许 SYSTEM／Administrators 修改，不覆盖域策略。

Windows 原 DNS 的 `WindowsNrptRedirect` 后端只替换既有本地 NRPT 提供者的服务器组，不修改名称、策略、权限或接口 DNS 偏好。助手重新读取并校验请求的完整名称集合、原服务器顺序、键身份及写权限；域管策略、加密来源、歧义来源和变化的快照拒绝接管。全局 DoH／DoT 能力位不等于每台服务器都使用加密；后端复用读取器的原生 MI 会话检查系统已知 DoH 服务器表，并读取原生 `DohWellKnownServers` 的配置端点（DoT 专用项不会由 DoH CIM 表返回），相关来源仍拒绝转成明文，全局自动／强制加密、DDR 或未知策略也拒绝。判定依据为 [Windows NRPT 与已知 DoH 服务器的实际规则](https://learn.microsoft.com/en-us/windows-server/networking/dns/doh-client-support#use-name-resolution-policy-table-with-doh)，不关闭系统加密来通过夹具；受控验收另外通过原生 netsh 增删本次 DoT 端点，核对该来源不会被当成明文。回环监听地址须真实分配在活动接口，监听与原服务器不得落入校园捕获。原始服务器字符串、键身份及随机所有权标记在修改前进入恢复日志；标记先刷新，再替换端点，恢复只还原仍指向本次监听的端点并保留外部新值。正常 quiesce 在撤回捕获后恢复原端点，独立故障恢复在所属设备消失后恢复原来源。校园规则与原来源批量写入后只刷新一次系统 DNS 缓存；原来源批量恢复在刷新成功后持久保存已完成项，部分失败仍保存完成进度，重试不碰后续所有者。校园规则撤销及缓存刷新完成后保存空 DNS 检查点，最终设备恢复不重复刷新；崩溃前未提交的进度仍重新核对／刷新。Windows 助手协议／存储版本由 `resource/network-helper-windows.json` 统一维护，不猜测或转换旧记录。`3d6c608` 的 Windows 双架构前置检查已通过此后端的普通系统解析、DoH／DoT 来源拒绝及助手强杀／SCM 恢复；四组正式 ABI 步骤及 Windows 各 40 项 CTest 通过，整轮仍因 x64 原 SDK 第 57／4096 包停滞失败；自动调用方按保护模型的来源引用映射完整本地 NRPT 规则，保留原 ID／class／原始服务器文本及有序上游，只有核心确认真实已分配 IPv4 回环地址的 TCP／UDP 53 端口后才提交；助手写前再次核对来源，返回所属标记用于严格投影原值。来源／安全上下文变化沿既有观察恢复后重连。校园域安装规则与 macOS 共用推导，避免同一范围的重复规则；明确策略切换在捕获确认后刷新系统 DNS 缓存，普通应答发布不刷新。受控普通应用场景覆盖缓存预热、自动监听、名称选择／撤回和两轮完整恢复，`e5cf04d` 的[双架构定向原生检查](https://github.com/wtalioy/JustConnect/actions/runs/40509722353)已通过此完整调用链，两架构各两轮预热缓存、名称选择／撤销与精确恢复，系统校园 DNS／TCP／UDP／SSH 继续通过；本地明文规则同时含根域与受保护范围时，规划保留完整原生来源，并在已有命名路由上标记经原生配置确认的默认服务器组；只为该原生监听转发无匹配名称和根查询，不把根域扩大成名称保护。不同来源仍按原生范围优先级分派，匹配失败不改用默认来源；托管及加密来源继续明确拒绝。根来源增量已通过混合上游 UDP／TCP、Qt 规划／实际 ABI 及 Windows 双架构两轮系统解析／恢复。

独立 C++ 入口在管理员授权的受保护安装后注册固定 LocalSystem 自进程 SCM 服务，验证服务所有者、控制权限、固定命令及失败动作；普通用户只读查询，外部配置拒绝接管。SCM 自动重启与周期恢复不依赖 GUI／Go。服务重开当前受保护安装时核对所有目录、映像内容身份与驱动／许可证固定哈希；R14 的无外部证书回归继续验证实际服务与助手强杀后的独立恢复，不向系统导入根证书。不同映像哈希的换版只接受已固定于受保护目录、内容哈希及驱动／许可证均匹配的旧服务；独立安装锁串行化换版，存在未恢复责任时不停止旧服务。全部恢复后复核所有权再替换，启动失败恢复原命令并重启已固定的旧映像；外部服务配置仍拒绝接管。当前原生验收覆盖安装、SCM／机器恢复及普通 Qt／Go 数据部件；独立 DNS 夹具另以实际非回环 IPv4 端点验证普通权限 `GetAddrInfoW` 的 NRPT 应答、localhost 保留和所属恢复，不以注册表回读代替有效解析。Wintun 系统 DNS、普通应用编排与双杀恢复另有完整联验；Windows 正常授权接管及校园网页／SSH 已实测；其余平台实机部署集中到 S8，独立人工授权专项取消。

原生 `--control` 为一次批准的提权进程提供固定本地控制管道：调用者 PID／创建时间来自启动参数并与实际管道客户端核对，SID 从保留的进程对象取得；普通端以启动返回的进程句柄核对实际管道服务端，不读取其他管理员账户的令牌，也不向请求指定的进程转移权限。控制管道名、协议、报文上限及期限由同一 Windows 契约生成。对历史责任记录仅接受本账户的检查、废弃恢复及回执确认，恢复在机器锁内核对账户后再检查活跃状态；不执行调用者程序、路径或任意 JSON 记录。GUI 进程死亡或 EOF 结束通道，已经发起的独立恢复保留既有保障。原生测试以已提权父夹具启动生产入口，不能替代真实 ShellExecute UAC 窗口验收；最新状态见计划。

`--authorize` 由普通 Qt 作为普通子进程启动，隔离系统 [ShellExecuteExW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecuteexw) 的同步授权等待。启动器先固定并验证自身签名／链接映像和驱动／许可证，再只以 `runas` 启动本次同一映像的 `--control`；核对实际批准进程映像后，只向原调用进程转交查询／等待句柄，不传管理员令牌。Qt 客户端以单一 worker 串行请求，管道连接与 I/O 均可取消；旧授权按代次释放，取消后的提权进程无客户端可进入网络操作。关闭应答须由客户端确认，客户端等待实际进程退出后释放通道，避免尾帧在关闭时丢失。普通启动器、安装与已安装恢复各有职责，Qt 的动态运行时不进入原生助手；此客户端已接入主窗口的 `WindowsNetworkAccess`，普通应用联验已通过受控 CI；真实桌面及跨账户授权仍待实机验证。

Windows 活动会话与控制协议共用已批准进程，私有设备与环仍由 C++ 持有。`apply` 只接受规范 IPv4 地址对、MTU、捕获前缀及明确 DNS 域名，生成新适配器 UUID 并在创建前保存所有权；禁止默认、回环、多播及捕获自有源地址。数据管道独立于控制管道，名称由契约和会话 UUID 推导，仍核对实际客户端 PID／SID。Qt 只持有可借出的原生管道，Go 自行复制并直接收发，逐包链路复用既有原生 relay；转发器退出仅中断收发，网卡的空闲保留或最终删除统一归所属会话决定。

新建所属网卡在启动收发环前关闭自身 DHCP／APIPA 自动寻址，避免无地址时 Windows 重新分配 `169.254/16`；不更改原接口或机器全局配置。键值依据 [Microsoft 的按接口 APIPA 设置](https://learn.microsoft.com/en-us/windows-server/troubleshoot/how-to-use-automatic-tcpip-addressing-without-a-dh)，真实延迟空闲／重连仍核对无地址及无捕获。

Windows 在一次 GUI 生命周期内复用已批准的助手和所属空闲网卡，控制租约绑定实际 GUI PID／创建时间／SID，连接尝试仍使用新的应用代次。正常断开先撤回捕获、恢复 DNS 并停止核心，再由 `park` 删除所属地址／对端路由并释放收发环；确认网卡无 IPv4 地址及非系统自动路由后，记录为 `parked`，DNS 所有权必须为空。再次连接先在机器锁内核对原助手／调用者／网卡及其他活动责任，持久写入新配置后才启动新环并配置网络；配置不变时不重复写接口属性。活跃助手的空闲记录不作为待恢复网络显示，但保留独立恢复责任；正常退出清除网卡及记录，GUI／助手异常结束仍由原独立恢复链清理。协议版本为 6，存储字段版本仍为 2，新增阶段严格解析，不转换未知记录。此复用仅覆盖本次应用运行，不跨重启保存授权或网卡。

`routes` 在所属接口核对现有条目，追加／删除均回读确认，不改其他接口；`quiesce` 先保存恢复意图，再撤回 DNS 与捕获，暂留私有设备／管道供核心有序停止；`restore` 验证当前助手身份，释放设备并确认所属 PnP 节点和有效接口均不存在后保存持久回执。DNS 外部改写保留并报告，仍停止自有数据面；未知助手不能执行正常释放。独立服务与正常释放复用同一恢复检查点，Qt 使用 [QWinEventNotifier](https://doc.qt.io/qt-6/qwineventnotifier.html) 监测实际进程结束，无额外状态轮询。配置准备复用应用层校园捕获推导、原 DNS 地址保留和私有地址分配，并从实际快照核对已选出口。`NetworkAccess::quiesced` 允许会话在撤回捕获后先停止核心，最终 `stopped` 仍须等所属网络已释放，设备可按上述空闲契约保留到退出；Unix 保留既有单段停止路径。`WindowsNetworkAccess` 复用应用会话与网络策略模型，账户锁仅协调 GUI，恢复授权仍由原生机器记录决定；授权拒绝不会启动核心，设备与有效 DNS 的完整读取确认后才交付已认证管道。捕获更新复用首次确认的 peer 路由模型；仅私有 peer `/32` 为 on-link，校园捕获经已确认的 peer 转发，避免 on-link 前缀派生广播主机路由与捕获合并／撤回冲突。实际刷新验证完整所属值；读取过滤只扣除精确所属捕获和首次确认的自动路由，后出现的外部本地行继续保留。停止等待 `CoreEngine::finished` 后再释放设备／回执，失败保留责任及新连接阻断。主窗口已接此入口，缺少受信助手时明确失败；普通 Qt／Go 系统 DNS 与流量联验、部署及真实环境的当前状态见计划。

### Unix 设备与路由恢复

Unix 的 `MacNetworkJournal` 由 macOS 捕获后端使用，存储所属意图及恢复检查点：只接受显式打开的 root 私有目录描述符，独立打开描述并持有非阻塞独占锁；固定记录文件须为 root 所有、0600、单链接的普通文件，目录须为 0700，拒绝符号链接及隐式当前目录。记录使用共用的 2 MiB 恢复预算及连接 UUID，已有记录必须显式载入；更新／删除比较完整原字节和文件身份，同值替换或确认删除后重建不接管。私有临时文件完整写入并 fsync 后原子发布，再同步目录；首次发布不替换并发出现的文件，删除同步失败可重试。调用方先验证可信来源，恢复仍由所属后端校验全部字段及启动／接口身份。`apply`、`restore` 和新实例 `recover` 共用同步检查点端口：应用值确认、删除开始及规则释放均由后端提交，空对象请求持久移除记录；调用方只适配存储。每次删除前写记录后重读引用／完整应用值和接口身份；存储失败不继续下一次内核修改，最后同步删除失败保留内存责任供重试。新进程看到删除已开始且匹配对象仍存在时保留并报告结果不明，不猜测它是原项还是外部同值重建；对象已消失则可完成剩余恢复。macOS 原生助手与完整会话已通过双架构检查，实际桌面授权／注销及产品交付仍待。

同一对象的 `createIpv4` 在交付前配置规范的点对点 IPv4 `/32`、MTU 与启用状态，回读地址、对端、掩码、MTU、标志及接口身份后才发布成功。快照记录连接、设备及配置前／实际应用值；失败关闭尚未交付的私有设备，不修改或恢复已有接口。macOS 使用受信系统 ifconfig；共享原生读回不假定设备初始为 down。macOS 助手及核心 fd 接入复用该入口和内核地址回读；macOS 完整会话已通过双架构原生检查，完整验收状态见计划。

### macOS 捕获路由

macOS 的 `MacTunRoutes` 仅为当前拥有、已配置点对点 IPv4 的新 utun 添加捕获；`/sbin/route` 使用固定参数及空继承环境，不接收任意程序、路径或命令。`NET_RT_DUMP` 从原生路由消息读取有界完整 IPv4 清单，保存地址、接口、标志和指标；仅忽略使用／报文计数及派生接口引用位。规范前缀不得捕获自有源／对端，已有相同前缀保留并拒绝，暂不支持同 IP 的原路由替换。`RTF_PROTO1` 作为自有捕获标志，含义依据 [XNU route.h](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/net/route.h)。

捕获记录绑定启动 UUID、连接 UUID、utun 名称／索引和地址对，写前意图、完整回读确认、删除开始及完成移除复用 `MacNetworkJournal`。首次原子发布使用 macOS `RENAME_EXCL`，固定文件名与既有 macOS 存储格式不变；已有日志、同步失败、链接、同值替换和外部改写的拒绝语义保留。同前缀的其他作用域／内核派生项通过完整已应用值与所属父路由区分，不按前缀唯一性判断。新恢复进程只消费由权限入口认证的 root 私有记录：未确认应用或已开始删除的匹配值保留；已消失或完整属性不同的路由只解除原责任，不改写当前值。设备改名／索引复用或地址对变化时保留责任。

原生夹具在 fd 交付前调用正式 macOS 捕获后端，已删两处 Python 手写路由；C ABI 流量之后，先在普通调用方仍持有 utun fd 时撤销捕获，再验证最终 fd、接口及路由清理。保护日志、部分失败、指标改写、已有精确路由和新进程恢复由同一后端验证。此增量的当前本地／原生状态见[计划](../plan.md#s4-策略与网络操作的恢复基础)，不代表完整应用接管已验收。

macOS 权限入口使用应用内 `SMAppService` LaunchDaemon 和固定的特权 Mach 服务，布局／协议由 `resource/network-helper-macos.json` 生成；root 进程只链接 Qt Core 与系统安全框架，复用上述设备、捕获及日志，不链接校园数据面或界面。双方逐条以 [SecCodeCreateWithXPCMessage](https://developer.apple.com/documentation/security/seccodecreatewithxpcmessage(_:_:_:)) 校验消息签名、角色标识、相同叶证书与 hardened runtime，拒绝调试／禁用库验证的身份；内核连接要求只设置一次。网络应用另需已授予的 `system.services.systemconfiguration.network` Authorization Services 凭据（[Apple 网络配置规则](https://github.com/apple-oss-distributions/Security/blob/main/OSX/authd/authorization.plist)），按实际网络配置操作授权，服务端只验证，不弹窗或扩展权限。客户端在工作队列注册／授权。连接前无法联系已注册助手时，通过 Service Management 刷新一次注册，重开受签名约束的 XPC 通道。助手空闲且无未恢复网络记录时退出，下次由 launchd 按需启动；通过 Qt 排队回调交付非阻塞 fd；事件和回应绑定实际原生连接，替换连接后丢弃旧回调，避免撤销当前会话。默认包由构建自动生成本地签名身份，同一构建的应用／助手保留相同叶证书、角色和 hardened runtime；签名后销毁私钥及临时钥匙串，不要求外部证书申请或系统根信任。本地身份与系统服务注册／撤销已通过原生检查；当前实际包与桌面批准范围见计划，不将旧 ad-hoc 包计为本次验收。

助手协议与存储版本由[同一资源](../resource/network-helper-macos.json)生成；root 私有记录限定为当前内核启动 UUID、XPC 调用方 UID 和连接 UUID，调用方不能指定程序、目录、接口或其他用户。写前记录创建／设备／捕获阶段，正常恢复保留持久回执直至客户端确认清理；断开、服务退出和重启扫描复用同一恢复路径，其他存活连接与未知／外部记录不接管。旧启动下的磁盘记录保留，不据此修改当前内核网络。双架构原生夹具已验证真实网络授权、普通用户 fd／UDP、持 fd 撤销、取消／EOF／助手强杀及重启恢复；签名夹具与整包重签均保留助手角色标识，包审计独立核对应用和助手实际签名标识。权限助手基线已通过完整矩阵和四组实际包；当前 DNS 动态追加及 Qt／Go 双会话已通过双架构原生检查与完整矩阵，证据见计划。当前自动本地签名包按实际产物验收，真实系统设置批准与校园访问仍待。临时证书与直接 bootstrap 的 CI 服务不能替代桌面注册批准。

macOS 的 `extend` 仅接受规范单播 IPv4 数组，必须来自当前持有该连接的同一签名 XPC peer；不能接管其他存活或已脱离的连接，也不增加授权入口。助手先核对 guardian 与捕获记录，再复用原写前意图／内核回读／成功检查点追加 `/32`；已覆盖地址幂等，外部精确路由保留并拒绝。已有捕获也逐项核对，部分失败仍先释放 DNS，再恢复整组捕获；恢复记录按资源定义的当前存储版本校验，新进程复用同一恢复路径。`routes` 同样绑定当前签名 peer，接受完整规范 IPv4 前缀集并复用恢复后端逐项撤回、追加与持久确认；空集只撤回捕获，仍保留活动设备和 DNS 所有权。外部作用域路由保留并与新建的无作用域捕获共存，未知无作用域精确项或改写拒绝接管；先撤回所属旧父路由，让内核清理其派生缓存，再核对新目标，失败先释放 DNS 再恢复整组。

`DNSRoutePublisher<Helper>` 为两平台共用确认关联、串行请求、旧代拒绝和结束取消，不维护第二份解析绑定或路由规则。助手确认后才回报核心 `acknowledgeDNSRoutes`；失败／所有权丢失拒绝确认。两平台正式会话均使用该协调器；Mac 原生签名夹具同时覆盖 CoreEngine 端口与完整 Qt／Go 双会话，状态及证据见计划。

macOS 的 `MacNetworkAccess` 复用 `ConnectionSession`／`NetworkPolicySession`：先取得当前账户／内核启动的应用锁并经助手发现、恢复及确认旧回执，再启动核心；实际资源／保护和既有 DNS 共同预留地址，助手配置完成并交付原生 fd、Qt 队列及 Go 确认后才报告校园就绪。停止先恢复 DNS／捕获和回执，再停止核心；取消、失败及助手丢失继续沿同一入口处理。助手丢失后若恢复失败，仍停止核心释放设备，保留未决责任与新连接阻断，明确恢复确认后再重连。探测／注册／授权尚未写入网络时，取消立即释放当前请求与会话责任；后台结果按同一请求 UUID 校验，迟到授权在引用释放时撤销，不能批准或覆盖新请求。授权提供者可在后台返回，退出不等待它；真实系统授权窗口和同时强杀应用与助手的验收状态见计划。Mac 无网络命名空间，不额外保存用户路径下的恢复凭据；root 日志仍为恢复权威。

助手的成功应用／更新回应携带完整已确认捕获记录、设备派生 IPv4 路由及 DNS 视图；请求仍限制 64 KiB，回应预算由既有日志上限和设备／DNS 信封派生。捕获记录的只读校验与 root 恢复共用，Qt 不由前缀猜测所有权。原网络过滤在当前原生 RIB 完整匹配记录后才扣除对应读取行，保留额外字段、外部地址及改变的 DNS；此读取投影不授权任何恢复写入。地址预留复用共有地址模型，无产品测试地址默认值。保护地址变化先由核心确认新策略，再由助手确认所属捕获集；两侧均确认后才完成用户选择。核心资源读取复用真实 DNS 绑定，失效地址在已有流结束后撤回，排空目的地址直接来自核心现有流表，不授予新流；缓存地址再次选边无需另存绑定表。原出口按实际选用接口、地址和默认路由观察，变化先恢复再按原预算重连；未知无作用域精确路由仍保留，不原地替换。动态策略及双杀的新原生验收状态见计划。真实桌面批准、实际包及校园验收另见计划。

### macOS 校园 DNS

macOS 的 `MacTunDns` 在独立 SystemConfiguration 会话中为连接 UUID 发布临时 IPv4 服务绑定与 supplemental DNS：接口、地址／掩码来自已配置 utun 的内核回读，DNS 端点为实际 peer，只接受明确的规范域名。两项均要求原先不存在，逐项添加并回读；不设置 Router、默认域或全局 DNS；显式使用 Apple [VPN.DNS](https://developer.apple.com/documentation/devicemanagement/vpn/dns-data.dictionary) 定义的 `SupplementalMatchDomainsNoSearch=1`，防止系统把校园后缀合并到全局搜索列表。域名校验复用共有模块，助手请求的必填 `dns_domains` 数组，空数组表示禁用；记录随当前存储契约校验。

发布后在连接操作的有界预算内读取系统 `scutil --dns`，核对普通查询解析器中的全部 supplemental 域名与唯一 peer，再交付设备；读取失败或超时关闭临时会话。接口专属／服务专属查询分组独立处理，不计入普通 `getaddrinfo` 就绪。该检查仅在应用 DNS 时运行；[Apple configd](https://github.com/apple-oss-distributions/configd/blob/main/Plugins/IPMonitor/dns-configuration.c) 为普通 supplemental 配置生成非接口绑定的解析器，接口仍由前后的原生 utun／路由回读确认。

[SCDynamicStoreAddTemporaryValue](https://developer.apple.com/documentation/systemconfiguration/1437789-scdynamicstoreaddtemporaryvalue) 将临时键绑定到发布会话；关闭或进程终止只删除仍属于该会话的值，其他会话即使写入相同值也转移所有权。因此 DNS 无需另存恢复日志，正常停止、部分失败和连接丢失先关闭该会话，再恢复捕获与设备；磁盘记录改变不妨碍释放仍持有的 DNS 会话。原生夹具覆盖部分发布、外部同值改写／命名冲突、默认路由不变及普通用户系统解析；Qt／核心完整会话的自动验收与最新生效检查见计划，真实桌面批准仍待。

### 系统代理、凭据与认证

自启动使用当前应用名对应的 Run／desktop／登录项，显式开关沿同一入口更新或撤回；旧版未加引号的 Run 命令与 desktop 内容不需要另一套后端。格式来自旧正式实现，回归覆盖更新／清理和无关条目保留；macOS 按应用包路径核对，无法确认的来源或路径拒绝，错误由界面展示。不扫描、猜测或删除其他应用项。

系统代理端口取 ConnectionSession 的活动监听快照，冲突检查和模态确认按连接代次隔离。SystemProxySession 继续在 QtConcurrent 工作线程串行执行用例，产品调用改由 `ProxyRecoveryBackend` 委托同包 `JustConnectProxyRecovery`：独立进程仅持有同一正式平台代理后端及其快照，不链接 Go／Widgets／浏览器实现，不提供通用命令或提权入口。客户端的私有本地通道固定接受查询／应用／恢复，64 KiB 完整 UTF-8 帧、规范端口和完整回复校验；每次请求含启动最多十五秒，失败／超时关闭通道并保留未确认责任。私有协议 3 支持无设置写入的入口观察，并在启动前分配责任 UUID，每次开始无旧责任的新操作更换标识；严格续接从启动起只接受对应作用域的受保护记录。敏感快照删除并回读确认后才发布独立的受保护完成证明，只含版本、责任标识与机器身份；每个存储范围仅保留一份。快照缺失且无匹配证明时保持未决，后来出现的其他记录或同值副本不删除。清理通道中断在原预算内最多重连一次，应用与查询不重放。自动交接只接受已确认的回环上游端点，仅替换当前启用且匹配该上游的服务／协议，保留原开关、绕过列表与其他服务；观察返回当前所有权和原上游端点，不返回代理凭据。快照按需保存自动交接范围，已有原生快照格式继续读取，作用域封装和确认均复用原凭据存储与日志。宿主退出／强杀使通道断开，恢复进程继续按原后端撤销自身修改，拒绝时保留快照并退避重试；Windows 同时持有按进程 SID 固定的系统互斥量和当前数据目录旧锁，握手汇总两者，任一不可用即明确拒绝且不运行后端；旧锁保留到停止支持仅使用旧锁的进程。macOS 改为固定 `/var/tmp/JustConnect-system-proxy-recovery.lock`，仅在父目录是 root 所有的 sticky 目录时使用，并同时持有旧数据目录锁；任一条件失败由同一握手拒绝，不运行后端。双架构及应用原生用例已验证不同根／账户的排他、外来遗留锁保留、旧锁拒绝、EOF 与强杀后同账户重新取得所有权。Unix 通道在私有临时目录内，Windows 限同一用户；[Qt 的权限说明](https://doc.qt.io/qt-6/qlocalserver.html#socketOptions-prop)明确 macOS 不依赖 socket 模式位，因此保留目录隔离。普通关闭仍须等待明确恢复确认，再停止核心；进行中的应用与已请求恢复保持同一忙区间。两平台恢复进程通过受保护凭据存储保存记录，新进程先恢复旧记录才允许新应用；macOS 产品接入亦通过双架构与应用原生验收。启动查询和通道断开也可能恢复旧记录，客户端从启动成功起保留未决责任，仅明确拒绝所有权或完整回复确认无责任时释放；查询不能丢弃已有应用责任。适配器的加载／恢复阶段收敛为未载入、就绪、恢复中与已确认四态，完成缓存区分未读取和已读取空值。同一客户端的缺失／不同所有者、同值重建、证明畸形／写入失败及重试边界已通过本地和两平台原生回归；此前交付的 `fcb324b` 四组实际包核对了私有协议 2、依赖及来源；协议 3 的实际包随 S6 最终交付验收。真实注销及 macOS 桌面实机仍待 S8；当前阶段人工验收范围以计划为准，不把原生自动验收当作完整发布验收。

两平台正式后端在首次修改前保存原值，恢复时保留外部新值；已确认恢复的项立即解除责任，通知失败的重试不接管后来出现的同值设置。Windows 按字段记录已恢复／外部接管项并移除无剩余责任的连接，macOS 在提交并回读后只重试激活通知；恢复目标已等于当前完整字典（含原先不存在）时不重复写入或提交，仍核对原值并确认激活。Windows 按 LAN／RAS 连接记录 WinINet 状态，macOS 使用 SystemConfiguration 锁定并提交原生字典。PAC 地址等未管理字段保留；禁用服务保持原样，新增对象不被恢复流程接管；macOS 已删除服务不重建。原生写入回归使用临时 runner 或私有配置；桌面授权、Clash 和校园实测的缺口不由这些用例代替。

`PlatformSystemProxyBackend::recoverySnapshot`／`recover` 是同一后端的新实例交接端口；记录绑定机器、连接 UUID 及平台范围，校验失败不触发原生操作。macOS 用二进制属性列表保留完整原生类型，Base64 只作编码；Windows 保留每个 LAN／RAS 的 flags、代理、绕过和 PAC 原值及字段释放位；schema 3 还记录写入意图／确认、未决恢复及不确定字段，拒绝尚未用于产品持久化的旧导出。记录含敏感数据，不可存入普通配置或日志。两平台的同步检查点端口在原生写入前保存意图、回读成功后确认，恢复也在写回前保存状态；存储失败停止后续修改，并重验存储等待期间的外部变化。新实例遇到未确认写入或恢复后仍匹配的设置时保留并报告，不能区分的同值重建不重新接管。`PersistentProxyBackend` 共用同一受保护存储适配，已扩展 macOS 构造及构建；私有 Keychain 与私有 SystemConfiguration 的组合回归已通过双架构及应用原生验收，覆盖写前顺序、提供者重新打开、锁定重试与外来记录拒绝。两平台产品恢复进程均复用该适配；构造不读存储，取得平台所有权锁后才在首次操作中加载。加载失败、非规范 JSON 或原生范围校验失败保留原记录并阻止新应用；已拒绝的损坏／外来记录不在当前进程内重新绑定，外部删除不能作为恢复成功证据。未接管原生项的拒绝在宿主断开后退出，记录仍保留；暂时锁定／不可用则继续退避等待，已接管项沿原恢复路径重试。成功恢复后回读并删除记录。Windows 在恢复读取前也提交检查点，防止观察到原值后丢失释放确认，新实例不接管随后同值重建的字段；仅剩激活通知时仍须确认通知。Windows 产品接入已通过双架构原生验收。macOS 后端已接入同一检查点端口并通过双架构原生验收，产品进程已接入 Keychain，实际进程的原生端点、并发拒绝、EOF 和强杀后新进程恢复已通过双架构与应用原生验收；测试仅在一次性 runner 使用临时默认 Keychain；sudo 使用目标账户目录，夹具先核对目录归属，再核对并恢复原默认项与搜索列表，失败时保留尚有未决记录的受保护夹具。

macOS 恢复记录 schema 2 按 HTTP／HTTPS／SOCKS 端点组、绕过和两个自动模式保存写入意图、成功确认、释放、未决观察／恢复及不确定字段；未用于产品持久化的旧导出拒绝加载。未尝试提交的本次暂存编辑不接管后来匹配的外部值；新实例对未确认且仍匹配的字段保留并报告，已恢复或外部接管项不重新接管。完整字典在存储等待后重读，外部变化使本次事务停止；原生提交并回读后确认释放，激活或记录删除失败只重试剩余责任。端点未决时暂缓依赖的自动模式，外部 PAC 地址与未管理字段保持原样。复用 [SCPreferences 的排他锁](https://developer.apple.com/documentation/systemconfiguration/scpreferenceslock(_:_:))及[提交／激活分离](https://developer.apple.com/documentation/systemconfiguration/scpreferencescommitchanges(_:))；[默认 preferences 属于系统范围](https://developer.apple.com/documentation/systemconfiguration/scpreferences-ft8)，产品持久接入的桌面授权与注销仍待验收。当前固定机器锁不随账户、工作或临时目录派生；普通其他账户不得删除原账户遗留的锁，也不推断其设置可被接管，依据 [sticky 目录删除限制](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/unlink.2.html)。锁只协调排他所有者，不授予代理修改或恢复权限；旧目录锁在停止支持仅使用旧锁的恢复进程后删除。

`WindowsProxyRecoveryLock` 从进程 TokenUser SID 派生固定全局互斥量，显式受保护 DACL 仅授予该 SID 同步／修改状态权限，句柄不继承，获取不等待；同一线程释放。正常与遗弃状态都只证明取得排他所有权，恢复记录仍须原后端校验。产品在原握手中汇总系统锁与旧目录锁，任一失败都不读恢复记录或运行后端，并保留旧目录锁直到不再支持仅持旧锁的进程。全局命名空间按 API 契约跨登录会话，实际跨会话／不同账户进程尚未实测；原生用例检查不同临时／工作目录的进程竞争及正常／强杀后的真实内核等待状态。依据：[命名空间](https://learn.microsoft.com/en-us/windows/win32/termserv/kernel-object-namespaces)、[创建与权限](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createmutexexw)、[线程所有权](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-releasemutex)。

系统凭据存储端口位于 `application/credentialstore.h`，提供有界不透明值的读／写／删和明确状态，平台工厂位于 `infrastructure/credentialstore/systemcredentialstore.h`。`windows/credentialstore.cpp` 使用当前用户 Credential Manager，`macos/` 使用 Keychain；锁定和权限状态不会被当作空凭据或成功。原生回归使用隔离条目／临时 Keychain。`ProxyRecoveryJournal` 复用该端口存放代理恢复记录，要求先载入并比较已知完整字节，写／删后回读确认；拒绝外部改写、异常空值和超限值，保留发布后确认丢失的可能结果。系统凭据 API 没有原子比较替换，调用方必须持有独占恢复锁；记录校验、作用域和原生恢复由平台代理后端负责。主窗口协调器持有串行后台 CredentialAccess，连接和配置编辑器复用它；退出先等待后台写入，再销毁配置存储。

`application/ConnectionCredentialVault` 维护按配置命名空间、服务器／端口、完整认证身份、手机号和账户派生的存储键，以及有版本的密码／TOTP 记录。修改密码不改变键；网络／TLS 偏好不改变账户归属。迁移在来源身份改变之前运行，只有系统存储写入并回读一致后才能移除旧 INI 值；已有安全值与旧 INI 冲突时保留双方，不用旧值覆盖新值。旧 Cookie 文件缺少可靠账户绑定，只可验证后隔离保存，不自动投入登录。原生调用为同步边界，由 CredentialAccess 在工作线程串行执行；访问旧配置时先完成验证迁移，来源变化的结果不交付凭据。

认证缓存使用独立的 `authentication-cache-v1` 条目，记录服务器确认账户及不透明核心快照，密码／TOTP 清除互不影响。缓存必须绑定选定账户，SMS 可按手机号绑定；残留的 SMS 手机号不能替代 SSO 账户。CredentialAccess 复用同一串行线程池及来源检查，读写前后核对完整公开快照和缓存修订号。调用方在开始一次连接前捕获修订号，并用于该次连接的全部保存；明确清除会立即推进修订号，再排队删除，旧读写及迟到刷新不能交付或重建材料。原生清除失败保留数据并报告失败，仍阻止已持有材料的旧回调再次保存；普通断开不推进修订号。保存策略默认开启，连接模型与界面共用该设置，已保存的选择优先。关闭后停止恢复／更新已有缓存，删除使用文件菜单的当前账户清除入口；普通断开保留允许保存的材料。核心确认账户和会话后即交付认证快照，不等待资源获取或隧道就绪；资源响应如更新 Cookie，会再次交付更新后的快照，相同材料不重复交付。后续 TLS／网络失败保留有效认证，明确会话失效仍按作用域清除；缓存保存事件不能表示连接就绪。连接先尝试有效缓存，缺少密码且恢复失败时才请求一次输入，TOTP 继续按原账户读取。SSO 首次保存先把服务器确认账户写入公开选择，再写其安全条目；已选 SSO 账户与缓存所有者必须一致，密码登录别名与服务器账户允许不同。正常退出等待核心停止、后台操作及首次 SSO 绑定续接完成，避免退出打断已授权保存。

`ApplicationPaths::clientDataFile` 仅定位自身旧缓存，不创建目录或明文文件；保留它用于旧版本升级迁移和用户显式清理；只有停止支持读取旧缓存的版本后才可删除。明确清理在同一后台串行入口验证删除当前配置的加密隔离副本，再删除所属旧文件，失败不误报完成，不触及账户缓存或其他配置。正式库不通过该路径持久化认证材料。

`infrastructure/settings/credentialaccess.*` 将凭据读写与旧值迁移放到单线程 Qt 线程池，使用独立 QSettings 实例；提交与结果交付前按同一配置模型核对来源文件、命名空间和认证身份，身份变化返回取消且不交付旧密码。主窗口和配置编辑器共用该入口；公开批次通过 SavedConnectionService 在同一工作线程提交，写入前另核对完整公开快照。原生失败不写明文替代值，窗口关闭不取消已授权保存，退出先等待后台写入。

配置复制通过 `SettingsMigrator::publicDraft` 与默认配置的公开字段判定复用迁移规则；只转移当前支持的公开设置及用户名，不复制密码、TOTP、存储命名空间、票据、URL 预览或未知键。来源不修改，目标不覆盖已有文件；缺失／损坏来源不能变成一个误报成功的空配置。设置窗口导入也使用同一入口，不从导入文件填充私有字段或存储命名空间。

`SsoLoginWebView` 保留结构化认证接口，网页由 `presentation/browser` 的 WebView2／WKWebView 实现。每个窗口独立使用 InPrivate／非持久化数据存储；受控 HTTP 回归验证本窗口能发送 Cookie，另一个窗口与关闭后重开不能复用。Windows 的临时数据目录在浏览器进程结束后删除。回调绑定活动网关完整 CAS／OAuth2 路径，只交付主框架唯一有效结果，并在网络提交前拦截；其他路径、iframe、来源或歧义票据不能完成登录。地址栏与页面导航复用协议／来源策略，HTTP 只允许明确配置的同一回环网关。Go 在实际请求边界再次校验来源／路径／唯一参数，不依赖网页层已经检查。网页控制台不接入应用日志。

连接使用安全存储中的凭据，失败时提示并允许明确的手动登录；未勾选记住时仅交给当前会话，勾选后保存失败仍可手动连接。密码／TOTP 留空保留已保存值，删除由设置中的独立按钮确认后执行且验证删除结果。来源文件／账户身份和请求代数限制晚到结果；公开编辑另检查完整公开快照，防止覆盖较新的 TLS／网络设置。没有明确认证方式的旧“自动选择”配置需要用户确认，不能据此绑定旧凭据。未确认服务器／账户的旧凭据进入独立加密归档，不自动用于登录。配置重命名前先完成遗留迁移；删除配置明确提示原生凭据仍保留，可事先按保存账号清除。外部覆盖配置不推断其旧缓存目录，避免与同名托管配置串用。

浏览器来源与 TLS 策略在构造时固定。学校 CA 通过窗口私有的系统证书链验证加入信任，不修改全局 QSslConfiguration、系统证书库或浏览器默认状态。关闭校验仅适用于活动网关的精确来源，并持续提示；同主机其他端口的导航与资源不能复用例外，正常跨端口登录应配置学校 CA 并启用校验。WebView2 使用私有链引擎／SSL 主机名策略，WKWebView 使用当前认证挑战的 SecTrust；正常系统信任保留。

认证 Handler 只交付结构化种类、图片／登录 URL 和明确能力，不再携带无人读取的终端提示。可信设备登记要求 `trusted_device` 请求及明确 `confirm` 回应，缺少处理器、取消或过期都不能登记。后续未知服务返回固定的不支持状态，不透传服务器原文。核心统一限制单次认证等待五分钟；超时关闭本次认证且旧回应失效，重试使用新的代次与请求标识。图片、点数及响应画布上限由 ABI 契约集中定义，Go 和 Qt 分别在交付／解码边界验证；认证 HTTP 控制面通过 Session.request 统一限制解压后的响应体，业务隧道保留原有流式传输。

浏览器入口与减包边界见 [UI 设计](UI-DESIGN.md#认证浏览器选择)；当前原生实现及四架构实际包验收按 [S7-13](../plan.md#s7-自动化ui-重设计与完整恢复) 记录。

宿主信号与系统会话结束的实现依据：[Go 与非 Go 宿主的信号约束](https://pkg.go.dev/os/signal@go1.27.2#hdr-Non_Go_programs_that_call_Go_code)、[Qt 会话管理](https://doc.qt.io/qt-6/qsessionmanager.html)。CI 的实际进程 SIGTERM、GUI 信号及会话入口模拟不代替操作系统强制终止时限或真实桌面注销验证。

### 原网络保护模型

原网络保护范围由 `application/networkprotection.*` 从原生网络快照推导，保留接口地址与所有路由表的来源索引，相同前缀合并来源。回环始终保护；默认和分割默认路由仅描述出口，不成为保护范围，也不把所有私网当作实际网络。结果是目标范围及来源，不推测策略路由优先级、不重新绑定物理网卡；原快照须与来源引用一起保留。同一模块计算校园 IP 区间、内置 DNS 记录与校园 DNS 的已知地址重叠，保留目标及资源来源索引；IP 区间可跨越或包含整个保护前缀。解析记录不是业务授权，缺少已知重叠也不证明动态域名无冲突；协议／端口授权仍归核心。冲突结果上限 4096 条，畸形／超限使整次推导失败，不交付部分说明。启动前地址保护与应用模型复用同一推导，明确校园选择经完整策略提交；运行中的网络观察、完整策略提交与捕获协调由所属 `NetworkAccess` 驱动，失败先恢复所属修改。

Tailscale 的官方地址池由同一保护模块维护；只有实际启用、身份索引有效且非回环／已识别代理隧道的同一接口，同时带有官方 CGNAT IPv4 与专用 IPv6 地址特征时，才推导完整地址池保护。依据为[官方地址范围](https://tailscale.com/docs/reference/reserved-ip-addresses)，不依赖可修改的接口名称，不列举对端或中继 IP；未识别时继续保留实际地址／路由保护。地址池仍引用原接口地址来源，原网络快照／路由不改；它保护尚未进入路由表的对端，并避免宽校园资源减去许多对端 `/32` 后产生大量捕获前缀。明确的校园地址选择／撤回仍走既有策略。此范围保护不证明外层打洞／中继的路径或整机 CPU 已验收。

核心的同一不可变保护策略还接收原网络名称规则及精确校园名称例外。名称保护先于校园资源、内置解析和缓存；默认使用系统默认解析与原生名称拨号，保留绝对查询及原生 IPv4／IPv6 连接选择，强制校园查询直接拒绝。校园名称例外仅影响该名称的连接，仍核对学校协议／端口授权；直接 IP 及其他名称的保护不变。原生查询失败不尝试校园或公共解析，关闭取消所属原生解析；更新与初始配置共用 `ProtectionConfig`，不维护两套字段。格式及边界见[核心 API](CORE-ABI.md#保护策略更新)。Qt 在每次连接前自动安装实际地址及 DNS 名称保护；核心接受 Start 后，工作线程随该代 starting 事件向应用交付已确认的完整初始策略。IPv4 选择及撤回保留最后确认的名称规则／例外，查看模型的刷新不会隐式替换名称保护。名称选择按具体主机规范化为小写 ASCII／ACE，拒绝根域、IP 和通配符；是否在保护范围内继续由核心唯一校验。名称更新及撤回保留已确认的地址范围／选择，原子确认前只保留待提交策略，失败不覆盖；读取中／失败仍可撤回本会话确认的名称例外。接管期间由所属 `NetworkAccess` 驱动网络变化协调，系统解析提供者限制仍适用。

系统 DNS 结果类型归 `application/dnssnapshot.h`，平台适配由 `readSystemDnsSnapshot()` 统一选择既有原生读取实现；调用者在工作线程运行，返回值沿用状态、完整事实和失败时空数据。各平台的原生回归经过统一入口，原生故障夹具仍直接注入平台读取器。持续策略观察使用 `observeSystemDnsSnapshot()`：Windows 通过系统 DNS／策略注册表树及接口／地址通知维护一份观察者私有的完整快照，未变时复用；变化先重置订阅再读取，读取中再有变化不缓存，监听不完整或读取失败均继续正式读取。它不缓存 DNS 查询答案，不改变两秒网络观察；启动保护、接管确认及独立恢复仍直接读取。原生观察仅处理匹配当前策略代次的模型，停止时清空代次不产生读取故障。

同一模块的 `campusCaptureTargets` 从实际资源和核心已确认的保护策略推导初始 IPv4 捕获／DNS 路由域。合并 IP 区间、静态解析地址及启用的校园 DNS，扣除实际保护范围，仅恢复已确认的精确地址例外；回环、0/8 和多播／保留高地址不允许例外。区间分解为去重的 `/2`—`/32`，结果过限整批拒绝，不生成默认路由；协议／端口授权仍由核心执行。不生成 IPv6 捕获前缀，当前规划不宣称透明 IPv6。远端 DNS 关闭时仅保留内置解析记录的路由域；域名从资源规范化并合并重复及父子覆盖。受保护的校园 DNS 地址或相交名称域使规划失败，须先完成原网络 DNS 转发／必要选择，不能以扩大校园域接管掩盖冲突。该规划不选择原出口或私有设备地址；初始出口查询、设备避让及平台编排见权限助手说明；运行中规划继续复用资源／保护与活动流责任，避免提前撤回仍在使用的捕获。

同一模型模块从 DNS 快照提取 `dns_namespaces`，每项保留原始表达式、角色及原快照来源（字段／行／数组项或动态存储键）。Windows 生效 NRPT 保留原始命名空间，不能统一解释成后缀；macOS State／Setup 的匹配域、搜索域和主域只作配置输入保留；另读取 `scutil --dns` 的 `macos_resolvers`，保留普通／接口／服务查询组、原生顺序、域名／搜索列表、IPv4／IPv6 服务器、端口、接口、标志及其余配置字段。动态 reachability 不作为配置变化；读取、格式或 256 KiB 整体预算失败均不发布部分视图，检查复用原五秒命令预算。畸形、NUL 与超过 4096 项均使整次模型失败；表达式不直接成为授权或已生效保护。依据：[Windows NRPT 命名空间](https://learn.microsoft.com/en-us/windows-server/networking/dns/name-resolution-policy-table)、[Apple DNS 配置处理](https://github.com/apple-oss-distributions/configd/blob/main/Plugins/IPMonitor/dns-configuration.c)。

`originalDnsProtection` 复用原命名空间事实生成 `name_targets`，每条规则引用原数组索引，相同规则合并来源；localhost 及其子域的默认原网络范围由同一模块提供。后缀和完整名称转换为规范小写 ASCII／ACE，Windows 无点 NRPT 按名称前缀处理；不把根域扩成全部域名，也不从 macOS State／Setup 配置猜测当前范围。macOS 仅以生效普通查询组的域和实际搜索列表生成保护；接口／服务专用组只展示，不泛化为普通查询。缺少生效视图时不退回旧输入猜测，删除原 NoSearch／DomainName／私有选项推导。其他平台沿用其原生搜索／路由／NRPT 语义。无法表示的表达式、非 ASCII NRPT 前缀、非法标记或超过模型预算时整次模型失败，不发布部分保护说明。每类模型项共用模块内 4096 项预算；实际核心请求仍受独立的 ABI 字节及条目限制。该结果同时供模型展示、启动前初始保护及运行中完整保护确认使用。 macOS 的原视图只在所属临时 DNS 键仍匹配已确认记录时，扣除自建普通 supplemental 解析器及私有接口的对应 scoped 解析器；外部源保留。生效确认与过滤共用接口／服务器／标准端口／选项匹配，避免两套端点判断。

原 DNS 数据路径由 Go 解析器复用现有报文交换、取消和有界绑定，C++ 继续负责原生来源与控制。来源保留已确认的普通 DNS 服务器和查询接口，业务留在原生路由，分别发布原记录与校园记录；TTL 失效不释放原方向保护，避免仍被捕获的同 IP 流量落入校园授权。macOS 静态普通查询源已通过双架构原生，接入见下文；其他平台及未支持的原生上下文继续拒绝不完整接管；配置与生命周期见[核心契约](CORE-ABI.md)。

原生 DNS 监听仍由同一 Go `Listeners` 会话持有，按宿主提供的原生上下文标识分组，允许不同上下文服务同一范围，查询接口与数据出口继续独立。无上下文的歧义请求拒绝，不把配置顺序当作系统选择；同名／同地址的不同原出口保留冲突，不由后到应答覆盖。TCP／UDP 使用同一实际端口；只接受绑定地址或本机回环的来源，设备接受前等待，所有请求、闲置连接和套接字随停止取消／回收。来源索引在配置编译时建立；同一端点可按已确认的原生优先级为不同名称范围使用各自服务器，查询接口保持一致。上游不一致时拒绝无匹配范围／根查询；原有单一上游的普通解析保持原样。监听绑定描述不再携带某个范围的服务器列表，实际名称匹配复用策略模块；保护对畸形输入的拒绝不充当范围匹配。TCP 帧处理、DNS 失败映射、UDP 大小、路由发布及绑定复用原入口，不增加第二套缓存或经过 Qt 转发报文。公共原解析只转发，不扩大捕获或污染受保护绑定。查询接口可为空，仅用于实际原生不绑定接口的上下文；监听地址仍须属于本机可用接口。macOS 静态及 State／DHCP 源已通过双架构原生，Windows 本地明文 NRPT 已有双架构原生覆盖，临时／加密／域管来源继续拒绝不支持的接管。

### macOS 原 DNS 来源

macOS 的 `prepareMacNetworkHelper` 复用公共重叠判断，将生效普通查询域／搜索域与唯一的既有网络服务核对。静态 Setup 及同一服务的 State／DHCP 来源、实际查询绑定和自动 DNS 恢复已通过双架构原生。服务器顺序、端口与绑定来自生效解析器，保存配置只用于来源归属及变化核对；允许生效列表是已配置列表经过系统筛选／排序后的结果，不按原始数组重排查询。正接口索引须匹配服务的真实 BSD 接口，IPv6 链路本地地址可由这个已确认的绑定补齐 zone；监听地址仍来自该接口实际分配的 IPv4。来源模糊、传输不支持、原值变化或缺少监听地址时明确拒绝；没有持久网络服务的临时提供者及加密上下文不在当前接管范围，保留原设置并明确拒绝，不猜测网卡或公共 DNS。

核心先按服务标识准备现有 TCP／UDP 监听，全部实际地址／端口确认后才授权助手；原查询保持系统路由，原上游从校园捕获中排除。已有原生监听覆盖整个校园 DNS 域时，不再发布第二个同范围 supplemental 解析器；该监听沿同一保护／学校授权分派原侧与明确校园选择。名称规则、原应答绑定、捕获排除及观察均复用现有模块，无第二套缓存、额外观察器或逐包 Qt／助手 IPC。

`MacOriginalDns` 使用公开 [SCNetworkProtocolSetConfiguration](https://developer.apple.com/documentation/systemconfiguration/scnetworkprotocolsetconfiguration%28_%3A_%3A%29) 和锁定的 preferences 单次提交，只改既有 DNS 协议的服务器／端口组，不接管他方临时 State 会话。原值用有界二进制 property list 保存，避免布尔／数值等类型损失。原本没有静态 preferences 时显式保存空值，恢复时撤销自身端点并交回动态提供者，不把先前 DHCP 服务器固定下来；外部新增的搜索字段及禁用状态继续保留。来源上下文保存实际服务器／端口、普通查询索引、接口及地址集合、原生域和原 State；写前、写前日志后及提交回读时核对 State，拒绝准备期间的动态改值，不改写他方的 State 会话。助手按资源定义的当前外层协议／存储版本记录连接、服务、原值、实际应用值及 applying／active／restoring 检查点；未知旧记录保留并拒绝，不为尚未正式部署的测试格式增加迁移兜底。提交前后核对原值、持久日志和回读，再有界确认实际解析器使用新端点。源对象析构不撤销持久重定向，宿主／助手双杀仍由既有独立恢复扫描负责。

正常退出、失败及独立恢复均先释放所属捕获，再恢复原 DNS 端点并确认自建端点已退出原生视图，最后释放设备／回执及核心监听。恢复只回写仍匹配自身的服务器／端口组，保留外部域／搜索字段和已替换的端点；原网络读视图按已确认记录投影回原端点，输入变化沿既有恢复／重连处理，观察同时核对独立 DNS 接口的地址集合和绑定，不能只看默认数据出口。私有 preferences 原生回归覆盖写前失败、已提交未确认、对象丢失后的恢复与外改；受控系统场景只创建自身 DNS-only 服务和临时 IPv4 状态，不重配现有接口，验证缓存预热、真实端点、TCP 回退／AAAA、同 IP 两侧流量与名称撤回、两轮恢复。`09be4da` 的 [ARM64](https://github.com/wtalioy/JustConnect/actions/runs/40450999800/job/122013443335)／[x64](https://github.com/wtalioy/JustConnect/actions/runs/40450999800/job/122013443053)已分别通过静态及 State 两类完整系统场景与各 37 项正式 CTest。IPv4-only 环境保留接管前的普通地址选择，并用系统 `DNSServiceQueryRecord` 单独核对真实 AAAA；上游原 A／AAAA 各一次、TCP 回退一次均有实际计数。其他来源、真实桌面／校园与签名部署继续验收。新增 State 系统场景复用同一驱动，只由自身临时提供者发布 DNS；私有 preferences 回归新增 DHCP 在写前／提交后改值、恢复自动模式、外部搜索字段与禁用状态，保持 20 秒失败期限。新增 CoreFoundation 路径与动态系统场景均已通过上述双架构 CI；本地不执行提权或网络写入。

### 策略聚合与冲突界面

`application/networkpolicysession.*` 按核心会话代次聚合网络与已就绪的校园资源，在两者成功后由单个后台任务读取系统 DNS 并推导保护／冲突模型。刷新清空旧模型，缺少能力、读取失败或畸形数据不发布部分内容；新代等待旧任务退出后仅构建当前代，停止立即失效交付。底层只读调用仍按各平台已有边界完成，协调对象销毁前等待所属任务。主窗口协调器复用同一个核心，断开进入停止阶段即失效模型；有序退出先失效结果，再由既有关闭流程等待后台读取完成，保留事件循环及原有超时边界。`setCampusAddress` 为显式调用生成完整地址策略，只接受实际保护范围内的规范 IPv4 地址；移除本会话已确认的例外不受刷新后范围变化阻挡，读取未结束或失败时沿用最后确认的完整策略撤回，不猜测新范围。版本沿用已校验的原生快照，代次内修订递增；同一时刻只提交一项，确认与待确认各保留完整策略，例外及待确认身份／忙状态由其派生；匹配确认后才发布选择，失败保留最后有效值，停止／换代丢弃晚到确认。刷新不重置修订；只读刷新本身不改策略，接管后端在完整观测后调用 `synchronizeProtection` 协调确认。启动前地址保护由核心适配器安装。

`NetworkPolicyWindow` 在地址页展示当前完整模型的原网络范围、接口／路由来源和已知校园地址重叠，保留授权协议／端口及内置记录／校园 DNS 的角色。选择实际 IPv4 范围后可输入单个地址，调用 `setCampusAddress`；界面只展示核心已确认的 `/32` 例外，失败保留原选择，并说明学校授权及相同地址无法同时访问两侧的限制。恢复入口仅提供本会话已确认例外，读取中或失败仍可撤回。输入窗异步且归属查看窗口，代次变化／会话销毁拒绝旧输入。DNS 页并列展示原始表达式、用途、来源和名称规则模型，另列系统保留的 localhost；单独展示已确认的具体校园名称，异步输入只提交该名称，撤回列表仅包含本会话确认的例外。长内容保留完整提示，说明最近读取的模型与核心已确认策略的区别。根域明确标为默认查询范围，NRPT 保留原生表达式，macOS 已保存配置与当前配置分开。刷新失败、停止、代次变化或会话对象销毁先清空旧行；内容使用纯文本，查看及刷新不调用策略提交。主窗口“文件 → 网络范围与校园地址重叠…”复用单个窗口，关闭释放窗口；无活动连接也可打开并查看无结果提示。受控选择／撤回、确认失败、旧输入、真实协议展示、清空和查询期间退出均有回归。

### 自动共存编排

运行期间外部改写浏览器代理时，仍由原有共存协调器在确认失去自动代理所有权后撤销本方责任，保留外部新值；不同于普通 Clash 开关的外来代理只发一次固定诊断与提示，不引入兼容后端。保存的本地控制入口不要求 Clash 始终运行：进程正常退出后普通直连可继续，同入口重启重新核验 PID、启动身份与监听归属；外来监听始终不能取得控制凭据。实际 Mihomo 重载／端口变化／停止／重启、调用链外部改写与断开保留有针对性回归。

`CoexistenceNetworkAccess` 在同一 `ConnectionSession` 生命周期内组合两平台原生接管、核心普通出口和 `SystemProxySession`。启动先确认代理恢复，再准备原生网络；认证及校园接管完成后读取实际监听、观察原系统代理并更新经过进程／端口验证的 Mihomo 出口，仅交接当前启用且命中的代理范围，确认后才报告校园就绪。未启用本地代理不影响没有交接需求的原生校园路径；需要交接而监听不足时明确拒绝，不生成默认端口。

系统代理变更由 Windows 注册表事件或 macOS SystemConfiguration 有效代理通知触发重新观察。macOS 在交接前从系统当前有效值识别上游，接管、回读及恢复继续用加锁的持久化服务配置核对所有权；普通周期复用已有原网络观察完成通知，只刷新核心只读状态，不反复调用桌面配置命令。仍有所有权的前端在 Mihomo 重启／端口变化时原地保留；读取失败保留先前验证且仍须逐流校验所有者的上游，没有该上游则拒绝普通请求，不能把读取失败当成实例已停止。只有成功观察确认原实例缺席或原入口关闭时才恢复普通直连；用户关闭或外部改写系统代理时释放所属修改，不重开开关。macOS 系统偏好锁遇到 `kSCStatusPrefsBusy` 时最多等待一秒（20 ms 间隔），每次重新同步原值；其它错误立即返回，等待超时不写入，恢复超时保留责任。[原生锁语义](https://developer.apple.com/documentation/systemconfiguration/scpreferenceslock(_:_:))；正常无竞争操作不增加等待。开始停止即暂停原网络策略观察，避免将撤销中间态报告为网络读取故障；先确认浏览器代理恢复，再撤回原生捕获并停止核心；取消等待串行撤销的最终结果，不把中途应用失败提前报告为恢复失败。最终恢复失败保留责任，明确重试前不自动争抢。回归覆盖切换、重启、取消和失败恢复；两平台原生组合、旧 Qt 缓存与实际浏览器的验证边界见[计划 S6](../plan.md#s6-clash-共存原型)。

macOS 原网络投影从同一网络快照中的已验证代理 TUN 角色识别普通捕获，不把用户切换 Mihomo TUN 当成物理原出口变化。角色同时核对活动控制进程的网络管理能力、控制器设备与内核接口索引／类型。系统读取留在所属 `networkstate/macos`／`windows`，会话桥只协调控制事实与快照；停止恢复失败保留责任并传递实际助手原因；已认证请求的记录读取／锁定失败使用既有回复结构返回具体原因，不把未确认状态当作已恢复。

macOS 的 TCP 监听身份取自系统 `netstat -anv -p tcp` 内核清单；`lsof` 的跨 UID 可见性不足以证明 root Mihomo 的数据入口。按表头定位 PID、端点和 LISTEN 状态，解析完整清单并从固定尾列取内核 PID，进程名中的空格或换行不能授予所有权；缺列／畸形清单拒绝。连接前后仍核对进程启动身份与当前监听，不读取私有内核结构，也不增加提权或数据转发服务。
